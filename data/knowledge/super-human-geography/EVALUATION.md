## 诊断

`AgentKnowledgeRagService` 的 trace 已显示检索到正确文件。`PlannerNode` 将 RAG context 加入规划模型提示，但 `WorkersNode.runWorker` 构造的 worker system/task prompt 没有传入 `RunContext.knowledgeContext`。规划器可看到资料，具体工作者却看不到；测试中 worker 转去联网或声称资料缺失，最终产生 unsupported details 和错误解释。这是当前超级 Agent RAG 调用链的上下文传递缺口。

下一步修复应将本轮私有知识上下文明确传给 worker，并在知识检索开启时要求优先依据这些片段、逐项使用 `[filename#chunkIndex]` 引用；不可回答时只说明资料不足，不臆测文档或工作区状态。之后用同一三题加省份直接问答、跨省比较和多个不可回答题回归。

## 河北问答检索融合回归（2026-10-20）

用户反馈“检索到了却说无法从私有知识确认”。回看对应真实会话 trace 后发现，融合候选中虽有 `04-hebei.md#3`，但最终 `selected=false`：检索服务在 rerank 前按逻辑文档去重，导致一份逻辑文档最多保留一个 chunk，河北人文历史与人口流动章节被河北概览块挤掉。

- 修复为以 chunk/document ID 去重，仅合并向量与词法两路命中的同一块，保留同一逻辑文档的不同 chunk；定向测试覆盖同一文档多 chunk 均送入 rerank 的情况。
- `mvn -q -Dtest=AgentKnowledgeRagServiceVersionFilterTest test` 通过，`mvn -q -DskipTests package` 通过；重启后 health 返回 `ok`。
- 真实 `super` Agent 问题“给我讲讲河北省的人文历史”回归后，selected 3 块为 `04-hebei.md#1`、`#3`、`#5`。回答引用了历史交通/人口迁移走廊、长城和文化景观、京津冀人口流动等片段；对语料未提供的燕赵文化起源、历代重大事件和代表人物明确说明无法确认。
- 结论：修复解决了相关 chunk 被错误排除的问题，但语料本身仍是概括性材料，不能支撑具体历史年表、人物与起源问题；该范围内的谨慎拒答是合理的。此次在线回归会话已删除。
