日期：2026-10-29

问题现象
- 用户浏览器里模型设置页显示"还没有供应商"，但数据库存在该用户的供应商与绑定；
- 同账号用新登录 token 访问接口却有数据（200 + 供应商列表）。

影响范围
- 任何持有"旧 JWT"的客户端：token 签名仍有效，但 uid 指向已删除/重建的用户行
  （如数据库重建、管理员重新初始化之后），后端按该 uid 查询得到空数据；
  表现为配置"消失"、列表为空，且无任何错误提示。

原因
- JwtAuthFilter 仅校验签名与过期时间，不验证 token 中的用户是否仍存在；
  uid 失效的 token 被当作合法身份，按不存在的用户 id 做作用域查询。

解决方式
- JwtAuthFilter 在解析 token 后校验 userRepository.findById(uid) 是否存在
  （60 秒本地缓存），不存在则视为未登录 → 接口返回 401 → 前端拦截器跳转登录页，
  重新登录后获得指向当前用户的 token。

验证结果
- 有效 token：/settings/catalog 200（数据正常）；无 token：401。
- 旧会话刷新后会跳转登录页，重新登录即可看到原有配置（数据本身未丢失）。

后续注意事项
- 本地开发管理员默认密码为 admin123（AdminUserInitializer 默认值）；
  数据库重建后旧浏览器会话需要重新登录，属预期行为。
- 若未来引入多实例部署，该 user 存在性缓存需改为短期 TTL 或事件失效。
