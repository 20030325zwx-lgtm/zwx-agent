问题现象：超级智能体提问后页面长时间停在“正在思考”，只显示规划器事件；后端实际已完成并写入 run 和答案。
影响范围：任务执行期间看起来像卡死，用户无法判断进度；SSE 丢失终态时页面不会自动恢复。
原因：
1. worker 的工具事件原本只在 workers 节点整体结束后才进入 state，执行期间没有实时事件。
2. 前端只依赖 SSE 更新状态，连接异常/漏事件时不会主动查询 run 终态。
解决方式：
1. WorkersNode 通过 RunContext.activitySink 实时推送子任务开始、工具调用、完成/失败事件。
2. RunStream.send 增加同步保护；orchestrator 对实时事件和检查点事件去重。
3. 增加 5 分钟 run 硬超时。
4. 前端对 RUNNING run 每 5 秒轮询 run 详情，发现终态后自动重拉消息、答案和文件。
5. 任务头增加运行计时和手动刷新。
验证结果：后端 201 个测试通过；用 mock API 验证计划、时间线、交付和终态恢复。
后续注意：页面加载到其他实例上的 RUNNING run 时，仍需后续补充自动接入实时流。
