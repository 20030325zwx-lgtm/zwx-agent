问题现象：用户表中已有普通账号但缺少管理员账号时，服务启动不会创建默认 admin，登录页只能引导用户注册。
影响范围：使用已有数据库部署或升级的环境，可能没有可用管理员账号；公开注册接口仍可被直接调用。
原因：AdminUserInitializer 在管理员缺失且未显式配置密码时，又以用户总数大于零为条件提前返回；前端同时保留完整注册流程。
解决方式：管理员用户名不存在时始终按配置密码创建，未配置时使用本地开发默认值；公开注册增加默认关闭配置；登录页预填部署环境提供的默认凭据并将注册按钮置灰。
验证结果：AdminUserInitializerTest、AuthControllerTest 共 3 项通过；前端 npm run build 通过；后端 mvn -DskipTests package 通过；本地数据库 V17 历史校验和修复后正常启用 Flyway 校验启动，27 个迁移全部通过；管理员登录返回 200，注册接口返回 403。
后续注意事项：生产密码只放在外部配置与 Git 忽略的本地前端环境文件中，不写入受版本控制的源码或文档；已有 admin 的密码不会被启动逻辑重置。
