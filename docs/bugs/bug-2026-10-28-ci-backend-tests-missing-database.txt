日期：2026-10-28
主题：CI 后端单元测试缺少数据库服务，导致长期红灯

问题现象
GitHub Actions 的「后端单元测试」job 长期失败（最近十余次运行全部为 failure），
IDE 的 Git Log 上对应提交出现红色感叹号；前端构建和意图评测门禁是绿的。

影响范围
CI 门禁形同虚设：后端改动无法通过流水线验证，红色状态还会持续污染提交历史视图。
不影响本地运行与已发布的桌面端。

原因
.github/workflows/ci.yml 的后端 job 直接 `mvn test`，没有启动数据库服务。
application.yml 里 datasource 是注释状态，本地依赖 application-local.yml；
CI 没有该配置，三个 @SpringBootTest（ZwxAgentApplicationTests、WebSearchToolTest、
PgVectorVectorStoreConfigTest）在加载上下文时拿不到 datasource URL，
Hikari 报 "Failed to determine a suitable driver class"，Flyway 随之初始化失败，
3 个测试全部报 ApplicationContext 错误。

解决方式
在 backend-tests job 增加 PostgreSQL 服务容器 pgvector/pgvector:pg16，
注入 SPRING_DATASOURCE_URL / USERNAME / PASSWORD，让 Flyway 正常建表后再跑测试。
用同样的镜像在本机起 scratch 库，执行完整 `mvn -B -ntp test` 验证。

验证结果
- 本机对 scratch 库跑完整套件：Tests run: 346, Failures: 0, Errors: 0, Skipped: 1，BUILD SUCCESS。
- scratch 库已删除，未污染开发数据。

后续注意事项
- 回归目标是让 CI 的后端 job 绿；若之后引入 OSS/Tika/Redis 等启动依赖，需要同样补 service 或改为切片测试。
- 不要用 -DskipTests 或禁用测试来“修复”红灯；数据库是这些上下文测试的必要依赖。
