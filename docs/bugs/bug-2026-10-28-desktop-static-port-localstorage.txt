主题：桌面端静态服务随机端口导致本地外观状态每次启动重置

问题现象
桌面应用每次启动后，主题（浅色/深色）、左侧导航折叠、任务栏折叠、工作区分组折叠等
界面状态都回到默认值；同一台机器上的网页端（127.0.0.1:3000）却能记住这些选择。

影响范围
仅桌面端（Electron）。不影响服务端数据，只影响本地 UI 偏好，但会造成
「网页端看起来和桌面端不一样」的错觉，属于产品化体验问题。

原因
Electron 主进程用 http.createServer 在内网起了一个临时静态服务来托管前端构建产物，
监听端口写的是 0（由系统随机分配），每次启动端口都不同。
localStorage 按 origin（协议 + 主机 + 端口）隔离，端口一变就是新的存储空间，
之前保存的 aster-theme-mode、aster.nav.collapsed、aster.super.sidebar.collapsed、
aster.tasks.collapsedGroups 全部读不到。

解决方式
desktop/electron/main.cjs 中静态服务改为优先监听固定端口 47821；
仅当端口被占用（EADDRINUSE，例如同时开了第二个实例）时才回退到随机端口。
同时用当前前端重新执行 build:web + prepare:assets，确保 desktop/app 与网页端同源。

验证结果
- 用同一份构建产物（desktop/app）在 47821 起服务并登录，任务页布局、侧栏、图标、
  深色/浅色表现与 3000 开发端口一致。
- 固定端口下 localStorage 的 origin 稳定，跨启动可复用；未能实际重启 Electron 窗口复测，
  但机制上已由端口固定保证。

后续注意事项
- 本次改动会让桌面端首次启动时丢失一次旧状态（新 origin），属于一次性影响。
- 若 47821 被其他程序长期占用，桌面端会退回随机端口并再次失去状态记忆；
  真出现时换一个固定端口即可。
- 桌面端与网页端仍是不同 origin，登录态与主题不会跨端同步，这是预期行为。
