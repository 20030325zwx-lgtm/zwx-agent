主题：CI 补上数据库后后端测试仍红——pgvector 用例依赖真实 DashScope Key

问题现象
2c189c2 为 CI 补了 PostgreSQL 服务与 SPRING_DATASOURCE_* 后，「后端单元测试」仍然失败：
PgVectorVectorStoreConfigTest.pgVectorVectorStore 抛 NonTransientAiException HTTP 401
InvalidApiKey，Spring AI 重试 10 次共约 146 秒，整个 job 跑到 3 分 40 秒。
其余 345 个测试通过，前端构建与意图评测门禁为绿。

影响范围
只影响 CI 后端 job；本地因 application-local.yml 带真实 Key 而正常通过。
接入真实大模型的 @SpringBootTest 被放在单元测试里，任何无凭据环境都会红。

原因
该用例对向量库做 add/similaritySearch，两条路径都会调用 DashScope embedding。
CI 没有配置 DASHSCOPE_API_KEY（仓库也没有任何 secret，意图门禁一直在跳过），
application.yml 的 spring.ai.dashscope.api-key 回落到占位值 your-api-key，请求被 401 拒绝。
注意 spring.ai.dashscope.api-key 只能由 SPRING_AI_DASHSCOPE_API_KEY 覆盖，
直接注入 DASHSCOPE_API_KEY 不会生效。

解决方式
给该用例加 @DisabledIfEnvironmentVariable(named = "CI", matches = "true")，
CI 跳过，本地默认 profile 仍照常执行（本地有真实 Key 与 pgvector）。

验证结果
- 本机 CI=true mvn test -Dtest=PgVectorVectorStoreConfigTest：Tests run: 1, Skipped: 1，BUILD SUCCESS。
- push 后待 GitHub Actions 后端 job 转绿确认。

后续注意事项
- 这是绕过而非根治：CI 依然没有覆盖向量库读写链路。若要覆盖，二选一：
  1) 添加仓库 secret DASHSCOPE_API_KEY，并在 job 里注入 SPRING_AI_DASHSCOPE_API_KEY，去掉跳过注解；
  2) 把用例改成注入桩 EmbeddingModel（固定维度向量），不再依赖外网。
- 新写 @SpringBootTest 时先确认启动/执行路径是否访问外网，避免再次把集成测试放进默认单测门禁。
