主题：模型供应商保存 Key 后输入框清空、脱敏 Key 提示不明显，被误认为未保存

问题现象
在「模型设置」里给智谱 BigModel 填了 API Key 并保存后，API Key 输入框变回空白，
用户以为没有保存；随后点「测试（用当前表单草稿）」报「未配置模型 API Key」，
进一步确认了「没保存」的错觉。实际数据库中 Key 已写入（secret_hint 有值）。

影响范围
只影响配置页的可用性判断，不影响保存本身；但会让人反复重填、误判配置失败。
旧版桌面端打包前端同样是这个表现。

原因
1. 保存后 selectProvider 会把表单里的 apiKey 清空（避免密码回显），
   脱敏 Key 只出现在字段标题「API Key（已保存 ****xxxx）」里，位置不显眼。
2. 输入框占位符固定写「留空保持不变」，即使从未保存过 Key 也是这句，
   无法区分「已有 Key」和「没有 Key」。
3. 保存成功的提示固定是「已保存」，不反映本次是否真的带上了 Key。

解决方式
- 占位符按状态变化：已保存时显示「已保存 ****abcd，留空则保持不变」，
  未保存时显示「尚未保存 API Key，请在此粘贴」。
- 保存成功提示区分两种情况：带 Key 时提示「已保存（API Key ****abcd）」，
  没带 Key 时提示「已保存（未设置 API Key）」。

验证结果
- 页面实测：已保存 Key 的供应商，字段标题与输入框占位符都显示 ****aH33。
- frontend `npm run build` 通过。
- 用已保存的真实 Key 调测试接口返回 429（模型访问量过大），不再是 401/404，
  说明 Key 与请求路径都已生效；429 属于智谱免费模型的限流，不是配置错误。

后续注意事项
- 测试报「未配置模型 API Key」时，先确认此前是否点过「保存修改」，
  再确认是否勾选了「保存时清除已存 Key」。
- 智谱免费模型在高峰期会返回 1305 限流，重试或换 glm-4.6v-flash 即可，
  不要当成 Key 配置问题排查。
