日期：2026-11-03
问题现象：创作台（快速生成）底部输入台在浏览器缩放/较矮视口下被裁切：提示词输入框被撑到约 96px，整行输入台被顶出视口底部；窄宽度下模型/提交区与输入框挤压，看起来"格式错乱"。
影响范围：创作台底部输入台；常见于浏览器 125%-150% 缩放或窗口高度较小时（用户实测 1690×1005 窗口、约 1.4 倍缩放）。
原因：`.composer-textarea`（min-height:44px）与公共样式 `.cr-textarea`（min-height:96px）同权重，靠 CSS 加载顺序决胜；公共样式后加载时输入框被撑高，输入台高度超出可用空间并被父级 overflow 裁切。另：窄于 1180px 时右侧模型/提交区仍常驻一行，把输入框压到 200px 以内。
解决方式：
1) 提高权重并显式锁高：`.st-composer .composer-textarea { min-height:66px; max-height:132px; height:66px; line-height:1.5 }`（66px≈3 行，避免切半行）；
2) `.st-composer` 加 position:relative + z-index:3，任何情况下都盖在结果舞台之上；
3) ≤1180px 时 `.composer-main` 换行，模型/草稿/提交按钮折到输入框下方一行（按钮右对齐），不再挤压输入框。
验证结果：1690×1005 / 1352×804 / 1200×700 / 1024×640 / 1128×670(缩放场景) 均无溢出（composer.bottom == viewport 高度），输入框稳定 66px；已部署 0.2.4，域名与 API 均 200、backend healthy。
后续注意事项：共享样式与组件局部样式同权重时，靠加载顺序不可靠；组件必须用更高权重（父类限定）覆盖公共样式。新增输入台控件时保持 composer 两行结构（输入 + 操作行），避免再次挤压。

【追加 2026-11-03】布局再调整：模型信息/草稿状态/生成按钮不再挤在输入框右侧小列，改为输入框占整行、下方工具栏一行（模型名单行省略 + 草稿状态 + 右对齐提交按钮）。窄屏不再需要折行规则。已部署 0.2.5。

【追加 2026-11-03 二】按用户要求再收口：模型由只读文字升级为真正可选择的下拉（按项目类型过滤 image_generation / video_generation 能力，默认选中当前绑定），与生成按钮一起右对齐成组；草稿状态/首帧 chip 留在左侧。所选模型的 modelRowId 随任务提交（后端显式解析，不回退其它模型）。已部署 0.2.6。

【追加 2026-11-03 三】按用户最终要求：移除底部输入条，模型选择 + 草稿状态 + 生成按钮整体移入右侧参数栏底部（sticky，滚动时仍可见）。右栏原有的「你的想法/最终提示词」承担输入，底部条与右栏输入不再重复；结果舞台占满左侧全高。≤900px 时右栏折到下方、提交区改为静态。已部署 0.2.7（域名/API 200）。
