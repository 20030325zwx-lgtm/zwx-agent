问题现象：项目画布没有默认起点；单节点/从此继续模式可能仅根据草稿中的提示词、素材就直接执行，缺少对全部上级真实完成状态的约束。
影响范围：创作画布初始化、旧草稿升级、执行连线、部分范围运行预检与执行器。
原因：原画布只有生成/素材/文本节点；运行图过滤了输入节点和范围外祖先；提示词输入可在上级生成前读到，不能等同于上级已完成。
解决方式：默认唯一 start 节点，旧草稿自动连接所有既有根节点；start 不调用模型、不产生素材。新增 flow-out/flow-in 执行端口。运行图保留开始节点及输入节点的依赖顺序；每个运行节点要求全部直接上级 SUCCEEDED。部分范围运行对所有范围外生成祖先查询项目/租户/用户内最新实际执行记录，拒绝等待、失败、取消、跳过、待选片状态，不信任草稿 status 或 selectedAssetId。未连接起点的生成节点不能运行。
验证结果：25 项后端相关测试、6 项前端纯函数测试通过；隔离浏览器测试验证唯一且不可删除的开始节点、蓝色端口拖线、运行中阻止下游、成功后放行、刷新恢复、既有图编辑回归；全部 API mock，无付费调用。前端构建与后端 package 通过，服务已重启。
后续注意事项：当前采用拓扑顺序串行推进，未引入并行分支执行；失败不会算完成。旧画布首次打开会补起点并自动保存，不改数据库结构。本次校验不包含真实供应商端到端任务。
