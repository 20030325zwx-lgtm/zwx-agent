## 用户意图与授权边界

- 用户最初要求先规划再开发，后来明确 Aster 是可扩展的 AI 工作台，不是只有聊天的应用。
- 长期可能覆盖个人研究/文档、开发项目、团队业务，支持自由画布、工作流与拖拽操作。
- 用户要求制作首页供反馈，已交付可交互设计草稿；随后要求正式开发采用适合 Agent 的成熟组件库，并回复“ok”后要求归档供其他智能体接手。
- 当前任务只完成归档，不继续开发、不启动其他智能体、不自动发送消息；接手者根据用户的新任务启动实现。

## 已确认方向

- 首个桌面目标：macOS Apple Silicon；Windows/Intel 后续。
- 桌面本机独立运行、免注册，用户不需要 Docker、Java 或数据库部署；配置模型后可用。
- 模型：OpenAI 兼容 Chat Completions 为主，保留 DashScope；多供应商、多模型、测试、默认模型、任务中选择。
- 首版核心：对话、多步任务、本地项目/文件、Skill/MCP；知识库和搜索按需配置，不阻塞启动。
- 网页直接进入工作区；首页展示任务入口、继续项目、最近工作、待处理与工作流，取消宣传式首页。
- 中央工作区按对象切换：任务、文档、代码、画布、流程；AI 协作围绕当前内容，资料引用范围可见。
- 自由内容画布和可执行工作流分别设计，不能把视觉连线直接当作执行授权。
- 正式组件：Ant Design Vue + Ant Design X Vue + Vue Flow。X Vue 是独立维护的 Vue 实现，不是官方 React 包；Aster 执行状态、工具确认和产物组件另行封装。

## 源码事实与最大技术问题

- 前端：`frontend/src/components/WorkspaceLayout.vue` 负责现有顶部导航；`views/Home.vue` 是宣传式首页；`views/SuperAgent.vue` 是独立会话工作区，已有侧栏、TaskComposer、RunInspector、计划与工具确认、SSE 和恢复逻辑。优先重组复用，不把全部新功能堆进同一个大组件。
- 模型：`platform/settings` 当前是 chat/vision 两个用途槽位，不是供应商模型目录；改造要保留个人/系统覆盖与旧数据迁移，选择模型须贯通任务阶段、轨迹与恢复。
- 桌面：`desktop/electron/main.cjs` 已启动本机 JAR，但仍依赖外部 PostgreSQL 等配置；当前 macOS arm64 脚本并不证明无需部署的成品可用。
- 数据库：PostgreSQL JSONB + pgvector 依赖较深。推荐先验证应用托管私有 PostgreSQL/JRE 的可分发、签名、资源和升级成本；这是待验证候选，不能直接声称已定案或无成本换 SQLite。
- 可选依赖：模型、向量、OSS、文档解析与搜索的启动依赖需解耦；文件本地存储适配、本机自动身份与回环认证尚未做。
- 工作流：已有 `evaluation/n8n-document-poc`，源码有通知、workflow-status、resume-info、review-events；仅核对存在，未复测。Flowable 7.2 mock POC 与 6.8 UI 试点不兼容为直接替换前端。不要把历史试点等同当前通用工作流产品。
