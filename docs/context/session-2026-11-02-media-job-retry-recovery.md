# 媒体任务未知提交与重试恢复（2026-11-02）

## 改动内容

- 修复没有 `SUBMIT` 尝试的任务被误判为可能已计费：供应商调用前异常或中断统一进入 `FAILED`，错误码为 `PRE_SUBMIT_FAILED` / `PRE_SUBMIT_INTERRUPTED`，可直接重试。
- 真正开始过提交但没有供应商任务号的任务继续进入 `RECONCILING`，不自动重发，并写入观察截止时间；到期后转为可重试失败。
- 启动恢复会修复历史上 `RECONCILING` 且缺少观察截止时间的任务。
- 人工重试改为原地重排原 `media_job`：复用任务 ID，清理本轮执行状态并递增 `lease_epoch` / `version`，保留输入、模型快照、幂等键、attempt 和事件历史，不再创建新任务或新任务卡片。
- 保留风险确认：`RECONCILING` 及 `FAILED / SUBMISSION_UNCERTAIN` 必须长按确认可能二次计费后才能重新排队；调用前失败可直接重试。

## 现场根因证据

- 共享 PostgreSQL 队列同时有两个活跃后端：旧实例 `acce6032-95e7-4508-baa4-c807d8cf4e82`（worker `worker-61038319`）和本地 worker `worker-f42d15d0`。
- 22:07 至 22:09 的相邻任务中，三个成功任务由本地 worker 处理；失败任务 `537c5300-794f-4cd8-96f2-9c5e006499c1` 被旧 worker 领取，且没有 `media_job_attempt`，随后被恢复为 `PRE_SUBMIT_INTERRUPTED`。这证明中断发生在供应商调用之前。
- 旧版本没有持久化调用前异常。尝试 SSH 读取远端日志时，`root@1.13.152.215` 和 `zhuwenxuan@1.13.152.215` 均被公钥认证拒绝，因此无法从现有证据进一步确定历史异常发生在哪一个调用前步骤，不能将具体异常类型写死。
