# 文档切片质量改进计划

## 目标

减少“召回到了相关切片，但模型答错表格字段、合并单元格归属或适用范围”的情况。切片需要保留可读的结构与来源，检索结果应能被原文件核实；解析不可靠时不能把关键词命中当成事实充分。

## 当前链路与已知风险

知识库文档由 MinerU、Docling 或本地解析器生成文本，再进入 `MyTokenTextSplitter`，最后写入 PGVector。当前 splitter 能保留 Markdown 章节路径和部分 PDF 页码，也会按结构边界分段。之前 MinerU 输出的 HTML 表格被当成普通长文本处理：`<td>` 标签、`rowspan` / `colspan` 和相邻记录混在一起，向量可能召回关键词，却无法稳定恢复列与行的对应关系。

解析质量也会独立影响答案：扫描件 OCR 错字、跨页续表重复/缺失表头、复杂多层表头和过长单元格，都可能令结构化文本仍然失真。重新切片只能改善索引表达，不能修复源解析阶段已丢失的信息。

## 分阶段方案

### P0：HTML 表格行结构化（本次完成）

- 用 Jsoup 解析 MinerU/解析器输出中的 HTML 表格。
- 根据表头将每行表达为 `列名：单元格内容`，并将 `rowspan` / `colspan` 的值展开到覆盖的列/行；支持基础多行表头组合，章节路径仍附加在切片上下文。
- 表格记录切片以 `structuredContentType=table-record` 标记，便于后续按类型观察和核验。
- 表格按记录边界分块；不会为满足字符上限而拆开普通长度的记录。
- 回归测试覆盖 rowspan 继承、字段关联及多行长表跨切片。

### P1：来源与解析质量闸门

- 统一记录 parser、页码、表格序号及行范围等来源信息；前端切片核验视图显示可回看的来源定位。
- 解析后检查空文本、异常低文本量、明显 OCR 错乱/重复页、表格行列数异常；失败与“可疑但可索引”分开表示，不静默发布低质量版本。
- 对扫描件、损坏文件或超长单元格给出可操作的解析质量提示；保留原文件，不以切片成功状态掩盖内容缺失。

### P2：复杂表格与跨页续表

- 补齐复杂多层表头组合、`rowspan=0`、嵌套表格和空单元格语义的回归与兼容规则；解析失败时保留可审查的原表文本。
- 识别分页后续表，验证相邻页列数与重复表头，再合并或补齐表头；不能可靠判断时保留分页边界并标记不确定，不猜测合并。
- 对 OCR 结果与原文冲突的表格提供低置信标记，避免自动把推测写成事实。

### P3：检索与回答核验

- 对表格问题从问题中抽取实体、字段和筛选条件，并检查候选行是否同时覆盖必要字段；不能只因关键词重合就判为充分证据。
- 将完整行和来源定位作为引用证据。涉及比较、计数或跨行汇总的问题，返回覆盖所需范围的多条记录；召回范围不足时明确提示证据不足。
- 增加固定问题集，分别验证“命中正确行”“字段不串列”“合并单元格继承正确”“来源可核对”“无证据时不臆答”。

## 本次实现边界

- 没有新增解析器依赖，复用现有 Jsoup。
- 未改变向量检索、提示词、OCR 服务或 UI。
- 未对数据库中的既有向量自动重建索引。旧切片需通过知识库页面的重建索引操作重新解析后才会采用新格式；新上传文档会走新逻辑。
- 没有 `<thead>` 时暂以首行作为表头，符合当前 MinerU HTML 常见输出，但无表头数据表可能因此误判；P2 需增加显式/启发式判定与不确定状态。
- 超长的单条记录、跨页续表、嵌套表格和 OCR 质量评估仍是待处理项，不能承诺本次全部解决。
