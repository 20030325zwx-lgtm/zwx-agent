# 网页与桌面工作区、模型设置及本地运行改造计划

日期：2026-10-28。状态：待用户审阅，尚未授权实施。本文提出的对象、路由和组件均为设计建议，不代表已实现。

> 后续方向修订：用户要求通用 AI 工作台，长期覆盖工作流、自由画布、开发与团队场景。本文第 3 节“以对话为中央主区”的布局仅作为专注对话视图；整体信息架构与实施顺序以 [AI 工作台设计借鉴与修订](./2026-10-28-ai-workbench-references.md) 为准。桌面平台、本机免注册和模型配置等已确认边界继续有效。

## 1. 已确认的产品边界

- 桌面首版：macOS Apple Silicon；Windows 和 Intel Mac 后续评估。
- 本机独立运行、免注册；用户不需要部署服务、安装 Java、数据库或 Docker。
- 安装应用 → 添加模型供应商 → 测试并设为默认 → 开始任务。
- 网页端直接进入工作区，不再保留当前宣传式首页作为使用入口。
- 两端共用会话、任务和设置界面；桌面补充窗口、本地身份、文件选择和进程管理能力。
- 首版覆盖对话、多步任务、本地项目与文件、Skill、MCP；知识库和联网搜索按需配置，不阻塞基本启动与对话。
- 模型接入以 OpenAI 兼容 Chat Completions 为主，保留 DashScope；不把原生 Anthropic、Responses 或本地推理引擎纳入首版必交付范围。
- “本机运行”指应用与任务运行时、数据在本机；模型推理由用户配置的服务提供，不等于安装包内置大模型。
- 本轮只做规划与布局草图；用户确认整份计划后再改业务代码。

## 3. 两端统一工作区

### 导航与布局

- 左侧 240–280px，可收起、可调宽：新建任务、搜索会话、项目分组、最近会话；底部固定设置与用户/本机标识。
- 中间弹性主区域：顶部只放项目/会话标题、必要操作和详情开关；对话阅读区建议最大宽 880–960px。
- 输入框固定在中间区域底部：附件、项目、权限模式、模型、发送/停止；高级参数折叠。
- 右侧 300–360px：计划、文件、引用、运行详情。默认收起，用户打开或查看计划时展开；待确认事项在主区明显呈现，不依赖右栏才能发现。
- 宽屏三栏；中等宽度详情覆盖式抽屉；窄屏侧栏也改抽屉，保证输入与消息可用。具体断点以真实内容验证确定。
- 设置作为同一应用内的完整页面：左侧设置分类，中间设置内容；“返回工作区”恢复原会话、滚动位置与输入草稿。

### 首页具体取舍

删除：大面积宣传标题、漂浮图形、LIVE 徽章、能力宣传卡、单智能体搜索、重复“进入工作台”按钮。

保留并迁移：会话搜索放侧栏；最近任务并入历史列表；知识库保留可直达管理入口；Skill/MCP/记忆/权限收进设置。

新任务空态：简短提示“今天想完成什么？”、可直接输入的任务框、最多三个可填入输入框的示例。示例点击不自动发起收费调用。

现有悬浮角色建议默认移除；任务进度集中在会话时间线与右侧详情。输入框不常驻堆放吞吐、套餐和累计 token；已有用量信息放可展开详情。

### 视觉建议

参考 ZCode 的信息层级、侧栏和设置布局，保留 Aster 品牌。采用低装饰、中性背景、清晰边界；浅色/深色/跟随系统，两端统一设计变量。草图仅确认结构，不代表最终视觉验收。

### 两端差异

| 项目 | 网页 | 桌面 |
| --- | --- | --- |
| 身份 | 保留已有账号和权限体系 | 自动创建内部本机身份，用户免登录 |
| 文件与项目 | 指向服务器的项目；浏览器上传 | 系统目录选择器，本机目录授权 |
| 模型配置 | 保留个人/系统作用域；密钥在部署服务器 | 本机配置；应用生成并保护本机加密主密钥 |
| 服务状态 | 与部署服务连接 | 内置运行时启动、诊断和恢复 |
| 窗口 | 浏览器响应式布局 | 原生标题栏、拖拽区域、系统快捷键 |

特别注意：网页中的“项目目录”不能伪装成访问用户电脑的任意本地目录。双端共享界面不等于数据自动同步；首版不做跨设备云同步。

## 4. 模型设置设计

### 页面结构

设置分类：常规、外观、模型；能力配置：Skill、MCP、知识库、记忆、权限；桌面另有本地数据与诊断。

模型页使用“供应商列表 + 详情编辑”结构：

- 供应商：名称、协议、Base URL、API Key、启用状态、最近测试结果。
- 模型列表：模型 ID、显示名称、启用状态、能力声明（如工具调用/视觉）；未知能力显示未验证，不自动标为支持。
- 支持新增/编辑/删除供应商与模型；删除被默认用途或会话引用的项时要求重新选择或保留明确不可用状态。
- 自动获取模型列表仅作增强；服务不支持列表接口时仍可手动添加模型 ID。
- 支持测试未保存的草稿；区分“已保存”“测试成功”“已设为默认”。测试会产生真实模型请求，按钮旁说明。
- 默认对话模型必选；视觉模型按需指定或复用经验证支持视觉的对话模型；Embedding 属于知识库设置，不出现在首次必填流程。
- 对话输入框可选供应商下已启用模型，记住会话选择；运行开始时记录模型配置版本，避免任务执行中随全局修改漂移。
- 展示失败原因：鉴权失败、地址/协议错误、超时、模型不存在、工具调用不支持等；不能只展示“连接失败”。

### 后端改造建议

逻辑对象：Provider（连接与密钥）、Model（供应商下模型及能力）、ModelBinding（默认用途/会话选择），具体表名与接口签名在实施设计时确定。

旧 `chat` / `vision` 配置应新增迁移，转换为供应商、模型与用途绑定；保留网页个人→系统→环境的继承规则，作用域之间不能错误合并。迁移前备份，不能清库或重置历史。

接入范围不止设置页：请求入口、planner/worker/verifier/aggregator、重试与恢复、视觉调用、调用轨迹统一经过模型解析，评测证明选择生效。新增 `modelId` 等请求字段属于拟议设计，需兼容旧客户端。

协议与品牌分开：OpenAI 兼容供应商不等于原生 Responses 支持。Base URL 路径规范化与 `/v1` 拼接须覆盖测试。

桌面允许用户明确配置 loopback/局域网模型地址；网页部署保持已有服务端出站限制，不能为了桌面全局关闭 URL 安全策略。本地无 Key 服务的支持可通过显式鉴权模式实现，不能静默填造假 Key。

## 5. 桌面独立运行方案

### 推荐技术路线与验证门槛

延续 Electron + Vue + Spring Boot；首选验证“应用托管的私有 PostgreSQL 进程 + 内置 JRE”，沿用现有 SQL 与数据模型。数据库自动初始化在应用数据目录，独立端口/凭据，用户无需安装或配置数据库。

这是待验证的推荐，不是已完成的可行性结论。阶段 A 必须确认 arm64 可再分发二进制来源、许可证、签名公证、安装包体积、冷启动与内存占用、数据升级和退出清理。知识库启用时的 pgvector 分发也需验证。

若该路线不满足分发或资源要求，再形成 SQLite/H2 方案对比；需计算 JSONB SQL、迁移、持久化恢复、向量存储适配的实际成本，不能未经评估直接切换。存储结论应先于大规模本地运行开发。

### 本地运行闭环

1. 首次启动：本地目录与加密主密钥初始化 → 私有数据库 → 迁移 → 本机后端 → 自动身份握手 → 打开工作区/模型引导。
2. 模型未配置时，设置和空工作区仍能进入；模型客户端按需创建，禁止依赖一个预置 DashScope Key 才能启动。
3. 免注册不等于开放接口：仅绑定回环地址，由主进程管理随机认证凭据、受限 IPC 和允许的来源；本机用户身份继续参与任务与数据归属。
4. 使用独立 desktop profile，不读取或修改开发机 `application-local.yml`，不内置开发账号、云凭据、数据库地址或个人文件。
5. 上传、图片与任务产物使用本机存储适配器，复用受控文件读取接口；无需配置 OSS/MinIO。
6. 对云视觉模型，图片应通过支持的上传/内联方式传递，不能把只有本机可访问的 URL 交给远端模型。视觉能力按模型支持情况启用。
7. 知识库、向量初始化、搜索、文档解析服务和远程 MCP 按能力可选装配；缺失时显示配置入口，仅禁用依赖它们的功能。
8. Skill 与 MCP 列表、配置、权限继续复用。需要额外解释器、npx/uv 或外部服务的 MCP 明确标注依赖；首版验收至少覆盖一种可用连接，不承诺任意 MCP 零依赖。
9. 健康就绪后再进入业务；启动失败展示原因、重试和脱敏日志入口；处理端口冲突、重复启动、睡眠唤醒、后端退出与恢复。
10. 数据放系统应用数据目录，与安装目录分离；更新前备份，升级保留会话/配置/文件。普通关闭窗口与彻底退出行为需明确，禁止默默丢失正在运行的任务。

### 本机密钥

优先复用现有后端密文机制，随机生成每安装实例的加密主密钥并由 Electron safeStorage/系统钥匙串保护；渲染进程不持有可枚举读取已保存密钥的接口。解密失败应明确恢复流程，不能生成新密钥覆盖旧数据。密钥不写日志、导出文件和前端 localStorage。

## 6. 实施顺序与验收

以下阶段只有在用户确认计划后开始。阶段可有重叠开发，但无需复制两套 UI；这里的“两线推进”不表示已授权创建额外代理。

| 阶段 | 交付 | 验收条件 |
| --- | --- | --- |
| A：桌面技术验证与契约 | 私有数据库/运行时最小验证；启动依赖清单；模型对象、作用域、迁移和调用契约 | 无开发环境机器可启动到未配置模型的设置页；明确分发、资源、升级可行性；据此细化工期 |
| B：共用界面改造 | 新工作区框架、侧栏、首页空态、设置框架、主题变量、响应式布局 | 网页和 Electron 均可新建/恢复会话；切设置保留草稿；旧会话深链可用；计划与工具确认不丢失 |
| C：模型管理闭环 | 供应商/模型管理、迁移、草稿测试、默认模型、会话选择、运行模型记录 | 两家供应商/多模型真实调用；切换、禁用、删除引用、重启恢复；密钥不回显；网页作用域隔离 |
| D：本机可用产品 | 自动身份、本地文件存储、目录授权、按需能力、启动诊断和进程退出 | 无 Docker/Java/PG/OSS 环境，安装后填一个兼容模型即可完成对话、多步任务、读取授权项目并生成文件 |
| E：发布与回归 | macOS arm64 安装包、签名公证、升级备份与恢复验证 | 干净机器安装/首次启动/重启/升级均通过；已有网页登录与任务流回归通过 |

推进关系：A 先关闭最大技术不确定性；B、C 作为两端共享成果；D 基于 A/C 接通；E 汇总验收。未完成 A 前不给出精确交付日期，以免把桌面后端改造误估成换皮工作。

重点回归：SSE 断线回放、跨重启恢复、执行权限、计划门、引用与产物、模型切换和密钥迁移、数据库升级失败恢复。仅 UI 改动做构建与交互检查；新增存储/鉴权/模型路由必须有针对性自动化验证。
