# 淘宝服饰海报工作流：能力与流程评审材料（2026-10-31）

> 供评审的完整流程总结。基线：master `3fe0424`（含当日全部提交）；实测运行 `c1e9e60a-8482-4e26-97c5-8f5c026cb792`。

## 1. 背景与目标

验证一个命题：**把"模特图 + 多件服饰 + 提示词 → 商品海报"沉淀为可复用的工作流模板，比每次把一堆图片和提示词丢给 AI 更可控、更便宜、更可批量化。**

为此补齐了两块能力缺口，并端到端跑通了一个真实计费的模板运行：

1. AI 创作新增 `image_edit`（参考图编辑）操作——此前只有 text_to_image，无法"让参考图里的模特穿上参考的服装"。
2. 工作流编辑器支持素材上传/选择——模板的使用者不需要接触 UUID 或提示词拼接。

## 2. 端到端流程（实测通过）

```
输入（运行对话框填写）
  ├─ 关键词：加绒保暖 不起球 显瘦百搭 秋冬新品
  ├─ modelAssetId：模特全身照（中转站生成，白底站姿）
  ├─ topAssetId：米色针织开衫（商品图）
  └─ pantsAssetId：深蓝直筒牛仔裤（商品图）
        │
        ▼  工作流 taobao-apparel-poster（6 节点 DAG）
  ① start ──────────── 透传输入（{{start.output.X}} 引用）
  ② 模特理解 ────────── image_understand：描述模特体型/姿态/视角（≤60字；服务不可用自动降级跳过）
  ③ 试穿提示词 ──────── text_template：静态模板 + 卖点 + 模特描述拼出编辑提示词（确定性拼接，零计费）
  ④ 模特试穿 ────────── media_image_edit：模特+上衣+裤子 3 张参考图 → 中转站 /v1/images/edits
  │                      （同一模特换装；WAITING_EXTERNAL 持久等待，重启可恢复）
  ⑤ 海报文案 ────────── llm_text：按卖点关键词生成严格 JSON（标题/副标题/3卖点/配色）
  ⑥ 海报合成 ────────── poster_render：本地 Java2D 固定版式 1200×1600（0 计费，中文排版确定性）
        │
        ▼
  产物：试穿图 + 海报 PNG 自动归入项目素材库（来源标记=工作流/生成结果）
```

**实测**：6 步全部 SUCCEEDED，总耗时约 3 分钟；试穿图约 90 秒返回（b64 直接入库）；海报标题「加绒显瘦秋冬装」、副标题与三条卖点由 LLM 生成并正确排版。本次运行计费：1 张试穿图（默认档）；素材图 3 张 low 档另计。

## 3. 关键实现（供架构评审）

### 3.1 image_edit 操作（创作域）
- `MediaJobService`：操作白名单扩为 text_to_image / image_edit；BR08 按操作区分——image_edit 强制 1–3 张**本人 READY 素材**（受理时校验归属与状态），text_to_image 仍拒绝参考图；参考图 ID 参与 requestHash（幂等：同图同文重试复用，改图/改文 409）。
- 引用事实来源：受理事务内写 `media_job_asset_ref(role=input)`，素材删除保护（BR14）据此判断"被活动任务在用"。
- `MediaModelResolver`：档案按操作校验能力（operations={text_to_image,image_edit}），openai-compatible 协议自动挂 `openai-images` 适配器（UNVERIFIED，诚实标注未真实验证的模型）。

### 3.2 调度与适配器
- `MediaProviderAdapter` 新增 4 参 submit 重载（带参考图字节），默认实现回退 3 参——DashScope 等异步适配器零改动。
- 调度器提交前从素材库读出参考图字节传入适配器；同步适配器提交前按 epoch 围栏延长租约（覆盖最长 240s 的 HTTP 窗口），提交不明走观察窗口后如实 FAILED（费用提示），不假称未计费。
- `OpenAiImagesMediaProviderAdapter`：multipart `POST {base}/v1/images/edits`，`image[]` 多文件（按魔数识别 PNG/JPEG/WebP）；错误分类与 A21 对齐（401/429+Retry-After/4xx/5xx/超时）。

### 3.3 工作流节点
- 新节点 `media_image_edit`：`imageAssetIds` 接受数组或逗号分隔（可引用 `{{节点.output.assetId}}`）；复用 WAITING_EXTERNAL + 恢复器链路，产物输出 `{jobId, assetId, mediaType}` 供下游引用。
- 来源追踪：工作流发起的任务 sourceType=WORKFLOW（runId+nodeKey），费用与恢复可归因。

### 3.4 编辑器可用性（让模板真的能用）
- 运行对话框：自动扫描图参数中的 `{{input.KEY}}`/`{{start.output.KEY}}` 推导运行输入；`*AssetId` 键渲染「项目选择 + 素材选择 + 上传图片」控件（imageAssetIds 多选）；目标创作项目选择（产物归属）。
- 节点面板：素材参数同控件；引用表达式与手动选择可切换。
- 素材库：来源分组（原始素材/生成结果）+ 大图预览（收藏/继续创作/删除/下载）。

## 4. 工作流形式 vs 直接丢图给 AI（实测对比结论）

| 维度 | 工作流模板 | 直接丢图给 AI |
| --- | --- | --- |
| 复用 | 换 3 个输入点一次运行；提示词逻辑沉淀在模板 | 每次重写长提示词，容易遗漏约束（如"保持脸型"） |
| 批量 | N 套搭配 = N 次参数化运行，后续可加循环节点一次跑完 | 每套手工来一遍 |
| 确定性环节 | 海报排版本地合成：0 计费、中文零错字、版式稳定 | 版式与中文靠模型，每次都在赌 |
| 图文一致 | 文案按关键词生成并与海报同批产出 | 图与文案通常两次会话，风格脱节 |
| 中间产物 | 节点间素材 ID 自动流转，产物自动入库带来源 | 人工下载/上传/粘贴 |
| 可恢复/审计 | 每步落库、重启续跑、幂等防重、attempt 记录 | 手滑重跑=双倍费用且无迹可查 |
| 成本结构 | 计费只花在必要环节（试穿 1 张）；排版/拼接/理解降级都免费 | 全部环节都压在生成模型上 |

## 5. 已知限制与风险（评审重点）

1. **试穿保真度依赖中转站模型**：gpt-image 系对复杂姿势/配饰/面料细节可能走样；未做多模型对比评测。建议：同一模板跑多模型出图对比（目录里已有 3 个 gpt-image 系模型）。
2. **海报版式固定**：poster_render 是单面板 1200×1600；多图拼接、促销标签、二维码等首页常见版式不支持。若确认该方向，需把 poster_render 泛化（版式模板化）。
3. **prompt 上限 500 字**：沿用了 DashScope 文生图契约的全局上限，对 image_edit（OpenAI 上限远高于此）偏保守；是否按操作/协议放宽待定。
4. **输入无 schema 声明**：运行对话框靠扫描参数引用推导输入键（约定优于配置）；模板作者拼错引用名会导致输入静默缺失。评审点：是否在定义里显式声明 inputs（名称/类型/必填）。
5. **SSRF/安全边界**：供应商 baseUrl 校验在本机部署模式放宽了主机名公网解析校验（VPN fake-IP 场景，bug-2026-10-31-vpn-fakeip）；网页部署模式不放宽。参考图仅取本人 READY 素材，无越权面。
6. **成本与配额**：试穿按次计费、无预估金额提示；三层并发配额已生效，但单用户批量跑 N 套搭配的费用可见性待加强（usage 记录已有，缺 UI 汇总）。
7. **验收缺口**：A31–A34（Agent/工作流端到端）与 C16 总验收仍未执行；本流程是新增能力，尚未纳入正式验收表。

## 6. 建议评审关注的问题

1. image_edit 是否应推广为通用操作（视频首帧/多图合成），以及 DashScope 侧是否补 edits 适配。
2. 模板输入是否升级为显式 schema（类型/必填/示例），以支撑"模板市场"式复用。
3. poster_render 版式模板化的优先级（对淘宝场景，版式多样性可能比换装更关键）。
4. 试穿质量的客观评测方法（同输入多模型 A/B + 人工评分），避免"能出图"≠"能上架"。
5. 批量运行（N 套搭配一次提交）与失败重跑的费用护栏。

## 7. 复现路径

1. 模型设置：新建 openai-compatible 供应商（base_url + key）→ 拉取模型 → 启用生图模型并勾选「图片生成」→ 绑定「图片生成」用途。
2. 创作项目：上传模特图、上衣图、裤子图（或用中转站生成）。
3. 工作流 `taobao-apparel-poster` → 运行 → 填关键词 + 三个图片输入 + 目标项目 → 发起。
4. 运行记录与产物：项目详情「工作流」tab 与素材库「生成结果」分类；海报 PNG 可直接下载。
