# 视频生成与剧情制作：产品及架构方案

日期：2026-11-01。状态：规划稿，未实施。源码基线：`e3caabd`。

## 1. 产品决策与假设

建设一个视频创作模块，提供两条路径，共用视频生成、任务、素材和模型能力：

- **快速生成**：输入描述或参考图，生成一条视频；无需先建剧本、角色或分镜。
- **剧情制作**：故事/剧本 → 角色与场景 → 分镜 → 关键帧 → 分镜视频 → 人工选片 → 排序裁切与字幕 → 成片。

用户已确认首版优先短剧情/短剧，独立视频生成仍是共用基础；商品剧情短片与小说改编保留扩展路径，小说改编通过导入已确认章节的快照进入同一流程。用户确认中转站已经配置，优先复用现有供应商配置，不要求重新配置或在聊天中提供密钥。具体视频模型、接口能力、预算及目标片长尚未核实；“中转站已配置”不能直接等同“视频链路已验证”。

我们自主掌握的是创作数据、分镜规划、资产一致性管理、执行调度、版本、剪辑和成片能力；本方案仍调用外部视频基础模型，不意味着自行训练视频模型。以后接入本地推理也应实现同一适配器契约。

本方案细化原 `2026-10-29-ai-creative-studio.md`、`2026-10-29-ai-creative-implementation.md` 的 C19–C24。画布沿用 2026-10-31 的既定决策：复用现有 VueFlow 和工作流引擎，原“独立自由画布”条目不再是视频发布依赖。

## 3. 首版范围与发布拆分

**V1-A：独立视频可用版。** 文生视频、单参考图/首帧图生视频、单次一个候选、历史与重试、播放/下载/收藏、进入剧情分镜。首发至少有一个实测模型支持两种生成路径；可以由两个经过实测的模型分别覆盖。没有图生视频能力时不能宣告完整 V1-A 通过。

**V1-B：剧情生产版。** 一项目一个故事，首版默认一集；可编辑剧本、角色/场景卡、分镜表、关键帧与视频候选、批量生产、失败项重试、选定结果。数据预留 episode 归属，暂不做复杂多季管理。建议每次批次最多 12 镜头、每镜头最多 2 候选，实际并发由平台/用户/供应商配额共同限制；这些是初始产品上限，可配置。

**V1-C：剧情成片版。** 单视频轨、顺序排列、入出点裁切、字幕轨、片段原声控制、可选一条上传的配音或背景音轨、MP4 导出。最少三镜头闭环。以 30–90 秒短片为首轮场景目标，实际长度由模型片段时长与裁切决定；不承诺一次模型请求生成整部剧情。

后续：首尾帧、视频续写、多图参考、原生音画同步、TTS/声音角色、多轨混音、转场、口型、长剧、协同剪辑。按模型实测逐项开放；首版不把“音频字段存在”当成能生成配音。

## 4. 使用流程与页面

### 4.1 快速生成

1. 创作首页“视频”进入快速生成；默认文生视频，可切换图生视频。
2. 填写描述、选择可用模型及其支持的画幅/时长/清晰度；图生视频选首帧图。提示词优化是独立文本操作，用户可保留原文。
3. 无项目时由服务端幂等创建用户的默认视频收纳项目；已有项目可选择归档位置。用户不必为了生成单条视频填写剧情资料。
4. 提交前显示模型、片段数、参考素材、预计费用（有可信报价时）和预算上限；报价未知明确显示未知，不能标为 0。
5. 显示排队、生成、转存、完成或失败；无上游进度时显示阶段和已耗时，不伪造百分比。
6. 成功后播放、下载、再生成、加入剧情分镜。再生成产生新任务及新资产，原结果保留。

“加入分镜”复用已有资产和权限校验，不重新计费生成。跨项目使用首版采用显式导入为目标项目资源引用/记录，保留来源关系；共享底层文件时按引用计数管理，不能复制短期 URL 冒充导入成功。

### 4.2 剧情制作

按“剧本 / 角色与场景 / 分镜 / 成片”组织页面，允许返回修改，每步展示当前版本与完成条件。

- **剧本**：原创输入、粘贴剧本、小说章节导入。AI 产物先入草稿；支持修改、对比、确认。重新拆解进入新草稿，按稳定镜头 ID 展示差异，不覆盖手工编辑。
- **角色/场景**：名称、描述、视觉锚点、参考素材、版本；明确同一角色在不同服装/场景下的变化。多人镜头标明角色与参考对应关系。
- **分镜表（默认）**：镜号、剧情目的、景别/机位/运动、动作、台词/旁白、目标时长、角色/场景、关键帧、视频候选、选定状态。文本字段有结构化校验，镜头数量和总时长超目标时提示调整。
- **分镜详情**：左侧大预览，右侧当前镜头参数与引用，底部候选；可只重做关键帧或只重做视频。整表批量按钮显示范围、候选数、预计调用与预算。
- **成片**：按镜头选定结果生成可编辑的简单时间线；用户排序、裁切、编辑字幕与音量后预览、导出。未选片镜头必须补齐或显式排除，不能静默遗漏。

剧情制作默认分镜表，比大 DAG 更适合审稿和挑选；高级用户可打开同一工作流的画布。镜头内容/角色/选片保存在剧情领域，工作流只负责一次执行，不让拖动画布修改剧情顺序。

### 4.3 人工质量闸门

剧本确认后才允许批量拆解投产；分镜版本确认后才批量生成；需要参考一致性的镜头先选定关键帧再生视频；所有纳入时间线的镜头必须选片。

闸门保存为领域确认状态，不靠一直打开弹窗。首版每次确认后发起下一阶段的有限运行，不要求实现跨天悬挂的 WAITING_USER。以后增加自动导演模式再扩展持久人工等待。

角色参考、固定风格和首帧可提高一致性，不保证完全一致；相同 seed 也不是身份锁。AI 质检只提供可复核建议，不能自动宣称人物、服装、商品完全保真。

## 5. 模型能力与生成契约

建议操作：`text_to_video`、`image_to_video`；后续按适配器能力增加 `first_last_frame_to_video`、`video_extend`。首版固定一个请求一个结果；多候选拆为多个子任务。

模型用途：新增 `video_generation`；剧本/分镜文本可增加 `story` 场景，未配置时回退可用 chat。视频用途不回退图片或 chat；显式选择的不兼容模型直接报错，不暗中替换。图像关键帧继续使用 image_generation/image_edit。

每个 profile 必须声明：

- 支持操作、参考角色及数量、输入尺寸/格式/时长约束。
- 允许的时长、画幅、分辨率组合；不仅是三个彼此独立的下拉框。
- 原生音频、首尾帧、seed、取消、幂等提交、查询/对账等真实支持情况。
- 提交/查询协议及适配器版本、轮询间隔、最大观察期限、下载限制。
- 经验证的供应商/模型组合与时间、证据；未知能力保持 UNVERIFIED。

首帧引用只能使用模型实际支持的传输方式：上传上游文件，或提供有足够有效期且上游可访问的受限 URL。localhost/私网素材地址不能直接交给外部模型。引用传输失败在生成提交前报错。

现有 InputSnapshot 需兼容扩展结构化引用（assetId、role、order、版本/内容身份），不能仅依赖数组第几个猜测首帧。旧图片 referenceAssetIds 保持兼容读取；同一语义由单一规范化层生成，避免两套字段冲突。

## 6. 业务数据与版本规则

以下是逻辑实体建议，实施前再定迁移编号和最终字段；不提前创建后续阶段空表。

| 实体 | 主要职责 | 关键规则 |
| --- | --- | --- |
| CreativeProject(VIDEO) | 快速生成收纳或剧情项目 | 模式可升级；视频项目允许视频及关键帧图像任务 |
| Story / Episode | 故事设定、集、脚本版本与确认 | 首版一集；顺序事务化；归属强校验 |
| Character / Scene + Revision | 人物/场景描述与引用素材 | 生产冻结明确版本；编辑不改变已生成历史 |
| Shot + ShotRevision | 稳定镜头身份、文本/对白/时长/引用 | 当前草稿与已确认版本分离；乐观锁防覆盖 |
| ShotCandidate | 某镜头某版本的关键帧/视频候选 | 关联 jobId、assetId、来源和质量备注；选定指针有版本条件 |
| ProductionBatch / Item | 已确认范围与子任务清单 | unique(batchId,shotRevisionId,candidateIndex)；状态从子项聚合 |
| Timeline / Revision | 有序片段、裁切、音频与字幕 | 引用确定资产；整数毫秒；导出冻结完整版本 |
| RenderJob | 非模型计费的合成任务 | 关联时间线快照、输出和日志；重试不生成镜头 |

每个子实体和引用必须验证项目及所有者，数据库能表达的归属约束使用组合键/外键，不只依靠前端。素材删除检查活动任务、角色/分镜、时间线及保留的历史版本引用；历史保留政策明确后才做物理清理。

发生关键变更（剧情、动作、角色引用、关键帧、模型/参数）时，新版本标记既有候选“来自旧版本”；仍可查看和显式采用，不自动替换当前选片。仅改显示名称/备注不强制重生成。角色或剧本变更展示受影响镜头，由用户确认更新范围。

小说导入记录 chapterId、确认状态、导入时内容快照与哈希；当前章节没有独立修订实体时不虚构 chapterRevisionId。后续改章不会悄悄更改已确认剧本。

## 7. 共用执行基础

### 7.1 媒体任务

沿用 `QUEUED → SUBMITTING → RUNNING → FETCHING → SUCCEEDED` 及现有 RECONCILING/INGEST_FAILED/取消分支。保留冻结令牌与 epoch/version 围栏，不因等待视频而长期占用数据库事务或工作流线程。

- 创建事务冻结项目、操作、引用、prompt、模型/适配器契约版本、参数与预算占用；幂等哈希包含项目和全部有意义输入。重复意图返回原任务，修改正文复用同键返回冲突。
- taskId 必须持久化后再安排查询；提交超时且不能确认是否受理时进入对账，不自动再付费提交。供应商不支持幂等/按提交键查询时，承认无法保证外部“恰好一次”。
- 恢复从已有 taskId 继续查询。重试分清：重新查询、重新转存、重新生成；前两者不调用 submit。
- 模型完成不等于本地成功：转存、探测与素材 READY 后才 SUCCEEDED。输出 URL 过期时尝试通过原 taskId 重新获取；无法获取则明确 INGEST_FAILED，不伪装重新生成。
- 用户取消与上游完成竞态保留可获取结果；不支持取消时明确“停止后续提交，已提交任务仍可能计费/完成”。

### 7.2 批量生产

批次是业务聚合，不是新的工作流执行引擎。批次项调用现有工作流或 MediaJob 服务，不另写供应商轮询器。默认优先“为全部镜头生成关键帧→选定→生成视频”；相邻镜头沿用末帧仅在明确依赖与能力支持时开启。

冻结批次范围后，每镜头/候选独立意图与任务。建议并发初始值 2，取用户/供应商/全局可用配额最小值；轮询不占提交配额。限流使用退避和抖动。

聚合状态区分运行中、全部成功、部分成功、全部失败、已停止且仍有在途、停止后完成跟踪。人工“已选定”是独立审稿状态，不等同任务成功。重复批次启动、重试与重启不得重复创建子任务。

预算以原子预占限制并发超额；记录估价、已承诺费用和可得实际费用。报价不可信时以最大调用次数/最大时长等可验证上限约束，并展示费用未知。重试是新候选意图，仅对确定需要重生成的失败项执行；未知受理任务不可批量自动重提。

### 7.3 工作流及 Agent

新增 `media_video_generate` 节点，输入含 operation、prompt、模型、受控参数、引用；完成输出沿用既有单资产 `{jobId,assetId,mediaType}` 形态并可增加 durationMs，避免同时迁移所有消费者。节点使用现有 WAITING_EXTERNAL 桥接。

nodeCatalog 的 asset 类型需增加媒体约束：视频不能误接只接受图片的节点；历史 asset 类型与图仍可读取。取消、查询、局部重跑保留上游选定资产身份；若上游已过期或权限失效，发起前失败，不能偷偷换最新版本。

文本拆剧本可复用 llm_text，但结构化分镜必须经领域 schema 校验后保存草稿；数据读写放 Story 服务。Agent 通过相同 API 发起规划/生成/选片建议，不绕过权限、预算、确认版本或改库。画布结构化 Agent 工具仍是独立后续事项，不是视频首版的隐含已完成依赖。

## 8. 视频资产、播放与合成

视频上传/远程转存改为有界流式：下载到任务私有临时文件或受控流，计算哈希和字节上限，再写存储；不将完整视频 byte[] 塞进 JVM、JSON、数据库或浏览器状态。视频配额单独配置，不能只调大图片 20MiB 限制。

使用受控 ffprobe 或等效探测器确认容器、编解码、真实时长、尺寸、帧率和音轨；不信文件扩展名或 Content-Type。封面失败允许使用占位并可补生成，媒体损坏不能 READY。Range 播放支持 200/206/416、正确 Content-Range、权限/签名及拖动续播，LOCAL/OSS 均验证。

复用安全下载边界：每次重定向重新校验目标，限制重定向、总时长和流量，不把模型端点允许本地访问的配置扩散成任意素材下载豁免。FFmpeg 使用受控本地文件和参数数组，限制网络协议、CPU/内存/超时/输出目录；字幕内容按格式转义。

合成使用独立受限 worker/进程，业务状态仍由应用服务管理，不另建编排引擎。桌面构建需显式检测/打包 ffmpeg、ffprobe、中文字体及其平台架构和分发许可；本轮未确认这些运行时存在。

首版统一目标画幅、帧率、编码和音频采样率，默认等比留边，裁切需预览确认；不默认直接拼接不兼容视频。内部整数毫秒，出片按输出 fps 量化；不默认变速补时长。字幕可来自剧本人工对齐，不声称自动语音识别。旁白/背景音缺失时允许纯画面＋字幕明确导出；原生声音只对支持模型开启。

渲染幂等键包含 timelineRevision、资产内容身份、导出配置和渲染器版本。进程异常只重试渲染。旧渲染迟到不得覆盖新成片选定指针；输出通过可播放与时长验证后登记 DERIVED 资产并保留来源。

## 9. 建议接口边界

优先扩展现有 `/ai/creative` 的任务、项目、素材接口，不复制视频专用任务中心。下列为建议资源操作，实施前核对控制器命名和兼容：

- 视频任务：创建/查询/取消/重新转存/重新生成，沿用 MediaJob API。
- 剧情：读写故事及脚本草稿、确认版本、导入小说快照、角色/场景版本管理。
- 分镜：拆解草稿、差异预览、确认、重排、读取候选、带 expectedVersion 选定候选。
- 批次：预估、创建、查询、停止后续项、仅重试确定失败项。
- 成片：保存时间线修订、校验素材、创建渲染、查询/取消、获取成片。

编辑使用乐观锁/版本冲突响应；生成、批次和渲染使用请求幂等键；归属和输入校验在服务端完成。长操作立即返回任务身份，前端轮询或订阅状态，不能等待 HTTP 请求直至整片完成。
