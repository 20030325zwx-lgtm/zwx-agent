## 1. 文档目的

本文解决的不是“再增加哪些页面”，而是统一回答以下核心问题：

1. Aster AI 创作服务的产品定位是什么；
2. 用户应当通过怎样的主线完成一次创作；
3. 已有任务、工作流、素材、模型、Skill、MCP、知识库和视频剧情能力如何组合，而不是继续平铺；
4. 哪些能力属于创作者日常界面，哪些属于系统管理能力；
5. 从当前实现演进到专业创作工作台的阶段、边界和验收标准是什么。

本文是产品与领域架构规划，不宣称所有页面和接口已经存在。凡涉及当前实现，均以 2026-11-02 源码与数据库迁移为准；竞品界面观察仅作为产品判断输入，不代表其内部实现或生成效果已经验证。

## 2. 现状结论

### 2.1 产品问题

当前 Aster 已经具备较多底层能力，但用户首先看到的是“服务概览、任务、工作流、知识库、设置”等系统模块。功能组织方式偏向后台管理系统，创作者需要自行理解模块关系，再拼接成创作流程。

主要问题：

- **入口按技术模块划分，而不是按创作目标划分。** 用户要“做一部短剧”，但导航要求用户分别理解项目、工作流、任务、素材和模型。
- **首页强调系统存量，不强调下一步动作。** 工作区数、会话数、工作流数能说明系统在运行，不能帮助用户开始或继续作品。
- **项目、任务、素材和工作流之间缺乏强上下文。** 它们各自可用，但用户容易在多个页面间丢失“当前在制作哪部作品、哪一集、哪个镜头”。
- **生成结果呈现弱于生成参数。** 专业创作产品应以画面、镜头、版本和候选为主，参数与运行日志应退到详情层。
- **已有视频领域能力未形成可感知的完整生产线。** V17/V18 已有剧集、场次、镜头、候选、选片和批次，却仍容易被理解成普通表单和任务列表。
- **Skill 的用户价值未被产品化。** Skill 目前更接近系统配置；创作者需要看到的是“导演分镜、角色设计、故事开发”等可理解的专业能力。

### 2.2 当前技术与业务基线

截至 2026-11-02，以下能力可直接复用：

| 领域 | 当前能力 | 本规划中的位置 |
| --- | --- | --- |
| 创作项目 | 图片、视频、小说等项目；项目归属与状态 | “作品”主对象 |
| 创作草稿 | 文本草稿、提示词与版本编辑 | 项目编辑与生成前草稿 |
| 媒体任务 | MediaJob、模型快照、输入快照、调度、恢复、重试 | “任务”执行事实来源 |
| 素材 | CreativeAsset、缩略图、下载/播放、来源任务、项目过滤 | 全局与项目素材库 |
| 工作流 | 定义版本、节点画布、运行、产物回写 | 高级自动化与技能执行底座 |
| 小说 | 章节、作品设定、剧情建议、确认 | 小说工作区与短剧输入来源 |
| 视频剧情 | V17：剧集、场次、镜头、角色、地点、连续性记录、候选与选片 | 短剧制作主工作区 |
| 视频批次 | V18：批次、子项、有限并发、停止未提交、失败重试、进度聚合 | 批量生产控制台 |
| 模型 | Provider、Model、用途绑定、配置密文、运行快照 | 创作设置与模型能力路由 |
| Agent | 多步规划、工具调用、会话、运行恢复 | 创作助手与跨模块协调层 |
| Skill/MCP | Skill 配置、动态 MCP、工具授权 | 专业技能与外部能力 |
| 知识库 | 文档解析、切片、向量检索、审批 | 项目参考资料与创作上下文 |

当前明确缺口：

- P4 成片时间线、字幕/音频与受控渲染尚未实现；
- 自由创作画布尚未形成独立领域和稳定交互；
- Skill 缺少面向创作者的技能库、详情、启用和项目绑定体验；
- 素材的业务分类、使用位置反查和回收站体验不完整；
- 创作首页、项目页和全局导航仍未围绕创作主线重构；
- 模型能力、价格和可用输入类型缺少统一的创作前提示；
- 当前通道对多参考图、音频、延长、画幅等真实支持仍需逐模型验证。

## 3. 产品定位

### 3.1 一句话定位

**Aster 是面向个人创作者的可追溯 AI 内容制作工作台，把想法、专业技能、素材、生成任务和作品版本组织成一条可持续迭代的生产线。**

### 3.2 核心用户

首要用户：

- 独立短剧和短片创作者；
- 使用 AI 进行图片、视频、小说创作的个人用户；
- 需要反复生成、比较、选片和复用素材的进阶用户；
- 希望保留生成依据、模型、提示词和版本证据的创作者。

首版不以以下用户为中心：

- 大型影视公司的多部门排期和人力管理；
- 需要复杂权限矩阵和审批流的企业内容中台；
- 专业非线性剪辑师的完整后期工作；
- 面向第三方开发者的插件商业生态。

### 3.3 产品差异化

Aster 不应以“接入更多模型”作为唯一卖点。可持续的差异化来自：

1. **内容结构化**：项目、剧集、场次、镜头、角色、地点和连续性不是一次性 Prompt；
2. **生产可追溯**：素材能回到提示词、参考、模型、任务和采用位置；
3. **候选与审核分离**：生成成功不等于创作完成，用户需要比较、采用和复核；
4. **任务可靠性**：幂等、恢复、失败重试、批次和配额是真实生产能力；
5. **专业技能复用**：把故事开发、导演分镜、角色设计等方法沉淀为可调用能力；
6. **Agent 协作而非替用户做主**：Agent 提建议、组织上下文和执行授权动作，不静默修改已确认事实。

## 4. 产品原则

### 4.1 作品优先，而非服务优先

用户看到的第一对象是作品、镜头、素材和结果。模型供应商、MCP、向量库和调度器属于支撑能力，默认不占据主导航。

### 4.2 上下文连续

用户进入项目后，剧集、镜头、素材、技能和任务都应自动限定在当前项目。任何跳转都保留项目与当前内容位置，避免重新筛选。

### 4.3 结果优先，参数渐进披露

候选画面、视频、版本差异和采用状态优先展示。模型参数、请求快照、供应商日志通过抽屉或详情展开，不与主创作界面争夺注意力。

### 4.4 人工确认是创作环节，不是异常

剧情确认、镜头确认、候选选片和成片确认属于正常流程。系统必须区别“生成成功”“内容已确认”“作品已完成”。

### 4.5 不伪造模型能力

参考图、音频、视频延长、画幅和价格仅在适配器真实验证后显示。未验证能力明确标记为不可用或实验性，不通过 Prompt 文案假装实现。

### 4.6 保留证据，不覆盖历史

新生成、新优化、新裁切产生新版本或新素材。历史提示词、模型快照、参考映射和采用记录可回看；旧任务晚到不能覆盖当前选片。

### 4.7 通用引擎与业务界面分层

业务页面负责作品内容、镜头和选片；工作流画布负责高级流程和自动化。用户不需要为了生成一个镜头先理解节点图。

## 5. 核心对象模型

### 5.1 对象层级

```text
用户
├── 创作偏好 / 模型绑定 / 已启用技能
├── 作品 Project
│   ├── 作品设定
│   ├── 剧集 Episode
│   │   ├── 场次 Scene
│   │   │   └── 镜头 Shot
│   │   │       ├── 提示词版本
│   │   │       ├── 参考素材
│   │   │       ├── 生成候选 Candidate
│   │   │       └── 当前选片
│   │   └── 连续性记录
│   ├── 角色 / 地点 / 道具
│   ├── 项目素材
│   ├── 项目任务
│   └── 成片 Timeline（P4）
├── 全局素材
├── 技能
└── 任务 / 工作流运行
```

图片项目和小说项目使用同一 Project 外壳，但不强制拥有剧集/场次/镜头结构：

- 图片项目：系列、画面草稿、候选和采用素材；
- 小说项目：作品设定、章节、剧情建议和确认稿；
- 视频/短剧项目：剧集、场次、镜头、候选、批次和成片；
- 自由画布：可关联项目，也允许先创作后归档到项目。

### 5.2 三种状态必须分开

| 状态类型 | 回答的问题 | 事实来源 |
| --- | --- | --- |
| 内容状态 | 剧情/镜头是否草稿、已确认、需复核 | 剧情领域记录 |
| 执行状态 | 请求是否待提交、在途、成功、失败、未知 | MediaJob / WorkflowRun |
| 采用状态 | 生成结果是候选、已采用还是淘汰 | ShotCandidate / 资产使用关系 |

不能用一个 `SUCCESS` 同时表达三种含义。

### 5.3 素材语义

素材不仅是文件，还必须回答：

- 属于哪个项目或是否未归档；
- 类型是什么；
- 是角色、地点、道具、镜头候选、首帧、尾帧还是成片；
- 来源于上传、生成、裁切、抽帧还是导入；
- 由哪次任务、哪版提示词、哪个模型产生；
- 当前被哪些项目、剧集、场次和镜头使用；
- 是否已采用、收藏、归档或进入回收站；
- 依据的角色/场景版本是否已经过期。

## 6. 信息架构

### 6.1 一级导航

```text
创作
作品
画布
素材
技能
任务
```

说明：

- **创作**：开始新创作、继续最近工作、选择模式和技能；
- **作品**：管理图片、小说、视频和短剧项目；
- **画布**：自由组织想法、参考和生成结果；
- **素材**：全局可访问素材与项目归档入口；
- **技能**：查找、启用、创建和管理专业创作能力；
- **任务**：生成队列、批次、失败项和运行历史。

以下内容从一级导航移出：

- 模型供应商、MCP、权限、记忆、系统配置：进入“设置”；
- 知识库：进入项目“参考资料”，全局管理入口保留在设置或更多菜单；
- 工作流设计器：进入“自动化/高级工具”，也可从技能详情打开；
- 服务状态：进入设置或运维状态页；
- 通用超级智能体：以右侧创作助手或“Agent 模式”存在，不与创作项目争夺一级入口。

### 6.2 项目内导航

视频/短剧项目：

```text
概览 | 剧情 | 分镜 | 作品设定 | 素材 | 任务 | 成片
```

小说项目：

```text
概览 | 作品设定 | 章节 | 剧情规划 | 素材 | 任务
```

图片项目：

```text
概览 | 创作 | 候选 | 素材 | 任务
```

导航项由项目类型决定，不展示与当前作品无关的空模块。

## 7. 核心用户流程

### 7.1 从想法开始

```text
输入一句想法或上传参考
→ 选择图片 / 视频 / 小说 / Agent
→ 系统推荐项目类型与技能
→ 用户确认创建作品或进入自由画布
→ 生成草稿/方案
→ 人工编辑与确认
→ 发起生成任务
→ 查看候选并采用
→ 归档素材或继续迭代
```

系统不得在用户只输入想法时自动创建大量任务或产生计费调用。创建项目、调用模型、批量生成均是明确动作。

### 7.2 从小说到短剧

```text
导入 TXT / Markdown 或关联小说项目
→ 解析章节与来源快照
→ 选择改编范围和目标风格
→ 生成剧集规划提案
→ 用户确认剧集与剧情
→ 建立角色、地点、道具和参考
→ 细化场次与镜头
→ 确认镜头提示词
→ 单镜头或批次生成
→ 候选对比与选片
→ 连续性复核
→ 进入成片时间线
```

改编过程必须保留小说来源范围。小说后续修改不能静默覆盖已确认剧本。

### 7.3 单镜头生产

```text
选择镜头
→ 补齐剧情目的、动作、摄影和参考
→ 运行连续性与能力校验
→ 预览模型实际提交文本
→ 生成 1~N 个候选
→ 查看任务状态与结果
→ 采用一个候选或继续生成
→ 标记镜头完成/待复核
```

### 7.4 批次生产

```text
在分镜表勾选可生成镜头
→ 选择候选数量与并发上限
→ 检查缺失参考和配额
→ 创建持久批次
→ 展示待提交/在途/成功/失败/停止
→ 只重试失败项
→ 所有任务收敛后进入待选片队列
```

“停止”沿用现有语义：停止未提交子项；在途任务是否可取消取决于供应商能力，不能承诺停止计费。

### 7.5 素材复用

```text
在项目或全局素材库查找素材
→ 查看来源和使用位置
→ 指定参考用途
→ 关联到角色/地点/镜头
→ 生成时冻结引用快照
→ 使用位置可反查
```

跨项目使用必须显式导入或复制引用，不能因为同一用户可见就绕过项目隔离。

## 8. 页面规划

### 8.1 创作首页

首页目标：让用户在 10 秒内知道“能做什么、从哪里开始、接下来继续什么”。

首屏结构：

1. 主创作输入区；
2. 图片 / 视频 / 小说 / Agent 分段选择；
3. 上传参考、选择素材、引用技能；
4. 主操作“开始创作”；
5. 最近作品和继续创作；
6. 最近任务及需要处理的失败/待确认项；
7. 灵感或模板入口，放在首屏之后。

不在首页首屏展示：

- 工作区、知识文档、工作流数量组成的一排统计卡；
- 模型供应商和内部服务状态；
- 大段产品功能说明；
- 与当前用户没有数据关系的空卡片。

### 8.2 作品列表

必须支持：

- 按图片、小说、视频、短剧筛选；
- 搜索标题和标签；
- 最近更新、创建时间和状态排序；
- 项目封面使用真实最近产物；
- 卡片显示当前进度、待处理事项、最近活动；
- 新建、复制、归档，不在卡片上堆叠所有管理动作。

### 8.3 短剧项目工作区

推荐三栏结构：

- 左栏：剧集 → 场次 → 镜头树；
- 中栏：当前剧情、分镜或候选主工作区；
- 右栏：角色/地点/道具引用、提示词版本、连续性和生成设置；
- 底部可展开区域：任务、日志、批次和费用信息。

顶部持续显示：项目名、剧集选择、制作进度、待选片数、阻塞数和主操作。

### 8.4 分镜页

支持表格与卡片两种视图：

- 表格适合批量检查、排序和生成；
- 卡片适合查看缩略图、候选和连续性；
- 镜头详情使用抽屉或右侧面板，不频繁离开当前剧集；
- 多选后允许批量生成、批量标记、分配参考；
- 生成按钮仅对满足条件的镜头启用，并解释阻塞原因。

镜头详情分区：

1. 剧情意图；
2. 画面、动作与表演；
3. 摄影、光线与声音意图；
4. 角色、地点和道具参考；
5. 提示词原稿、优化稿和实际提交稿；
6. 候选与当前选片；
7. 任务和历史版本。

### 8.5 素材库

全局素材库提供聚合检索，项目素材库默认锁定当前项目。

筛选维度：

- 媒体类型：文本、图片、视频；音频在真实接入后开放；
- 业务类型：角色、地点、道具、镜头、成片、通用参考；
- 项目、剧集、场次、镜头；
- 候选、已采用、参考、上传、收藏、未归类；
- 来源任务、模型、创建时间和标签。

素材详情优先展示媒体和引用关系，技术元数据折叠展示。

### 8.6 技能库

技能分类：

- 技能广场；
- 我的技能；
- 我创建的；
- 收藏；
- 当前项目已启用。

技能详情契约：

| 字段 | 说明 |
| --- | --- |
| 名称与定位 | 用户能理解的专业能力名称 |
| 适用场景 | 何时建议使用 |
| 不适用范围 | 防止错误调用 |
| 输入要求 | 必填素材、字段和前置状态 |
| 输出 | 草稿、表格、素材、任务或项目修改 |
| 工具与模型 | 所需模型用途和 MCP/工作流 |
| 风险等级 | 是否会生成计费、修改确认内容或访问外部服务 |
| 示例 | 输入、过程摘要和真实输出类型 |
| 版本 | 更新记录和兼容性 |

首批系统技能：

1. 故事开发；
2. 剧本撰写；
3. 角色设计；
4. 世界观与场景设定；
5. 导演分镜；
6. 视频提示词优化。

首版只做官方内置与用户自建，不做付费市场、排行榜和开放作者结算。

### 8.7 任务中心

任务中心不是日志列表，应围绕“需要用户处理什么”组织：

- 生成中；
- 待选片；
- 失败可重试；
- 输入缺失；
- 已完成；
- 已停止。

每条任务展示业务标题，例如“第 2 集 / 第 3 场 / 镜头 04 · 生成候选”，而不是只展示任务 UUID 或供应商状态。

详情内再展示：模型、输入快照、供应商 ID、尝试链、错误和运行日志。

### 8.8 自由画布

自由画布定位为探索和组合空间，不代替短剧分镜和工作流设计器。

首版节点：

- 文本便签；
- 图片/视频素材；
- Prompt；
- 角色/地点引用；
- 生成结果；
- Agent 对话；
- 分组和连线。

首版必须完成的闭环：在画布选择素材和 Prompt → 发起生成 → 结果回到画布 → 保存到素材库或归档到项目。

暂不支持：多人实时协作、无限历史分支、完整节点式工作流执行、复杂矢量绘图。

### 8.9 成片工作区（P4）

P4 目标是完成短剧最小成片闭环，不建设完整 Premiere 类编辑器。

最小能力：

- 按镜头顺序加载已选视频；
- 调整顺序和基础入/出点；
- 导入或编辑字幕；
- 导入背景音乐和旁白；
- 基础音量设置；
- 预览总时长与缺失镜头；
- 受控 FFmpeg 渲染；
- 导出 MP4 并保留素材、镜头和任务来源。

明确不做：多轨特效、关键帧动画、高级调色、复杂转场库和第三方剪辑工程格式。

## 9. Agent 规划

### 9.1 产品形态

Agent 采用两种入口：

- 创作首页的 Agent 模式：从模糊想法开始；
- 项目内右侧助手：理解当前项目、剧集、镜头和素材上下文。

Agent 不应作为遮挡内容的永久悬浮球。桌面端使用可折叠侧栏；移动端使用全屏抽屉。

### 9.2 能力边界

Agent 可以：

- 解释当前项目状态；
- 推荐下一步和适用技能；
- 根据授权读取项目内容；
- 提出剧情、镜头和 Prompt 修改建议；
- 创建草稿、发起已确认的生成任务；
- 汇总失败原因和待处理事项。

Agent 不可以：

- 静默覆盖已确认剧情或当前选片；
- 在未确认时发起批量计费生成；
- 把模型推断当作项目既定事实；
- 跨项目读取未授权内容；
- 声称已识别图片中不存在或未经视觉模型验证的信息。

### 9.3 上下文策略

项目内 Agent 使用定向上下文：

```text
作品设定
+ 当前剧集确认稿
+ 当前场次与相邻场次
+ 当前镜头
+ 实际关联角色/地点/道具版本
+ 当前候选与任务状态
+ 用户明确选择的参考资料
```

不默认把整个项目、所有历史会话和全部知识库塞入一次调用。

## 10. 模型与费用体验

### 10.1 模型选择

创作者看到的是能力选择，不是 Provider 配置表：

- 当前默认图片模型；
- 当前默认视频模型；
- 当前默认文本/规划模型；
- 是否支持参考图、音频、画幅、时长和延长；
- 预计消耗仅在有可靠价格数据时显示。

Provider、密钥和模型绑定仍在设置中管理。

### 10.2 生成前检查

生成确认区展示：

- 模型与操作类型；
- 候选数量；
- 输入素材；
- 不支持或将被忽略的参数；
- 配额和并发；
- 已知价格或“价格未知”；
- 是否属于计费动作。

不得虚构费用，也不能因为价格未知就隐藏计费风险。

## 11. 视觉与交互系统

### 11.1 视觉方向

Aster 保留克制、专业、偏生产工具的品牌气质，不直接复制其他产品的紫色渐变、悬浮装饰或卡片形式。

建议：

- 主背景使用中性灰白，工作面使用白色或深色中性层；
- 一个主强调色，仅用于当前选择、主操作和进度焦点；
- 状态色只表达状态，不作为大面积装饰；
- 卡片圆角不超过现有设计系统标准，减少“卡片套卡片”；
- 创作媒体使用真实缩略图，不使用统一占位图标代替结果；
- 内容区标题紧凑，避免后台页面中的超大空白标题区；
- 表格、时间线、分镜板等固定格式组件使用稳定尺寸，避免动态内容导致布局跳动。

### 11.2 信息密度

- 首页低密度，突出开始和继续；
- 项目概览中密度，突出进度和阻塞；
- 分镜、素材和任务页高密度，支持扫描、筛选和批量操作；
- 运行日志、模型参数和审计证据按需展开。

### 11.3 空状态

空状态必须包含：

1. 当前为什么为空；
2. 用户可以执行的首要动作；
3. 可选示例或导入方式；
4. 不展示无意义的统计数字和大面积装饰。

## 12. 技术实施边界

### 12.1 前端重组

建议新增或拆分：

```text
frontend/src/views/creation/
├── CreationHome.vue
├── ProjectLibrary.vue
├── project/
│   ├── ProjectShell.vue
│   ├── ProjectOverview.vue
│   ├── StoryWorkspace.vue
│   ├── StoryboardWorkspace.vue
│   ├── ProjectAssets.vue
│   ├── ProjectTasks.vue
│   └── FinalCutWorkspace.vue
├── assets/
├── skills/
├── canvas/
└── tasks/
```

实际实施可渐进迁移现有 `views/creative`，不要求一次改目录。优先拆分过大的 `CreativeProject.vue`，保留现有 API 与共享素材加载逻辑。

### 12.2 后端边界

- `creative/story`：内容、角色地点、连续性与确认；
- `creative/production`：候选、批次、选片和后续时间线；
- `creative/service`：项目、草稿和通用创作服务；
- `platform/workflow`：通用工作流，不承载短剧剧情规则；
- `capability/skill`：技能定义、版本、启用与执行适配；
- `capability/mcp`：外部工具连接，不直接成为用户创作对象。

### 12.3 数据演进

后续迁移不得破坏现有 V17/V18 数据：

- 已有项目、素材、任务和候选身份保持不变；
- 新业务分类允许为空，旧素材显示“未归类”；
- 新时间线引用已选候选，不复制或覆盖原视频；
- Skill 版本冻结到运行快照；
- 回收站优先使用软删除/状态，不立即清除对象；
- 新增项目引用必须验证 tenant、owner 和 project 组合归属。

## 13. 分阶段路线图

### M0：产品外壳收敛

目标：不改变生成内核，先让产品围绕创作主线可理解。

交付：

- 新一级导航；
- 新创作首页；
- 作品列表与真实封面；
- 最近作品、待处理任务和继续创作；
- 设置、知识库、模型、MCP 和工作流设计器降级到二级入口；
- 统一创作页面视觉令牌与空状态。

验收：

- 新用户无需进入工作流/设置即可创建图片、小说或视频项目；
- 用户可从首页一步继续最近项目；
- 首页不再以服务统计卡为主体；
- 现有任务、工作流、知识库和设置路由仍可访问。

### M1：短剧工作区产品化

目标：把已实施 P0-P3 从能力集合变成完整制作界面。

交付：

- 项目 Shell 与剧集/场次/镜头树；
- 剧情、分镜、作品设定、素材、任务分区；
- 镜头详情右侧面板；
- 候选媒体对比与选片；
- 批次面板并入分镜上下文；
- 阻塞原因、待选片和待复核统一呈现。

验收：

- 用户在一个项目页面完成“改剧情→确认镜头→生成→选片”；
- 不需要跳到全局任务页才能判断当前镜头状态；
- 同一角色/地点素材可跨集复用且可反查；
- 批次失败项可在原剧集上下文重试。

### M2：素材中心重构

目标：让生成结果成为可管理、可复用、可追溯的资产。

交付：

- 全局/项目素材视图；
- 业务类型、来源、使用位置和采用状态；
- 素材详情来源链；
- 未归类、收藏、归档、回收站；
- 批量标签和关联；
- 已使用素材的删除保护。

验收：

- 任一候选可回到任务、Prompt、模型和镜头；
- 任一角色参考可查到使用镜头；
- 删除在用素材会明确阻止并展示引用；
- 旧素材无需重新生成即可归类和采用。

### M3：技能产品化

目标：把系统能力包装为可理解、可选择、可复用的专业方法。

交付：

- 六个内置技能；
- 技能列表、详情、启用、收藏和项目绑定；
- 输入输出契约；
- Agent 推荐技能；
- 运行时冻结技能版本；
- 高风险/计费动作确认。

验收：

- 用户能从创作首页选择技能并完成一次真实创作；
- Skill 详情明确适用与不适用范围；
- 技能升级不改变历史运行解释；
- 未授权工具不会因安装技能自动获得权限。

### M4：最小自由画布

目标：支持非线性探索，但不复制工作流设计器。

交付：

- 文本、媒体、Prompt、引用和生成结果节点；
- 分组、连线、缩放和平移；
- Agent 侧栏；
- 画布发起生成；
- 保存到素材库/项目；
- 自动保存和恢复。

验收：

- 用户可从参考图和一句话生成结果并留在同一画布；
- 刷新后画布恢复；
- 结果可以归档到项目并保留来源；
- 画布节点不直接修改已确认短剧内容。

### M5：P4 成片

目标：完成从已选镜头到可下载成片的最小闭环。

交付与验收采用本文 8.9 的范围。

### M6：质量与运营闭环

目标：用真实数据证明产品可用，而不是只证明页面存在。

交付：

- 漏斗与失败原因统计；
- 提示词版本和候选采用率；
- 模型/技能真实成功率；
- 项目级成本与任务耗时；
- 关键流程自动化回归；
- 云端与桌面端一致性检查。

## 14. 优先级

| 优先级 | 内容 | 理由 |
| --- | --- | --- |
| P0 | M0 产品外壳、M1 短剧工作区 | 直接改变用户对产品价值和专业度的判断；复用能力最多 |
| P1 | M2 素材中心、M3 技能产品化 | 建立复用和专业方法壁垒 |
| P2 | M5 成片 | 完成视频端到端交付，但依赖已选片和素材管理稳定 |
| P3 | M4 自由画布 | 价值高但实施成本大，不应阻塞短剧闭环 |
| 持续 | M6 质量与运营 | 每阶段同步建设，不单独拖到最后 |

自由画布不应因为参考产品具有该入口而提前成为最高优先级。当前 Aster 的独特优势是已经具备结构化剧情、候选、选片和可靠批次生产，先把这些能力产品化更能体现技术水平。

## 15. 核心指标

指标只用于验证产品决策，不将纯访问量当作创作价值。

### 15.1 激活

- 首次进入到创建第一个项目的完成率；
- 首次创建到产生第一个可预览素材的完成率；
- 首次创作所需步骤数和中断原因。

### 15.2 生产效率

- 从创建项目到首个候选的时间；
- 从镜头 READY 到产生候选的时间；
- 批次成功、失败、停止和恢复比例；
- 每个采用素材平均重生成次数。

### 15.3 创作质量代理指标

- 候选采用率；
- 提示词优化后的人工采纳率；
- 因连续性问题触发的复核数及解决率；
- 已采用素材的复用次数；
- 生成成功但从未查看/采用的比例。

这些指标不能替代人工质量评估。提示词长度、AI 自评分和模型请求成功率都不能直接证明作品质量。

### 15.4 留存

- 用户是否继续同一作品；
- 一周内再次进入项目并完成有效编辑/生成/选片；
- 素材与技能是否被跨任务复用。

## 16. 非目标与明确不做

当前规划周期内不做：

- 大型团队的部门、排期、工时和薪酬管理；
- 多人实时协同画布与复杂冲突合并；
- 完整专业 NLE 剪辑器；
- 未验证的声音克隆、数字人和口型同步承诺；
- 开放式付费技能/插件市场；
- 为展示功能而重复建设一套任务、工作流或素材引擎；
- 用一个万能聊天框替代项目、镜头、选片和任务状态；
- 直接复制参考产品的视觉资产、品牌和交互细节。

## 17. 风险与控制

| 风险 | 表现 | 控制方式 |
| --- | --- | --- |
| 页面重构破坏现有功能 | 路由、任务和工作流入口丢失 | 渐进迁移，保留旧路由重定向和回归清单 |
| 领域状态混用 | 成功任务被误判为完成镜头 | 内容/执行/采用三状态分离 |
| 模型能力描述失真 | UI 显示支持但通道不支持 | 能力矩阵以适配器实测为准 |
| Agent 越权修改 | 已确认剧情被自动覆盖 | 提案/采纳分离，版本条件和确认门禁 |
| 跨项目数据泄露 | 同用户不同项目素材被错误引用 | 服务端父子归属校验，不能只靠前端筛选 |
| 批量生成失控 | 重复计费、恢复后重提 | 复用现有幂等、租约、候选预建和批次唯一意图 |
| 画布过早膨胀 | 大量编辑器成本阻塞核心闭环 | M4 后置，首版节点和交互严格限界 |
| 成片能力膨胀 | 试图实现完整剪辑软件 | 只交付顺序、基础裁切、字幕、音频与导出 |

## 18. 实施门禁

每个里程碑开始前必须明确：

1. 当前源码和迁移基线；
2. 复用与新增的领域边界；
3. 不可逆数据操作和回滚路径；
4. 真实模型能力和计费授权；
5. 桌面端与网页端差异；
6. 跨用户、跨项目和旧数据兼容测试；
7. 可点击原型或页面结构评审；
8. 验收数据集和失败场景。

任何阶段不得以“先做出来再补安全、状态和恢复”绕过已有工程底线。

## 19. 第一批执行建议

下一批实施建议只做 M0 + M1 的界面与信息架构收敛，不同时启动技能市场、自由画布和 P4：

1. 建立新的创作导航和 ProjectShell；
2. 重做 CreativeHome，使主输入、最近作品和待处理任务成为首屏；
3. 将现有 StoryWorkspace 嵌入 ProjectShell；
4. 拆分剧情、分镜、设定、素材和任务标签；
5. 把 ShotDrawer 重组为镜头右侧工作面板；
6. 让候选媒体、选片和批次进度成为分镜页主视觉；
7. 保留旧路由和 API，完成页面回归后再清理旧组件；
8. 用真实已有视频项目做浏览器端验收，不使用只有占位数据的静态展示证明完成。

第一批完成后，Aster 应当能够明确展示其真正的技术能力：它不是一个把多个 AI 接口放在一起的后台，而是一套能管理长篇内容结构、角色与场景连续性、镜头候选、可靠生成任务和最终采用依据的创作生产系统。
