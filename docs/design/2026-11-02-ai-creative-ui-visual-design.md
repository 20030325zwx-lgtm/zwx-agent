# Aster AI 创作 UI 视觉与交互设计规范

- 日期：2026-11-02
- 状态：视觉设计基线，实施前需以真实页面和真实数据完成评审
- 关联规划：[Aster AI 创作核心产品规划](./2026-11-02-ai-creative-core-product-plan.md)
- 适用范围：创作首页、作品、项目工作区、短剧制作、素材、技能、任务，以及这些页面共用的导航、面板、弹窗和状态组件

## 1. 文档目标

本文将“界面需要更专业”转化为可执行的设计约束，解决以下问题：

1. Aster 应当呈现怎样的产品气质；
2. 当前界面为什么仍像后台系统，而不像创作工具；
3. 页面、组件、颜色、字号、密度、动效和媒体展示应如何统一；
4. 创作首页、短剧工作区和素材库应怎样重构；
5. 前端应按什么顺序实施，如何判断视觉改造真正完成。

本文只定义 UI 视觉和交互表达，不改变核心产品规划中的业务边界，不把参考产品中出现的功能视为 Aster 已具备的能力。

## 2. 调研依据与边界

### 2.1 本次直接观察

本次结论来自以下可验证输入：

- 用户提供的“幻映 AI 素材库”截图；
- 已登录参考站点中创作首页、短剧制作、自由画布、技能和素材等页面的可见结构；
- Aster 当前 `/creative` 页面及其全局导航；
- Aster 当前 `GlobalNav.vue`、`CreativeHome.vue`、`CreativeAssets.vue`、`CreativeProject.vue`、`StoryWorkspace.vue`、`creative.css` 和设计令牌实现。

对参考站点的观察仅用于分析界面结构、信息层级和交互组织，不代表已验证其内部技术、模型效果或商业能力。

### 2.2 参考产品提炼

以下产品只提炼公开、成熟的设计方法，不复制其品牌、素材或具体布局：

| 参考方向 | 可借鉴方法 | Aster 的转化方式 |
| --- | --- | --- |
| Linear | 高信息密度、克制层级、键盘友好 | 任务和批次使用紧凑行式布局，减少装饰性卡片 |
| Figma | 工具区、画布区、属性区职责清晰 | 项目工作区采用导航、内容、检查器三层结构 |
| Runway / Adobe Firefly | 结果媒体优先，生成参数次级呈现 | 候选画面占主要面积，参数进入右侧检查器 |
| Frame.io | 审核状态、版本和反馈围绕媒体组织 | 镜头候选明确“生成成功、待选、已采用”状态 |
| Lightroom | 素材网格、筛选、预览和元数据协同 | 素材库采用稳定缩略图网格和右侧详情面板 |
| Notion | 渐进披露、低干扰编辑 | 不常用配置进入抽屉、Popover 或设置页 |
| 幻映 AI | 清晰的一级导航、素材分类和可行动空状态 | 借鉴结构逻辑，不复制倾斜素材图、品牌色和浮动助手外观 |

### 2.3 明确不参考

- 不复制参考产品 Logo、插画、示例图片、文案和品牌色；
- 不照搬大面积紫色、蓝紫渐变或发光球体；
- 不用“玻璃拟态”“科技感光效”掩盖信息层级问题；
- 不因为竞品有自由画布、插件或 3D 素材，就在 Aster 中制造未实现入口；
- 不使用虚构的生成结果或永远不会出现的理想数据证明设计完成。

## 3. 当前 UI 诊断

### 3.1 已经做对的部分

- 创作、作品、素材、任务已经进入一级导航，系统模块被降级到“更多”；
- 创作首页已经围绕“输入想法 → 选择类型 → 开始创作”组织；
- 使用 Lucide 图标，并已有浅色/深色主题和语义化设计令牌；
- 素材、任务、项目和视频剧情已有真实数据与状态基础；
- 页面不是静态概念稿，现有功能可作为渐进改造的底座。

### 3.2 主要视觉问题

#### 层级仍依赖卡片和边框

大量区域使用相近的白色表面、边框和圆角，标题、筛选、内容和操作之间的层级不够明显。用户首先看到的是多个矩形容器，而不是作品、镜头或候选结果。

#### 设计令牌存在两套语言

`frontend/src/style.css` 中仍保留蓝色渐变背景、较大的 14-18px 圆角和 `--sk-*` 体系；工作台又使用 `--wb-*`。两套令牌并存会造成页面质感和组件行为不一致。

#### 圆角和胶囊使用偏多

当前通用卡片采用 12-16px 圆角，筛选和状态大量使用胶囊。创作工具需要稳定、精确和高密度，过多大圆角会使界面偏消费产品或展示页。

#### 字体层级过碎

界面同时出现 10.5、11、11.5、12、12.5、13、13.5、14、15、16 等字号。差异过细，既增加维护成本，也不能形成稳定层级。

#### 媒体结果没有成为视觉中心

短剧工作区仍以表格文本为主，镜头候选藏在详情抽屉中。用户制作视频时，画面、候选和采用状态应比字段说明更醒目。

#### 宽屏空间利用不足

创作首页和素材空状态在宽屏上容易出现大面积无意义留白；项目工作区又可能因信息集中在单列中显得拥挤。不同页面需要不同的容器策略，不能统一限制为一个窄内容列。

#### 状态表达不统一

同类状态在不同文件中存在硬编码颜色。任务状态、内容确认状态、候选采用状态也容易被放在同一种标签组件里，造成语义混淆。

### 3.3 参考截图的有效启发

用户提供的素材库截图有以下优点：

- 左侧一级导航与素材页内分类分开，用户知道自己处于哪个层级；
- 页面标题、容量、主操作和筛选分区清楚；
- 空状态不是一句“暂无数据”，而是提供新建、导入和从其他工作区保存三条行动路径；
- 主按钮和次按钮区分明确；
- 素材类型、业务分类和用户分类不是混在同一个下拉框里。

同时也不应直接照搬：

- 超宽屏下空状态装饰图占据较大空间；
- 倾斜素材图只适合空状态，不适合真实素材网格；
- 三组侧栏会压缩中等屏幕内容宽度；
- 浮动助手与 Aster 当前核心工作流没有直接关系。

## 4. 视觉定位

### 4.1 关键词

**克制、专业、媒体优先、结构清晰、可长时间工作。**

Aster 的视觉不应像营销网站，也不应像基础管理后台。更合适的方向是“影视制作台 + 精密创作工具”：背景安静，控件可靠，媒体醒目，状态准确。

### 4.2 视觉叙事

- 页面背景和工具区保持中性，让图片与视频自然成为色彩来源；
- 品牌色只表示主操作、选中和焦点，不铺满大面积背景；
- 内容组织依赖间距、对齐、分隔线和字体权重，而不是层层卡片；
- 阴影只用于浮层和临时覆盖关系，不用于普通页面分区；
- 工作区强调“正在制作什么”和“下一步做什么”，不强调系统有多少模块。

### 4.3 视觉原则

1. **媒体先于容器**：先确定画面和视频的展示面积，再放文字和操作。
2. **层级先于装饰**：没有清晰层级时，不通过渐变、光效或插画补救。
3. **密度服务任务**：首页适度舒展，镜头表和任务中心保持高密度。
4. **状态必须可读**：不能只靠颜色，状态同时包含文本、图标或形状。
5. **渐进披露**：高频操作常驻，模型参数、日志和来源快照按需展开。
6. **布局稳定**：加载、悬停、状态变化和长文本不能让主要区域跳动。

## 5. 设计令牌

以下为目标令牌。实施时应统一进入 `frontend/src/design/tokens.js`，由 `--wb-*` 向组件提供，不再扩展 `--sk-*`。

### 5.1 浅色主题

| 语义 | 建议值 | 使用位置 |
| --- | --- | --- |
| 页面背景 | `#F7F7F8` | 主内容底色 |
| 导航背景 | `#F1F1F3` | 全局侧栏 |
| 一级表面 | `#FFFFFF` | 输入区、检查器、弹窗 |
| 次级表面 | `#FAFAFB` | 表头、内嵌分组 |
| 悬停填充 | `#F0F1F3` | 列表和按钮悬停 |
| 主边框 | `#E3E4E7` | 分隔和控件边界 |
| 强边框 | `#CDCFD4` | 选中前的可交互边界 |
| 主文字 | `#18191C` | 标题和正文 |
| 次文字 | `#5E626B` | 描述、元数据 |
| 弱文字 | `#8D919A` | 占位、时间 |
| 品牌色 | `#2563EB` | 主操作、选中、焦点 |
| 品牌悬停 | `#1D4ED8` | 主按钮悬停 |
| 品牌弱底 | `#EAF1FF` | 选中项和信息提示 |
| 成功 | `#16803C` | 完成、已采用 |
| 警告 | `#A15C00` | 待确认、部分完成 |
| 危险 | `#C9364F` | 失败、删除 |
| 信息 | `#2563EB` | 运行中、提示 |

页面背景不使用径向渐变。媒体缩略图本身已经提供足够色彩，工作区背景应保持稳定。

### 5.2 深色主题

深色主题使用中性炭黑，不使用大面积深蓝：

| 语义 | 建议值 |
| --- | --- |
| 页面背景 | `#111214` |
| 导航背景 | `#17181B` |
| 一级表面 | `#1C1E22` |
| 次级表面 | `#222429` |
| 悬停填充 | `#292C31` |
| 主边框 | `#30333A` |
| 强边框 | `#444850` |
| 主文字 | `#F1F2F4` |
| 次文字 | `#B4B7BE` |
| 弱文字 | `#7F838C` |
| 品牌色 | `#6B93FF` |

图片和视频周围可使用更深的媒体舞台 `#0B0C0E`，但不把整个产品都变成黑色播放器。

### 5.3 字体

字体栈继续使用系统字体：

```css
-apple-system, BlinkMacSystemFont, "SF Pro Text", "PingFang SC",
"Microsoft YaHei", "Helvetica Neue", sans-serif
```

字号只保留以下层级：

| 层级 | 字号/行高 | 字重 | 用途 |
| --- | --- | --- | --- |
| Page title | 24/32 | 650 | 页面唯一主标题 |
| Section title | 16/24 | 600 | 页面分区标题 |
| Panel title | 14/22 | 600 | 抽屉、面板标题 |
| Body | 14/22 | 400 | 主要正文和输入 |
| Compact body | 13/20 | 400/500 | 表格、工具栏、元数据 |
| Caption | 12/18 | 400 | 时间、来源、帮助文本 |

规则：

- 不使用 10.5px 和 11px 承载必要信息；
- 字号不随视口宽度缩放；
- 所有界面文字 `letter-spacing: 0`；
- 中文标题依赖字号和字重建立层级，不使用全大写或扩展字距；
- 数值、ID 和日志可使用等宽字体，但不用于普通正文。

### 5.4 间距

采用 4px 基础网格：`4 / 8 / 12 / 16 / 20 / 24 / 32 / 40 / 48`。

- 图标与文字：8px；
- 紧凑控件之间：8px；
- 表单字段之间：16px；
- 同一内容组：12-16px；
- 页面分区：24-32px；
- 页面水平安全边距：桌面 32px，中屏 24px，移动端 16px。

不允许通过零散的 5、7、9、14、18px 间距“目测修正”布局。

### 5.5 圆角

| 对象 | 圆角 |
| --- | --- |
| 小按钮、输入框、菜单项 | 6px |
| 卡片、缩略图、面板 | 8px |
| 弹窗、大型抽屉 | 10px |
| 状态圆点、头像 | 50% |

胶囊形状只用于状态、筛选条件和分段控制，不用于普通命令按钮。

### 5.6 边框和阴影

- 页面分区优先使用留白或 1px 分隔线；
- 普通卡片使用边框，不使用阴影；
- 下拉菜单：`0 8px 24px rgba(0, 0, 0, 0.12)`；
- 抽屉/弹窗：`0 18px 48px rgba(0, 0, 0, 0.18)`；
- 焦点环：2px 品牌色，外偏移 2px；
- 禁止多层蓝色阴影和发光效果。

## 6. 布局系统

### 6.1 全局框架

桌面端采用稳定的工具型布局：

```text
┌────────────┬──────────────────────────────────────────────┐
│ 全局导航   │ 页面标题 / 项目标题 / 全局操作              │
│ 208 / 64px ├──────────────────────────────────────────────┤
│            │ 页面内容                                     │
│            │                                              │
└────────────┴──────────────────────────────────────────────┘
```

- 展开导航 208px，收起导航 64px；
- 顶部页面栏 56px，仅在需要面包屑、项目状态或全局操作时出现；
- 导航和内容之间只使用边框，不加投影；
- 当前页面高亮使用浅填充和左侧 2px 指示，不使用大面积品牌色按钮。

### 6.2 页面宽度策略

不同页面使用不同容器，不再统一套用 `max-width: 1120px`：

| 页面 | 宽度策略 |
| --- | --- |
| 创作首页 | `max-width: 1180px`，居中 |
| 作品列表 | 充满内容区，最大 1440px |
| 素材库 | 充满内容区，筛选栏固定 220px |
| 项目工作区 | 全宽，不设内容最大宽度 |
| 任务中心 | 全宽，列表 + 详情分栏 |
| 设置表单 | `max-width: 920px` |

### 6.3 项目工作区

短剧和复杂项目采用三段式：

```text
┌──────────┬──────────────────────────────┬─────────────┐
│ 项目导航 │ 主制作区                     │ 检查器      │
│ 200px    │ min 640px                    │ 360-420px   │
│ 剧情     │ 剧集/场次/镜头/候选          │ 参数/来源   │
│ 分镜     │                              │ 生成/状态   │
│ 素材     │                              │             │
│ 任务     │                              │             │
└──────────┴──────────────────────────────┴─────────────┘
```

- 检查器只在选中对象时出现；
- 检查器出现后主制作区宽度不得小于 640px，否则以覆盖式抽屉呈现；
- 用户选中镜头、候选或任务后，右侧内容随对象切换，不跳转到新页面；
- 项目导航不重复全局导航中的“作品、素材、任务”，只表达当前项目内部结构。

### 6.4 响应式

| 视口 | 行为 |
| --- | --- |
| `>= 1440px` | 完整三栏，素材 5-6 列 |
| `1100-1439px` | 全局导航收起，检查器 360px |
| `768-1099px` | 项目导航收起为图标栏，检查器覆盖打开 |
| `< 768px` | 单栏浏览；复杂分镜只保证查看和轻量编辑，不承诺完整桌面制作体验 |

移动端不把三栏简单压缩到一屏，也不允许按钮文本被截断或覆盖内容。

## 7. 导航与页面骨架

### 7.1 一级导航

建议顺序：

1. 创作
2. 作品
3. 素材
4. 技能（能力完成产品化后再上线）
5. 任务

画布在能力稳定前不进入一级导航。工作流、知识库、智能体和服务概览放入“系统工具”区域，视觉上降一级。

### 7.2 页面标题栏

标准结构：

```text
[面包屑/返回]
[页面标题] [数量或状态]                         [次操作] [主操作]
[一句必要说明或当前上下文]
```

规则：

- 页面只能有一个 24px 主标题；
- 数量使用普通次文字，不做醒目徽章；
- 主操作最多一个；
- “更多”操作使用省略号图标菜单；
- 说明文案只解释当前状态或业务约束，不介绍产品卖点。

### 7.3 工具栏

- 搜索、视图、排序和筛选在同一水平工具栏；
- 多选后工具栏切换为批量操作模式，不额外堆一排按钮；
- 筛选条件超过三个时使用筛选面板，并在工具栏显示已应用数量；
- 图标按钮必须有 Tooltip 和可访问名称；
- 高频命令使用图标 + 文本，熟悉的关闭、更多、排序等使用图标按钮。

## 8. 核心页面设计

### 8.1 创作首页

目标：用户 10 秒内能开始新作品，或继续最近的作品。

首屏结构：

1. 简短标题“开始创作”；
2. 主输入框，支持一句想法；
3. 图片、视频、小说等类型分段控制；
4. 最近作品，以真实封面或稳定占位图展示；
5. 待处理事项，只显示失败、待确认和进行中；
6. 模板/技能入口放在首屏下方，不与主输入争夺注意力。

设计要求：

- 主输入宽度 680-760px，高度 120-152px；
- 不做营销 Hero，不使用超大标题和装饰渐变；
- 最近作品卡片固定 `16:9` 封面区，避免加载后跳动；
- 无封面时使用项目类型图标、标题和中性底色，不使用随机 AI 图；
- 待处理事项采用紧凑行，而不是同尺寸卡片。

### 8.2 作品列表

- 默认采用封面网格，可切换紧凑列表；
- 网格卡片比例统一，标题最多两行；
- 卡片常驻显示类型、更新时间和关键进度；
- 悬停显示打开、更多等操作，不改变卡片尺寸；
- 删除、归档等低频危险操作进入更多菜单；
- 列表为空时提供“新建作品”和“从现有素材开始”两个真实可用动作。

### 8.3 短剧项目工作区

项目顶部只保留：返回作品、项目名、保存状态、项目级主操作。

项目内导航建议：

- 概览
- 剧情
- 分镜
- 设定
- 素材
- 任务
- 成片（P4 上线后出现）

视觉重点：

- 项目名和当前集属于持续上下文，切换标签时不能消失；
- 内容状态、执行状态、采用状态采用三套固定标签；
- 剧集和场次使用可折叠层级，不把每层都包成大卡片；
- 批量生产进度靠近分镜列表，不放到页面底部成为孤立模块。

### 8.4 分镜页

分镜是 Aster 最能体现专业度的页面，应优先重构。

推荐布局：

```text
┌───────────┬────────────────────────────────────────────┐
│ 集/场导航 │ 镜头卡 01  [预览 16:9]  描述 / 状态 / 操作 │
│           │ 镜头卡 02  [预览 16:9]  描述 / 状态 / 操作 │
│           │ 镜头卡 03  [预览 16:9]  描述 / 状态 / 操作 │
└───────────┴────────────────────────────────────────────┘
选中镜头后：右侧检查器显示提示词、参考、候选、生成参数和连续性提示
```

镜头卡必须显示：

- 镜号和场次；
- 当前采用画面，未采用时显示候选数量；
- 景别、运镜、时长等核心信息；
- 内容状态和生成状态；
- 生成、查看候选或处理失败的主要动作。

不在列表中平铺完整 Prompt、模型请求参数和日志。

### 8.5 候选与选片

- 候选采用 2-3 列媒体网格，而不是文字列表；
- 图片遵循原始比例但限定稳定容器，视频统一 `16:9`；
- 当前采用候选使用边框、勾选图标和“已采用”文本三重表达；
- 失败候选保留失败原因摘要和重试入口，不显示空黑框；
- 对比模式最多同时展示 2-4 个候选；
- 模型、提示词和来源信息放在媒体下方的折叠元数据区。

### 8.6 素材库

布局：页面标题栏 + 工具栏 + 左侧筛选 + 素材网格 + 按需出现的详情检查器。

左侧筛选分组：

- 素材类型：图片、视频、音频、文本；
- 业务分类：角色、场景、道具、镜头、其他；
- 来源：生成、上传、工作流、项目；
- 项目和收藏；
- 用户分类在真实数据模型支持后启用。

当前数据模型未确认支持 3D 模型、素材包导入、容量购买和回收站，因此这些不能仅为对齐参考截图而上线。

素材网格规则：

- 默认卡片最小宽度 220px，间距 12px；
- 图片可使用 `4:3` 统一裁切预览，详情中查看原图；
- 视频使用 `16:9`，悬停不自动播放声音；
- 标题、类型、来源和时间在两行信息区完成；
- 收藏、更多操作覆盖在缩略图右上角，始终保留点击热区；
- 详情检查器显示来源任务、项目、尺寸、模型和使用位置。

空状态优先显示真实动作：上传素材、新建文本素材、返回作品开始生成。装饰图可以存在，但不能比动作更醒目。

### 8.7 技能库

技能页面采用目录式体验，不做应用商店式营销卡片墙。

- 顶部搜索和领域筛选；
- 技能卡显示名称、用途、输入、输出和启用状态；
- 详情使用右侧面板，包含适用场景、所需工具和权限；
- “启用”是二元设置，使用开关；
- “立即使用”只有在存在明确入口和输入协议时出现；
- 系统 Skill、MCP 工具和面向创作者的技能不可混为一个列表。

### 8.8 任务中心

任务中心采用“列表 + 详情”结构：

- 左侧/主区是紧凑任务行；
- 右侧详情显示输入快照、输出、失败原因、事件和重试；
- 状态筛选使用分段控制或标签页；
- 任务行优先显示作品、生成类型、状态、时间和费用/模型摘要；
- 失败原因先给用户可理解的摘要，技术堆栈只在调试详情中出现；
- 运行中使用进度条或阶段文本，不用无限闪烁的装饰动画。

## 9. 组件规范

### 9.1 按钮

| 类型 | 用途 | 规则 |
| --- | --- | --- |
| Primary | 当前区域唯一主动作 | 实底品牌色，每个区域最多一个 |
| Secondary | 次要明确命令 | 白色/表面底 + 边框 |
| Ghost | 工具栏和行内操作 | 无边框，悬停出现填充 |
| Danger | 确认后的危险动作 | 默认次级，确认层中使用危险色 |
| Icon | 熟悉的工具命令 | 32-36px 方形，必须有 Tooltip |

按钮高度只保留 32、36、40px 三档。加载时保持原宽度，避免文字变化导致布局跳动。

### 9.2 输入与选择

- 默认高度 36px；
- 标签放在控件上方，必要说明放下方；
- Placeholder 只给例子，不替代字段标签；
- 错误信息紧邻字段，不能只 Toast；
- 数值使用输入框、步进器或滑杆，不使用自由文本；
- 模式切换使用分段控制，二元配置使用开关或复选框。

### 9.3 状态

状态体系分为三类：

| 类别 | 示例 | 视觉形态 |
| --- | --- | --- |
| 内容状态 | 草稿、已确认 | 中性/成功标签 |
| 执行状态 | 排队、运行、失败 | 圆点 + 文本或进度 |
| 采用状态 | 待选、已采用 | 轮廓标签 + 选择标记 |

同一个标签不能同时表达“生成成功”和“镜头完成”。标签统一 12px 字号、20-22px 高度，避免不同页面自行定义颜色。

### 9.4 卡片

卡片仅用于独立、可重复选择的对象，例如作品、素材和候选。页面分区、筛选区和表单区不默认做成卡片。

- 圆角 8px；
- 普通状态 1px 边框；
- 悬停只改变边框或背景，不整体放大；
- 卡片内部不再嵌套装饰卡片；
- 卡片尺寸由网格和媒体比例约束，加载状态不得改变高度。

### 9.5 抽屉和弹窗

- 检查、编辑和上下文操作优先用右侧检查器/抽屉；
- 需要阻断并确认的短流程使用弹窗；
- 大型编辑器不塞进窄弹窗；
- 抽屉宽度 360、420、560px 三档；
- 弹窗标题栏和底部操作固定，中间内容独立滚动；
- 关闭按钮使用 `X` 图标并提供可访问名称。

### 9.6 表格和列表

- 表头 13px/500，行高 40-48px；
- 长文本默认单行省略，悬停或详情查看完整内容；
- 操作列固定在右侧；
- 批量选择后保持列宽不变；
- 仅有 2-3 个字段的对象使用列表，不强行使用表格。

## 10. 空、加载、错误和成功状态

### 10.1 空状态

空状态应回答三个问题：

1. 这里将出现什么；
2. 为什么现在为空；
3. 用户下一步能做什么。

每个空状态最多一个主动作和两个次动作。禁止只显示“暂无数据”。

### 10.2 加载

- 首次加载使用与最终布局同尺寸的骨架；
- 局部刷新保留已有内容并显示轻量进度；
- 媒体加载使用固定比例占位；
- 超过 8 秒的生成任务进入任务状态，不用页面级 Spinner 阻塞。

### 10.3 错误

- 可恢复错误提供“重试”；
- 权限或配置错误提供具体去向；
- 生成失败保留输入和已生成候选；
- Toast 只用于操作反馈，不承载需要用户决策的信息；
- 危险操作说明影响范围，并使用可恢复策略或二次确认。

### 10.4 成功

保存成功不频繁弹 Toast；使用状态文字或短暂图标即可。生成完成后应把注意力引向结果或待选片数量，而不是播放庆祝动画。

## 11. 图标、图片和动效

### 11.1 图标

- 统一使用 `lucide-vue-next`；
- 常规尺寸 16/18/20px；
- 常规描边 1.8px；
- 不混用 emoji、手绘 SVG 和不同风格图标；
- 不使用图标表达陌生业务概念，陌生概念需要图标 + 文本。

### 11.2 图片与视频

- 作品封面和视频候选：`16:9`；
- 图片素材网格预览：`4:3`，详情保留原比例；
- 角色设定：可选 `3:4`；
- 音频：稳定波形或统一音频占位，不使用随机封面；
- 预览失败显示明确占位和重试，不显示破损图片图标；
- 所有媒体区域必须提前定义 `aspect-ratio`，防止布局抖动。

### 11.3 动效

动效只表达状态变化和空间关系：

- 悬停/聚焦：120-160ms；
- 抽屉/弹窗：180-220ms；
- 页面切换不做大幅位移；
- 不使用粒子爆炸、漂浮光球和循环呼吸光作为常规反馈；
- 遵守 `prefers-reduced-motion`，减少模式下关闭非必要动画。

当前收藏粒子动画应改为图标填充和短暂缩放，避免在生产工具中制造过强干扰。

## 12. 可访问性和可用性

- 正文与背景对比度至少 4.5:1，大字号至少 3:1；
- 所有功能可通过键盘到达；
- 焦点顺序与视觉顺序一致；
- 图标按钮具备 Tooltip、`aria-label` 和 32px 以上点击区；
- 状态不只依赖红绿颜色；
- 弹窗打开后焦点进入弹窗，关闭后回到触发元素；
- 长中文、长英文单词、模型名和 ID 都不能撑破容器；
- 200% 浏览器缩放下主要流程仍可完成。

## 13. 前端实施映射

### 13.1 令牌与基础样式

| 文件 | 建议改造 |
| --- | --- |
| `frontend/src/design/tokens.js` | 收敛颜色、圆角、阴影、字号和间距令牌 |
| `frontend/src/design/base.css` | 增加字体、焦点、减弱动效和滚动条基础规则 |
| `frontend/src/style.css` | 移除与工作台冲突的 `--sk-*` 页面视觉和径向渐变 |
| `frontend/src/views/creative/creative.css` | 从页面样式改为真正的创作组件基础样式 |

实施时不能一次性删除 `--sk-*`。应先用 `rg` 确认所有消费者，逐页面迁移后再清理。

### 13.2 组件层

建议沉淀：

- `PageHeader`
- `Toolbar`
- `SegmentedControl`
- `StatusBadge`
- `MediaTile`
- `EmptyState`
- `InspectorPanel`
- `FilterSidebar`
- `TaskRow`
- `ShotCard`

只有在两个以上页面存在真实重复时才抽象，避免先建设庞大组件库再做页面。

### 13.3 页面层

| 优先级 | 页面 | 目标 |
| --- | --- | --- |
| UI0 | 全局导航、令牌、按钮、输入、状态 | 消除全局不一致 |
| UI1 | 创作首页、作品列表 | 建立第一印象和开始路径 |
| UI2 | 短剧分镜、镜头检查器、候选选片 | 展示核心专业能力 |
| UI3 | 素材库、任务中心 | 建立生产资产与执行闭环 |
| UI4 | 技能库、深色主题精修 | 完成能力入口和长期使用体验 |

UI2 完成前，不投入大规模自由画布视觉开发。

## 14. 分阶段交付

### UI0：视觉基础收敛

交付：

- 统一 `--wb-*` 令牌；
- 统一字号、圆角、按钮、输入和状态；
- 移除页面背景渐变和冲突样式；
- 建立浅色/深色组件对照页；
- 替换硬编码状态颜色。

验收：任意页面的按钮、输入、标签和弹窗看起来属于同一产品。

### UI1：入口体验

交付：

- 创作首页主输入与最近作品重构；
- 作品网格和列表视图；
- 导航选中、收起和窄屏行为统一；
- 真实空状态、加载和错误状态。

验收：新用户能在 10 秒内识别主入口，老用户能在 3 次点击内继续最近作品。

### UI2：短剧专业工作区

交付：

- 项目内导航；
- 剧情层级视图；
- 媒体优先的镜头卡；
- 右侧镜头检查器；
- 候选网格、对比和选片；
- 批次进度就地呈现。

验收：用户无需阅读数据库式字段表，就能判断每个镜头处于编辑、生成、待选还是已采用状态。

### UI3：资产与任务闭环

交付：

- 素材筛选侧栏、媒体网格、预览和来源检查器；
- 任务列表 + 详情；
- 项目、素材、任务之间保留上下文跳转；
- 批量选择和批量操作。

验收：用户可以从采用素材追溯到项目、镜头、提示词和任务，并能从失败任务回到可恢复位置。

## 15. 视觉验收清单

每个页面至少在以下视口截图验证：

- 1440 × 900；
- 1280 × 800；
- 1024 × 768；
- 390 × 844（仅验证声明支持的移动能力）。

必须覆盖：

- 浅色与深色；
- 空数据、少量数据和大量数据；
- 加载、错误、禁用、运行中、待确认和成功；
- 最长中文标题、长英文模型名和长 ID；
- 导航展开/收起；
- 检查器打开/关闭；
- 浏览器 100% 和 200% 缩放；
- 键盘焦点与 `prefers-reduced-motion`。

验收标准：

1. 没有文字、按钮、状态和媒体互相遮挡；
2. 动态内容不导致主布局明显跳动；
3. 页面只有一个明确主操作；
4. 媒体结果比参数和日志更醒目；
5. 状态不依赖颜色才能理解；
6. 普通页面分区没有不必要的卡片嵌套；
7. 任何参考产品的品牌资产和独特视觉表达都未被复制；
8. 所有展示功能均有真实业务能力或明确的禁用说明支持。

## 16. 第一批执行建议

第一批只做以下内容：

1. 收敛设计令牌，去除背景渐变、大圆角和过多字号；
2. 统一全局导航、页面标题栏、按钮、输入和状态；
3. 重构创作首页的主输入、最近作品和待处理列表；
4. 将短剧分镜从字段表格改为媒体优先的镜头列表；
5. 将 `ShotDrawer` 重构为稳定的镜头检查器和候选选择区；
6. 使用真实项目、真实失败任务和真实候选完成浏览器截图验收。

这批完成后，Aster 的专业感应来自清晰的信息结构、真实媒体结果和可靠生产状态，而不是装饰效果。素材库、技能库和自由画布再沿同一套视觉规则逐步扩展。
