# Aster 整体创作体验与视觉重设计

2026-11-02 · 设计提案 · 尚未替换线上界面

## 1. 设计目标与推荐方向

将 Aster 建设为以画面、故事和作品为中心的创作空间。用户始终知道：现在创作什么、哪些素材参与生成、结果在哪里、接下来能怎么改。项目管理、任务日志和模型配置保留，但逐步退到符合语境的位置。

推荐视觉方向「安静的编辑部 + 沉浸式创作台」：浅暖灰浏览界面、石墨色文字、克制的鸢尾紫强调色、大面积真实作品、深色媒体预览舞台。品牌辨识来自排版、留白、媒体比例与细腻动作，避免把所有页面做成渐变卡片和控制面板。

本轮范围是整体规划、交互和动效规范，以及概念交互预览。不会以一份概念稿宣称业务重构已经完成。Skill 模块按[已有规划](2026-11-02-video-skill-module.md)接入；本方案更新其视觉与导航归属，执行协议仍沿用。

## 2. 观察依据与现状诊断

本轮实际查看本地首页、作品列表、素材库，并核对 Vue 页面代码；登录查看幻映首页、素材库空态，前轮已查看技能页。未发起生成、上传或修改用户数据。截图只能支持布局判断，不能推断参考站动画时长和实现技术。

| 观察 | 用户感受/问题 | 重设计决定 |
|---|---|---|
| 当前首页输入后进入作品工作区；提示语解释数据在服务端 | 点“开始创作”与实际生成之间有落差，技术说明抢占首屏 | 首页允许准备完整创作输入；未提交时叫“进入创作台”，真正提交才叫“生成” |
| “作品”列表链接实际指向项目，包含无产物项目 | 不清楚是在找最终图片/视频，还是找工作目录 | 一级使用“我的创作”，内部明确“项目”和“作品”两个视图 |
| 项目名可由长提示词形成，卡片再重复长描述 | 字太多，作品失去标题与视觉身份 | 建议短标题、用户可改；提示词留在详情，列表只给一行概要 |
| 全局导航后又有素材筛选侧栏；项目还有多级标签 | 框架占据画面，多次切换才能继续创作 | 一级导航收敛；素材过滤改为顶部常用项 + 按需筛选抽屉 |
| 素材卡每项常驻收藏、下载、继续创作、删除 | 浏览时像 CRUD 记录，危险动作过于显眼 | 点击看大图；“用作参考”作为语境动作；其余进菜单/多选工具栏 |
| 素材以固定横向缩略图显示，人物图可被明显裁切 | 难判断完整构图与人物是否截断 | 原比例浏览模式，另提供整齐网格；完整预览始终 contain |
| 生成结果、上传文件同库，普遍标题“生成图片” | 来源和创作意图难检索，版本重复堆积 | 保留统一资产底层，新增名称、版本组和作品视图投影 |
| `ProjectStudioTab` 为结果区 + 固定宽参数区；`ProjectShell` 有多个制作标签 | 有创作基础，但所有项目暴露同等复杂度 | 快速创作与叙事制作两种工作区结构；深度工具渐进展开 |
| 全局任务页源码说明仍写“当前开放图片生成” | 文案与视频能力不一致 | 本轮记录为待修文案；重设计统一能力驱动文案 |
| 当前已有主题 token、Lucide、Vue Flow、Ant Design Vue | 全部推倒会损失可用底座 | 重构体验层与组件皮肤；复用领域服务与成熟无障碍行为 |

参考站实见：主输入支持视频/图片/文本/Agent 模式，参考内容、模型、生成参数集中在输入框周边；有最近画布、灵感大厅；素材页提供搜索、批量选择、分类及有行动入口的视觉空态。当前参考账号素材为空，因此不把其真实有内容素材预览、版本管理或上传体验写成已验证能力。

## 3. 信息架构：创作对象必须说清楚

### 3.1 一级导航

推荐固定 4 项：**创作 / 我的创作 / 素材库 / 技能**。底部工具菜单收纳工作流、知识库、智能体、服务概览与设置。全局顶部放“生成活动”入口，执行中显示数量，异常显示可操作提示；保留现有任务路由作为“全部生成记录”深层入口，历史链接不失效。

不要首期建立空的“社区”“插件市场”“自由画布”入口。参考站有这些页面，不代表本项目需要同时建设。工作流可视化继续使用已有 Vue Flow；创作画布若要做，需独立定义资产节点、撤销历史和保存语义。

### 3.2 项目、作品、素材、生成记录

| 名称 | 定义 | 浏览原则 |
|---|---|---|
| 项目 | 一次持续创作的容器，承载故事、草稿、分镜、资产关联 | 封面 + 短标题 + 继续创作；允许尚无结果 |
| 作品 | 值得回看或交付的产出视图，包含成图、片段、成片、章节 | 按产出浏览，不拿项目占位卡冒充成片 |
| 素材 | 所有可复用输入与产出资产 | 原始上传/生成结果为来源属性，不是相互隔离的仓库 |
| 版本组 | 同一创作意图下的多个成功候选 | 默认一张主卡展开版本，用户选择采用版本 |
| 生成记录 | 一次请求及其执行尝试 | 用于状态、失败与恢复，不等同于作品 |

“作品”先做基于现有成功资产的聚合视图，用户可标“精选/已采用”；不强制新增一套媒体存储。底层若缺版本组、短标题、选定封面、项目引用关系则明确补字段/接口。旧数据无法可靠推断版本关系时保持单独展示，不按时间相近自动归组。

## 4. 整体设计系统

### 4.1 视觉 token 提案

| 层级 | 浅色建议 | 深色建议 | 用途 |
|---|---|---|---|
| 页面底 | `#F6F5F2` | `#151617` | 安静中性色，不使用大面积蓝底 |
| 内容面 | `#FFFFFF` | `#202123` | 输入、菜单、必要卡片 |
| 次级面 | `#EEEDE9` | `#292B2E` | 分段控件、选区底 |
| 主文字 | `#202124` | `#F0F0EE` | 正文、标题 |
| 次文字 | `#62646A` | `#AAAEB5` | 描述和辅助信息 |
| 品牌强调 | `#6654C7` | `#B8ACFF` | 引用、焦点、选中标识 |
| 分隔线 | `#E4E3DF` | `#35373B` | 仅分隔必要区域 |
| 主按钮 | `#25252A` + 白字 | `#ECECE7` + 深字 | 一个区域一个主要动作 |

这些值是候选 token，实施时以实际字号与背景完成 WCAG 对比度验证（正文至少 4.5:1、控件边界和大字至少 3:1），不是本轮已经完成的检测结论。视频/图片预览舞台单独使用中性深色，不通过整体滤镜改变作品颜色。用户可选择浅色/深色/跟随系统。

字体使用现有系统中文栈，标题 28–32px/600，区块标题 18px/600，正文 14–16px/400，元信息 12–13px/400；避免全站 12px。正文行高 1.5–1.65；标题紧凑但不压缩汉字。展示型英文点缀不得替代中文关键标签。

间距用 4/8/12/16/24/32/48。控件圆角 8–10px、媒体卡 14px、输入台 20px、弹层 16px；只给浮层和输入台明显阴影。多数内容用留白分组，减少“卡片包卡片”。图标统一 Lucide 18–20px，密度大时仍保证命中区域；不能只靠 hover 才发现关键操作。

### 4.2 响应布局

- ≥1440px：侧栏 208px；浏览区最大 1480px；创作区可用满宽；媒体预览优先获取剩余空间。
- 1024–1439px：侧栏可缩为 64px；创作参数区 300–340px；同时只保留一个右侧面板。
- 768–1023px：默认收起导航；素材选择/参数变覆盖式面板，预览保持完整。
- <768px：底部 4 项导航；单列创作、可切换结果/输入；素材选择全屏；主操作避开安全区和软键盘。拖拽均有点击替代。
- 媒体的 contain/cover 由场景定义，缩略图高度提前占位，防止图片加载让按钮跳动。

## 5. 页面重设计

### 5.1 创作首页：一个输入台，四种起点

首屏：一句“把想法变成下一幅画面。”，下方输入台包含创作类型、提示词、参考素材、可选技能、模型与少量常用规格。优先入口为“写一句想法 / 从素材开始 / 使用技能 / 继续最近创作”。首期不露无法使用的漫画或模型选项，未支持功能放产品说明。

最近创作最多 4–6 个，有真实封面且文案简洁；无产物显示带作品名的排版封面，不用无意义灰框。灵感作为次级精选区，用自有或明确授权样例，点击先看输入和可复用部分；不制造虚假社区热度。任务失败用顶部活动入口提醒，不在首页铺满状态统计。

首页不强制先填项目名。可先保留本地草稿；提交或主动保存时幂等创建项目，自动标题可改。必须先确认现有后端是否允许该路径，不把“界面隐藏新建表单”当作已实现自动保存。

### 5.2 我的创作：找回作品也找回上下文

顶部“项目 / 作品”切换，搜索、类型、排序；卡片显示完整短标题、媒体类型、最近活动及版本数。项目点击进入上次工作位置；作品点击进入大预览，能直接继续创作、看版本或回原项目。

作品视图支持“全部成功产出 / 已采用 / 收藏”，默认按创作组聚合，避免 20 张近似图塞满首页。卡片的更多菜单收纳重命名、选封面、归档；删除不常驻。空态有一个明确主动作，而非大段系统说明。

### 5.3 素材库：从档案列表变成创作资源台

顶部全局搜索 + 图片/视频/文本类型快捷筛选；项目、来源、角色/场景/道具、收藏放可收起筛选。首屏给予媒体约 70% 以上的内容区面积。提供“原比例”“整齐网格”切换与密度调节；原比例布局须保证 DOM 顺序与键盘顺序一致，避免 CSS 多列造成视觉/焦点错位。

卡片只保留预览、短标题、必要类型/时长；hover 显示收藏与更多，键盘 focus 和触摸均可用。单击预览，勾选框单独控制多选，不用双击作为唯一入口。多选出现底部工具条：引用、归入项目、下载、移至回收站。跨页选择必须显示范围，不能让用户误删未看到的内容。

全局素材库直接允许上传；拖入时出现明确投放区、类型/大小限制与逐文件进度。失败项独立重试，成功项保留；关闭上传面板不应伪装上传已取消。上传完成不自动调用模型。

### 5.4 大预览：让“看”和“用”连在一起

桌面预览使用深色媒体舞台 + 300px 信息栏；左/右切换相邻结果，关闭回原滚动位置。右侧默认“创作信息”，展示提示词、引用素材、版本和来源；尺寸/格式/存储细节折叠。主动作随素材类型变化：“用作首帧”“作为图片参考”“沿用提示词”。不支持的角色明确禁用，不将视频误加到图片槽位。

视频点击才播放，默认不自动发声；列表预览在可见且 hover 稳定后才播放，移出停止，最多一个实例。按需获取签名地址，过期自动刷新但保留播放位置。图像支持缩放/原尺寸；全图检查优先于漂亮裁切。

版本比较：图像可左右并排/滑杆；视频先做同步播放/暂停和分屏，不强行承诺不同长度逐帧对应。主版本选择记录用户动作，不覆盖原资产；比较关闭后保留选片状态。

### 5.5 快速创作台：结果是主角

桌面采用“中央结果舞台 + 底部输入台 + 按需素材/参数侧栏”。中央按创作轮次展示输入摘要、生成候选和状态。底部输入台保持稳定，支持引用缩略图、可选 Skill、模型/比例/时长；高级参数折叠。避免整屏永久 3 栏挤压视频。

从任何素材的“用作参考”进入时，打开素材托盘并显示引用角色；不覆盖已有草稿。来源可追溯到素材 ID；跨项目复用应创建关联或按当前权限复制，不能只传临时 URL。多图输入上限与用途由模型能力驱动；“供方案理解”与“发给视频模型”必须区分。

每轮生成是一组候选卡。用户可以采用、比较、调整后生成新版本；任务失败卡原地显示原因与恢复动作。结果就绪在原占位位置出现，用户正在浏览历史时只提示“有新结果”，不抢滚动、不强迫切页。

### 5.6 视频叙事工作区

顶部项目名与保存状态；主模式“故事 / 分镜 / 成片”，角色与场景为上下文面板，工作流与日志归进阶工具。分镜以镜头卡和连续预览为主，右侧选中镜头属性；批量操作在多选后出现。保留现有细分路由，先做导航映射。

底部镜头条用于排序、选片、状态查看。没有后期引擎时叫“镜头顺序”，不可画一个假时间线暗示可剪辑。成片页仅在真实合成可用后提供导出；否则显示选片与合成计划。

### 5.7 小说、知识库、工作流及设置

- 小说：纸张式正文阅读/编辑，章节目录可折叠，AI 建议用 diff 接受/拒绝；创作焦点不被媒体参数占据。
- 工作流：保留 Vue Flow 节点能力；统一工具栏、节点视觉、运行状态；模板选择先呈现用途和输入输出，技术字段在检查器中。
- 知识库：创作者看资料集合、引用情况和上传进度；索引状态/调试进入管理详情。
- 智能体：对话页延续输入台与引用模式；工具事件默认折叠，关键确认可见。
- 设置：仍用清晰表单/表格，按模型连接、存储、偏好分组；创作页配置后能返回原草稿。服务概览等管理功能保留专业密度，不让它们决定全产品的视觉语言。
- 登录/首次使用：统一品牌与字体；先创建第一份草稿，缺模型时给“连接模型”明确入口，不让空白配置页成为首次欢迎页。

## 6. 关键交互契约

| 流程 | 交互要求 | 实现依赖/边界 |
|---|---|---|
| 从素材继续创作 | 选择素材→选用途→带入当前输入台→编辑→确认生成 | 持久 asset ID 与草稿状态；能力校验 |
| Skill 应用 | 保留原文→展示建议差异→用户采用→生成 | 版本化方案，不自动覆盖提示词 |
| 多项上传 | 每项进度/取消/失败重试；离开前提示未完成项 | 后端现有上传能力需核对；断点续传若无不可宣称支持 |
| 失败重试 | 卡片不消失，原任务 ID 不变，增加尝试记录 | 复用现有 retry 与 fencing，禁止 create 替代 |
| 提交不明 | 明确“正在核对供应商结果” | 不自动重复提交；沿用重复计费确认 |
| 已生成但入库失败 | “恢复结果”，保留成功生成信息 | 只重新下载/入库 |
| 成功后再创作 | 新版本归同组，原结果保留 | 与失败重试分开；版本分组字段为新增提案 |
| 草稿保存 | 输入先本地即时保存，服务端防抖；显示保存/失败/冲突 | 刷新恢复、版本冲突、权限隔离；不无限静默失败 |
| 删除 | 先回收站、可撤销；有关联先解释影响 | 后端撤销期限/引用策略需明确；不做只有 UI 的假撤销 |
| 快捷键 | Cmd/Ctrl+K 搜索；Esc 关闭；方向键浏览预览；Cmd/Ctrl+Enter 提交 | 提交必须无 IME 合成态且焦点正确；仍保留可点击按钮 |

输入区采用 Enter 换行，Cmd/Ctrl+Enter 提交，避免中文输入误触收费操作。正在运行的记录只展示服务端事实；没进度数据就用阶段和已用时，不假造百分比、成功率或预计费用。

## 7. 动效系统：用于表达关系、状态与手感

### 7.1 全局动作语言

动作分 4 层：触感反馈（按钮/选中）、空间关系（展开/收起）、内容更新（结果/排序）、少量品牌时刻（首次欢迎/首次成片）。高频操作克制，低频重要瞬间才有更明显动效。生成等待期间不持续抖动、旋转大图或循环播放装饰。

统一时间 token：`instant=90ms`、`fast=140ms`、`normal=220ms`、`spatial=320ms`、`showcase=420ms`。默认缓动 `cubic-bezier(.22,1,.36,1)`，退出 `cubic-bezier(.4,0,1,1)`。弹簧初始候选 stiffness 380/damping 34/mass 1，仅用于小范围有回弹价值的交互，按实际组件调校，不把参数作为品质保证。

### 7.2 动效清单

| 场景 | 动作规格 | 中断/降级 |
|---|---|---|
| 按钮 | 按下 scale .98，90ms；hover 颜色/阴影 140ms | 无布局位移；disabled 不响应 |
| 导航/分段切换 | 选中底片或下划线平移 180–220ms | 快速切换从当前状态接续，不排队 |
| 侧栏 | 内容轻移 12–20px + opacity，220ms | 宽度切换避免每帧重排整页；窄屏覆盖 |
| 素材选择 | 勾选即时，缩略图进入引用托盘 220–280ms | 大距离飞行动画仅桌面；减弱动效时直接出现 |
| 素材卡→大预览 | 共享元素位置/比例变换 280–320ms；背景淡入 | 只变换预览层，不拉伸真实图；不支持时普通淡入 |
| 筛选/排序 | 布局位置过渡 180–240ms，稳定 key | 超过可见范围的卡片不参与；虚拟列表无大批测量 |
| 批量工具条 | 从底部上移 12px，180ms | 不盖住最后一排/键盘焦点 |
| 方案展开 | 内容区自然高度变化 220ms | 校验错误即时可见，不等动画播完 |
| 结果就绪 | 在原占位交叉淡入 180ms，强调边框一次 | 不自动滚动；多结果错峰最多 4 张，每张 30ms |
| 版本切换 | 已解码媒体间淡入 160ms | 保留旧画面至新画面 ready，禁止白闪 |
| 收藏/采用 | 图标 scale .9→1.08→1，200ms | 更新失败回滚并说明；不使用彩纸爆炸 |
| Toast | 上移 6px + opacity，160ms | 错误可持久，不能瞬间消失；aria-live 不逐帧播报 |
| 首次成片 | 轻量一次性亮边/成功标记，≤420ms | 只有真实成功事件触发；可关闭 |

### 7.3 库选型：结合当前 Vue 3.5 技术栈

本轮查阅以下官方文档，未安装包、未验证生产包体和运行性能。

| 方案 | 核实能力 | 推荐 |
|---|---|---|
| Vue Transition / CSS / Web Animations | 当前技术栈可使用原生过渡 | 按钮、透明度、简单面板基础层，优先不引依赖 |
| [Motion for Vue](https://motion.dev/docs/vue) | 官方文档使用 `motion-v`，支持 layout/layoutId、AnimatePresence、手势、useReducedMotion | 推荐唯一主要编排库，覆盖共享布局与退出动效；Motion+ 示例/组件属于另一产品层，不能默认可免费复制 |
| [GSAP](https://gsap.com/docs/v3/) | Timeline、Flip、ScrollTrigger、context/revert 与 matchMedia | 复杂品牌片段或特殊时间线才评估；首期不与 Motion 同时控制同一元素 |
| [AutoAnimate](https://auto-animate.formkit.com/) | Vue directive/composable，子项增删移动自动过渡，尊重 reduced-motion；站点注明 MIT | 轻量替代方案，适合简单列表；若已有 Motion 不重复引入到相同区域 |

其他候选：Rive/Lottie 可用于少量设计师制作的品牌插画，但本轮未核实版本、许可和性能，不纳入首期安装清单。Aceternity/Magic UI 等可作为审美素材来源，不将面向 React 的组件直接搬进 Vue；具体组件授权另核实。

建议结论：**CSS/Vue 负责基础，Motion for Vue 负责复杂交互；GSAP 保留候选，AutoAnimate 为轻量替代，不堆叠四个引擎。** 落地前固定版本、检查许可证、测量路由增量包体及 Electron Chromium 兼容性，不凭官网宣传承诺 120fps。

### 7.4 性能与可访问性

只优先动画 transform/opacity；避免对大面积 blur、box-shadow、width/height 连续重绘；局部高度变化要测量影响。动画不承担业务回调真相，关闭动画也能完成全部操作。每个组件卸载时清理观察器、计时器、播放与动画实例。

尊重 `prefers-reduced-motion` 并提供应用内“减少动态效果”：关闭空间飞行、回弹、自动视频预览，保留即时状态/必要淡入。焦点环清晰；弹层 focus trap、关闭后恢复焦点；触屏目标 44px；所有 hover 操作有 focus/触摸替代。上传/生成状态使用节制的 aria-live。

验收目标（待实测）：常规交互反馈 ≤100ms；目标设备动画接近 60fps；动画引入不产生明显长任务；作品列表滚动无重复解码卡顿；预览恢复滚动位置。测试需覆盖 1000 条资产分页/虚拟化、长提示词、50 个生成记录、慢网和签名过期。不可把目标写成已达成指标。

## 10. 质量验收与禁止退化

- 1440/1280/1024/768/390px 走查；100%/125%/200% 缩放；长中文、英文、无缩略图、不同宽高比不挤坏按钮。
- 用同一组 12–20 张真实授权素材验收不同页面，不能靠精挑的封面掩盖实际数据布局问题。
- 从素材库选图到输入台已带引用不超过 3 个明确操作；大预览到继续创作不超过 2 个明确操作。当前未量测全路径，实施前录制基线再对比。
- 卡片主图占据主视觉，删除和下载不再抢主层级；用户无需读技术状态才能知道下一步。
- 预览关闭返回原位置、草稿刷新恢复、版本采用可追溯、后台任务跨页可见。
- 未配置模型、网络断开、余额不足、提交不明、上传失败、入库失败各有准确动作；生成中不展示假百分比。
- 动画中反复点击/关闭/切换不会留下遮罩、丢焦点、重复请求；减少动态效果模式等价可用。
- 不为视觉重构替换框架，不一次性安装整套动效库，不照搬参考站品牌/付费模板/无授权素材。

## 11. 本轮交互预览说明

随文提供“创作台 / 素材库 / 我的创作”概念预览，可体验素材引用、生成轮次、失败原位重试、版本切换与动效开关；预览内所有媒体为原创 CSS 示意画面，生成结果与状态是明确的演示数据，不连接供应商，不代表最终媒体质量。

预览服务于布局和手感讨论；最终实现必须用真实授权图片/视频完成高保真验收。推荐先定这个连续创作方向，再补齐 D0 的精细媒体视觉和完整错误状态。
