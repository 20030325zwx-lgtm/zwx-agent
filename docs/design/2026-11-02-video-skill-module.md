# AI 创作：视频 Skill 模块设计与实施规划

日期：2026-11-02。状态：设计提案，尚未实现。面向产品、设计、前后端开发与验收。

## 1. 结论与范围

建议建设「创作技能库 + 创作页技能选择器 + 可恢复的执行记录」，复用现有视频项目、素材、分镜、Workflow 与 MediaJob，不另造视频执行引擎。

用户可以直接输入提示词、选择素材、选择一个技能，然后查看可编辑方案并生成视频；技能是可选增强，不能成为快速生成的必填项。复杂短片才进入剧本、分镜、素材确认、逐镜生成的分阶段流程。

**关于“全部搬过来”：可以规划全量目录与兼容导入，但目前不能承诺 73 个技能全部复制后即可运行。** 原因是内容授权尚未核实、依赖平台专用工具、部分技能与视频无关。应逐项完成「来源授权 → 文件导入 → 依赖解析 → 能力适配 → 实测验收」，无授权内容保留研究索引，采用自行编写的同类技能实现能力。

本次交付是设计文档及调研清单；未向参考站点安装、收藏或发布技能，未执行外部技能中的命令，未发起收费生成。

## 2. 事实基线：项目已有能力与缺口

| 项目 | 已核实状态 | 对设计的影响 |
|---|---|---|
| 视频项目 | 有剧情、分镜、设定、工作流、素材、任务、快速生成入口 | 技能进入已有页面，不建立平行素材库 |
| 快速生成 | 已有文生视频；首帧图生视频接受一个 IMAGE 素材 | MVP 只承诺当前适配器支持的输入；多图不等于首帧 |
| 图片引用 | 已实现 OSS 临时签名 URL；本地存储无法直接提供供应商可访问地址 | 提交前校验存储与引用能力；不把临时 URL 存成永久素材标识 |
| 视频实测 | 先前文生视频链路曾成功；本次首帧新链路未做真实供应商验证 | 图生视频发布前需要端到端契约实测，不能仅凭字段名宣称兼容 |
| 失败重试 | `MediaJobService.retry` 重排同一 job ID，保留事件；不确定提交需确认，入库失败走恢复 | 所有技能界面沿用同一语义；不能把重试实现成 create |
| Skill 加载 | `SkillRepository` 使用 `Files.list` 加载平铺 Markdown；自定义元数据包含 id/name/trigger/agents/tools | 外部嵌套 `SKILL.md` 包需导入归一化，不可直接拷目录 |
| Skill 工具 | `BuiltInSkillRegistry` 当前实际映射的工具别名为 `webSearch` | 写上视频工具名称并不会获得视频生成能力 |
| Skill 页面 | `SkillSettings.vue` 是内置技能按 Agent 启停配置 | 保留管理用途，新增面向创作者的技能库 |

## 4. 产品定义与信息架构

| 概念 | 职责 | 不承担的职责 |
|---|---|---|
| Prompt 模板 | 单次文本结构与变量 | 持久化编排、调用供应商 |
| Skill | 场景方法、输入输出约定、阶段规则、所需能力 | 自建队列、自行执行任意脚本 |
| Workflow | 节点依赖、阶段等待、批量编排 | 替代模型适配层 |
| MediaJob | 一次媒体生成的提交、轮询、入库、重试、事件 | 解释整份导演方法论 |
| Provider Adapter | 把统一能力转成某供应商真实协议 | 根据技能文字猜测支持参数 |

建议导航：AI 创作首页增加「技能库」；项目快速生成里增加「使用技能」；剧情/分镜页面只推荐当前阶段适用的技能。原设置页保留租户/Agent 可用范围管理。

拟议路由（不是已存在 API/路由）：

- `/creative/skills`：技能库，查询参数保存分类、阶段、关键词、排序。
- `/creative/skills/:skillId`：可分享的详情页；列表内可用抽屉打开同一内容。
- `/creative/skills/:skillId/edit`：有权限者编辑草稿与版本。
- 项目现有 `studio`：从技能库跳转时携带技能版本及草稿标识，不把提示词/素材私密内容放 URL。
- 项目现有 `tasks`：统一查看执行结果；Skill 执行详情关联既有任务列表。

## 5. 页面与视觉设计

### 5.1 技能库

```text
AI 创作 / 技能库                          [创建技能] [导入技能]
找到适合这次创作的方法
[技能广场] [我的技能] [我创建的] [收藏]
搜索名称、场景或作者……    行业▾  创作阶段▾  当前可用□  排序▾
┌ 一图短片           ┐ ┌ 导演分镜           ┐ ┌ 商品广告           ┐
│ 从首帧到动态镜头   │ │ 从剧本到镜头方案   │ │ 从卖点到视频方案   │
│ 输入：文本＋图片   │ │ 输入：文本/剧本    │ │ 输入：文本＋图片   │
│ 输出：视频         │ │ 输出：分镜表       │ │ 输出：方案＋视频   │
│ 可用/待验证/缺能力 │ │ 官方 · v1          │ │ 预计需确认 2 阶段  │
│ [详情] [使用]      │ │ [详情] [使用]      │ │ [详情] [使用]      │
└───────────────────┘ └───────────────────┘ └───────────────────┘
```

建议规格：复用现有主题 token、字体和组件。内容区最大宽度 1440px，桌面内边距 24px、卡片间距 16px、圆角 12px；宽屏 3 列，中屏 2 列，小于 768px 单列。所有宽度以可用内容区为准，不硬套参考站窄屏双列。标题 24px、卡片标题 16px、正文 14px；说明最多 3 行，详情展示全文。

卡片主动作「使用」，收藏为辅助动作。「加入我的技能」代表固定到个人快捷列表，不自动授予工具权限。禁用卡片仍可读详情，明确写「缺少视频模型」「暂不支持多图参考」并提供对应操作。暂未配置价格时显示「价格待供应商确认」，不伪造金额/等待分钟数。

### 5.2 技能详情

桌面建议 960px 宽抽屉或独立页，移动端全屏。头部：名称、作者、来源、版本、收藏与「使用技能」。主体分为「使用说明 / 输入与输出 / 示例 / 版本与来源 / 文件」；首屏先解释能做什么、需什么素材、产出什么。

- 输入说明：必填与可选、素材数量/类型、适用范围、当前模型兼容情况。
- 示例：自有或授权的示例输入、可复现参数、示例结果；未验证的内容标「示意」，不冒充实测。
- 版本：更新摘要、来源 commit、内容 hash、授权记录、兼容报告；不自动升级运行中任务。
- 文件：左侧目录、右侧只读 Markdown；普通用户无需阅读原文就能使用。
- 主按钮：兼容时「使用技能」，未配置时「配置模型」，部分支持时「仅生成方案」，已下架时不可新启用但历史记录仍可查。

### 5.3 快速生成工作台

```text
项目 / 快速生成                技能：[一图短片 v1 ×] [更换]
┌ 创作输入（约 36%） ───────┬ 方案与结果（约 64%） ─────────────┐
│ 提示词                    │ [方案] [生成进度] [历史版本]     │
│ 给这只香水做一段展示……    │ 原提示词 → 优化提示词（可编辑） │
│                           │ 镜头：缓慢推进；主体保持……      │
│ 素材 [首帧缩略图 ×] [+]    │ 参考素材：香水.jpg，角色：首帧  │
│ 模型 / 可选时长 / 比例     │ 提交前：模型、素材、数量、费用  │
│ [生成方案]                │ [确认并生成视频]               │
└───────────────────────────┴────────────────────────────────┘
```

大屏双栏；小屏依次为输入→方案→结果，底部固定主动作但不遮挡正文。未选技能时保留当前直接生成。选择技能不能清空已有提示词和素材；更换技能先预览字段映射，不兼容字段保留在草稿并提示。

素材必须有明确角色：首帧、尾帧、人物参考、场景参考、动作参考等；MVP 仅开放当前真实支持的首帧。后续即使允许多素材上传，也要区分「仅供方案理解」和「会发送给视频模型」，避免用户误以为上传就一定参与生成。

### 5.4 导入与编辑

导入流程：选择 Markdown/ZIP/GitHub → 解析包 → 选择入口 → 来源与授权 → 兼容报告 → 保存私有草稿 → 测试 → 发布可用版本。

- GitHub 填仓库、ref、子目录；多个入口展示列表供选择，可批量导入但逐项给出结果。
- ZIP 展示目录、入口、文件数/大小；允许配套 references/assets，脚本默认不可执行。
- 外部标准 `name/description` 自动映射；本项目 `id/trigger/agents` 等缺项由表单补齐，不静默假定。
- 兼容报告分为可用、仅方案、缺工具、依赖缺失、授权待核实、解析失败；「保存」和「启用」是两个动作。
- 编辑器左侧基础信息/参数，右侧说明正文；进阶页再展示协议与文件。发布生成不可变版本，编辑旧版本应创建新草稿。
- 同源同 commit 同 hash 重复导入返回已存在版本；同名不同来源不自动覆盖；导入失败可在原导入记录重试。

### 5.5 通用交互与无障碍

所有状态同时有文字与图标，不只靠颜色。卡片不嵌套可冲突的点击区域；键盘可访问收藏/使用/详情。弹层关闭后焦点回触发按钮，Esc 关闭非提交中弹层；有未保存编辑才提示保存草稿。加载使用骨架屏；分页、搜索失败保留当前条件；空结果提供清除筛选；错误消息贴近对应字段。搜索防抖并取消过期响应，避免慢请求覆盖新结果。

## 6. 核心用户旅程

### 6.1 提示词 + 素材直接生成

1. 用户打开快速生成，输入目标并选一张首帧；可选「一图短片」技能。
2. 系统读取素材元数据与权限；若技能需要视觉分析，先检查图像理解能力，不能只凭文件名推断画面。
3. 生成结构化方案，显示原文/建议文本、素材角色、支持的时长和输出数量。用户可直接改文本；不覆盖其已输入的品牌、人物与风格约束。
4. 校验模型、适配器、素材可读性和预算；用户确认后由统一服务创建 MediaJob。
5. 同页持续显示「排队 → 准备素材 → 提交供应商 → 生成 → 入库 → 完成」。UI 阶段映射现有事件，不要求新增同名数据库状态。
6. 成功结果归项目素材库；执行记录保留技能版本、方案版本、实际提示词和素材 ID。刷新/离开页面不影响后台执行。

### 6.2 多镜头短片

技能先给剧本/分镜草稿 → 用户确认 → 提取角色/场景资产 → 用户确认素材 → 生成逐镜头计划 → 校验总量与费用 → 批量生成 → 选择成功版本 → 后期合成。

已有资产优先复用；任何改动对后续镜头的影响都展示差异。修改镜头 3 不应重生成镜头 1、2。分镜与 Clip 可以一对多/多对一，数据中保留映射；时长来自模型能力，不能硬编码参考技能的 4–15 秒。

复杂技能的阶段由服务端确定性状态机控制，LLM 输出只能建议下一步，不能绕过确认或自行无限批量提交。

### 6.3 重试、恢复和“重新生成”的准确语义

| 情况 | 界面文案/动作 | 必须遵守的行为 |
|---|---|---|
| 方案生成失败，未创建媒体任务 | 重试方案 | 同一 Skill run，增加阶段尝试记录；不创建 MediaJob |
| 校验失败 | 修正配置/素材 | 展示具体原因；不可循环自动重试 |
| 调用供应商前失败/中断 | 重试当前任务 | 调用现有 retry；同一 media_job ID，不新增任务卡片 |
| 已提交但结果不明 | 正在核对结果；查看详情 | 优先查供应商；不自动重复提交；强制重提沿用现有重复计费确认 |
| 供应商明确失败 | 重试当前任务 | 同一 ID，保留各次 attempt、供应商请求及错误记录 |
| 下载/入库失败 | 恢复结果 | 仅重新获取或入库已生成结果，不再买一次视频生成 |
| 成功后希望另一版本 | 生成新版本 | 与“失败重试”区分；保留成功结果。新版本需独立生成记录并归同一创作条目，不能冒用当前只支持失败状态的 retry |
| 用户改了提示词/模型/素材 | 保存方案新版本后生成 | 不静默修改已提交请求；失败任务原样重试沿用原快照，修改生成的业务语义单独确认设计 |

自动重试提案：仅对可确认未提交的瞬时故障、查询与下载步骤做有限退避（建议最多 3 次、指数退避并加随机抖动）；错误类别、次数与下一次重试时间可见。参数错误、余额不足、权限错误不自动循环。超时且可能已被供应商受理时禁止自动重投。

幂等要求：确认按钮双击、网络重传、页面恢复均关联同一确认请求；批次重试只处理失败镜头，已有成功产物不能重复生成。旧 worker 回写必须受现有 lease/version fencing 保护。

## 8. 技术方案（以下字段、服务与接口均为提案）

### 8.1 技能包协议与兼容层

建议包结构：`SKILL.md`（入口）+ `manifest.json`（本产品结构化扩展）+ 可选 `references/`、`assets/`。外部包缺 manifest 时生成草稿，不修改原始包；保留原文件与规范化结果。

manifest 最小字段：`id/name/description/version/category/stages`、`inputSchema/outputSchema`、`requiredCapabilities`、`dependencies`、`entrypoint`、`sourceUrl/sourceRef/sourceCommit/contentHash`、`license/licenseEvidence`。`agents/trigger/tools` 由旧格式兼容映射，不把未知工具默认放行。

输入示例（概念协议）：`prompt`、`assetBindings[{assetId, role}]`、`durationSeconds`、`aspectRatio`、`constraints`。输出示例：`planRevision`、`summary`、`shots[{shotId,prompt,durationSeconds,assetBindings}]`、`warnings`。这些字段不是现有接口签名，落地时需与已有领域 DTO 对齐。

结构化输出必须经 schema、素材权限、能力和参数校验，Markdown 作为可读说明而非调度协议。超大参考文档按阶段加载，不把 73 个正文一次性塞进模型上下文。依赖解析需有版本锁、循环检测、深度与总量限制。

### 8.2 外部工具适配矩阵

| 外部依赖 | 本项目目标能力 | 当前处理原则 |
|---|---|---|
| `canvas_*` | 项目文档/分镜草稿读写与确认 | 尚需桥接；以版本化领域数据代替自由覆盖画布 |
| `request_user_input` | 前端阶段表单 | 由 schema 驱动，不靠模型在长文本里模拟按钮 |
| `resource_status` | 素材与任务状态查询 | 校验当前租户/用户/项目访问权 |
| `load_skill` | 固定版本依赖加载 | 限制可调用清单，不允许技能自行扩大权限 |
| `text2image/image2image` | 已有图像生成链路的受控入口 | 逐项对照现有能力与参数，不能仅改名 |
| `multi_modal2video` | 视频生成统一能力 | 当前仅文生/单首帧可作为基线；多图/音视频参考标未支持 |
| `video_editor` | 后期时间线/合成能力 | 独立阶段建设；没有适配器时只能输出剪辑方案 |
| `Bash(belt *)`/Remotion 命令 | 经批准的服务适配器/渲染作业 | 不将外部命令直接转成线上任意 Shell 权限 |

能力注册需区分「适配器实现」「账号已配置」「当前可用」「真实验证状态」。支持模型名称相同不代表中转协议相同，特别要核实首帧字段在网关中实际转发至供应商，而非仅被解析接受。

### 8.3 数据模型

建议增加以下逻辑实体，最终表名随现有迁移规范确定：

| 实体 | 关键内容 |
|---|---|
| skill_definition | 身份、名称、作者、分类、归属、可见范围、生命周期 |
| skill_version | 不可变正文/文件索引、schema、能力、依赖锁、来源 commit/hash、授权状态 |
| skill_installation | 租户/用户启用版本、收藏、配置；与管理员授权分离 |
| skill_import_job | 导入来源、解析结果、逐项错误、尝试记录；失败可原位恢复 |
| skill_run | 项目、技能版本、输入快照、当前阶段、确认的方案版本、运行状态 |
| skill_run_step | 阶段尝试、错误、产出引用、确认者/时间、恢复点 |
| skill_run_media_job | run/step/shot 与既有 media_job 的唯一关联、请求幂等键 |

每个 run 绑定不可变技能版本；媒体提交前冻结实际提示词与素材引用。任务仍以现有 MediaJob 为生成状态真相，SkillRun 只聚合，不另建竞争状态机。对象存储只存文件；查询与权限由数据库领域关系控制。快照不持久化密钥/临时签名 URL。

### 8.4 API 草案

相对现有 API 基址，拟议资源如下；实现前核对 Controller 路由，避免重复。

| 动作 | 拟议接口 | 行为 |
|---|---|---|
| 搜索/详情 | `GET /creative/skills`、`GET /creative/skills/{id}` | 分页、兼容状态、版本摘要 |
| 导入预检 | `POST /creative/skill-imports` | 异步解析，只产生预览/草稿 |
| 导入状态/确认 | `GET /creative/skill-imports/{id}`、`POST .../{id}/confirm` | 基于解析 hash 确认，不重取不受控新内容 |
| 保存/发布 | `POST /creative/skills/{id}/versions`、`POST .../versions/{version}/publish` | 权限与授权/能力校验 |
| 创建执行 | `POST /creative/projects/{projectId}/skill-runs` | 只生成方案或进入待确认，不能暗中付费生成 |
| 确认执行 | `POST /creative/skill-runs/{id}/confirm` | 校验 planRevision、幂等键、能力与素材后关联任务 |
| 状态/事件 | `GET /creative/skill-runs/{id}`、`GET .../{id}/events` | 组合已有任务事件，游标去重、断线恢复 |
| 阶段重试 | `POST /creative/skill-runs/{id}/steps/{stepId}/retry` | 媒体阶段转现有 job retry；入库阶段转恢复 |

确认内容变更返回冲突并展示新方案；不能用旧确认执行新提示词。创建 run/step 与任务关联需事务与唯一键约束；任务异步派发采用现有可靠机制或事务 outbox，避免提交成功但 UI 未收到响应就重复创建。

### 8.5 权限、导入与内容约束

因本模块接受外部包，必须处理真实导入风险：ZIP 路径穿越/符号链接、压缩炸弹、恶意 Markdown 链接/HTML、GitHub 私网地址跳转、依赖无限递归。建议默认限制 10MB 压缩包/50MB 解压/200 文件/5 层依赖，具体按实际素材包调整；图片示例大文件单独管理。

GitHub 首期只接受公开仓库，固定 commit；解析不执行脚本、不拉子模块、不安装依赖。Markdown 安全渲染；外部正文只作为技能内容，不得覆盖租户权限、工具许可、计费确认和系统约束。导入者不能靠 manifest 自授管理员/跨项目素材访问权限。

默认私有；公开发布需记录具体分发依据。远程更新先生成候选版本和差异，使用者选择升级；正在运行的任务继续旧版本。自动更新频率不是核心功能，MVP 采用手动检查即可。

## 9. 实施分期与验收

不提供未经团队容量评估的固定工期；按依赖和可验收增量交付。

| 阶段 | 交付范围 | 完成标准 |
|---|---|---|
| P0-A 基础与契约 | 技能版本/schema、能力注册、兼容报告、文生与首帧契约验证 | 未支持参数不能提交；真实首帧链路验证有记录；旧 worker 消费问题消除或隔离 |
| P0-B 产品闭环 | 技能库/详情、前 4 个技能、studio 选择器、方案确认、运行记录 | 文本+素材可完成方案→任务→资产；直接生成仍可用；刷新可恢复 |
| P0-C 外部导入 | Markdown/ZIP/GitHub 预检、草稿、依赖映射、来源记录 | 标准包/旧格式均有明确结果；同包幂等；缺工具不可静默启用 |
| P1 生产流程 | 剧情/分镜上下文、资产一致性、分阶段恢复、批次关联 | 只重试失败镜头；成功镜头不重复计费；版本可追溯 |
| P2 扩展内容与后期 | 经授权目录迁移、多参考能力、广告多版、字幕/剪辑适配 | 每个能力独立契约测试；后期可单独重试；外部包授权档案完整 |

关键验收用例：

1. 不选 Skill，原文生/首帧生成入口不回归；选 Skill 后原提示词和素材不丢失。
2. 能从首帧素材进入一图短片；显示真实可用参数，缺图像理解时不伪造视觉分析。
3. 用户确认后双击/断网重传只创建一次任务；前端关闭后重进可恢复状态。
4. 故障注入在调用供应商之前：显示准备阶段失败；重试 job ID 不变、事件保留、供应商只收到应有次数。
5. 提交已受理但响应丢失：进入核对，不自动重投；结果入库失败只恢复下载/入库。
6. 批次部分失败只恢复失败项；技能新版本发布不改变历史运行输入。
7. 外部包包含未知工具/缺失依赖/无许可/多个入口时给出准确状态，不显示“全部成功”。
8. 租户 A 无法通过 skill run、素材 ID、文件预览访问租户 B；正文不能越过工具权限。
9. 输入草稿、方案修改、失败详情在窄屏可操作；键盘能完成选择/确认/关闭弹层。
10. 首期每个技能至少保留正常输入、缺素材、模型不支持、用户改方案、失败恢复的验证样例。

产品指标：技能选择到方案确认率、确认到视频成功率、供应商前失败率、原位重试恢复率、重复提交率、单次成功成本。分别统计方案耗时和供应商耗时，不把所有失败归给模型。
