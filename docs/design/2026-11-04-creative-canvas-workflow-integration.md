# 创作台画布化与工作流融合整改方案

日期：2026-11-04

状态：核心整改已实施（2026-11-04）；项目画布、三种运行范围、候选选择恢复、任务取消和入口收拢已进入代码并完成本地迁移/重启。模板复制与短剧结构节点化仍按后续产品迭代处理。

范围：首期图片/视频创作；小说、短剧剧情、分镜、批次与通用工作流保留既有能力，按阶段接入。

## 1. 问题与目标

目前从首页进入创作项目后，快速生成、剧情、分镜、项目工作流、素材、任务分散在多个页签。用户先要判断去哪一页，才开始组织提示词、素材、模型和结果。全局另有独立「工作流」列表和编辑器，创作项目与工作流的关系不直观。项目内快速生成区同时显示结果、表单、技能方案、模型参数和任务操作，内容多且缺少流程空间。

本次目标是：用户在首页选择「生成图片/视频」并点击「进入创作台」后，直接看到该项目的可编辑无限画布。画布是创作的主场景，节点承载输入、操作、结果；左侧是所选节点的编辑器；后台仍以持久任务队列和工作流运行记录执行。复杂流程逐步搭建，单个生成节点无需学习工作流概念就能用。

### 当前实施状态（2026-11-04）

- 已实现：图片/视频项目默认进入项目画布；首页意图、模型、素材和技能标识带入画布；支持素材、文本、图片生成、图片编辑、视频生成节点；节点检查器包含模型、提示词优化、素材和生成参数；草稿与视口通过 creative_canvas 持久化并使用 revision 乐观锁。
- 已实现：服务端校验图大小、节点/边、允许类型、目标类型、视频输出限制和 DAG 无环；运行前校验 prompt、模型、素材归属/状态/类型和参考图数量。
- 已实现：node / from_here / all 三种范围冻结为 workflow_run.graph_snapshot，沿用 WorkflowService、workflow_node_execution、MediaJobService 和恢复调度器；运行提交具有项目画布级幂等记录。
- 已实现：多产物进入 WAITING_SELECTION，前端明确选择候选后服务端恢复后继；支持刷新恢复运行状态、分支失败隔离和运行取消。全局“工作流”入口降为“更多”中的“自动化”，旧 URL 和编辑器保留。
- 已执行 Flyway V31/V32 并重启本地前后端。未调用真实供应商生成 API；计费链路由用户在明确预算下验收。

成功标准：新用户从首页输入想法到提交第一条媒体任务，不必进入独立工作流页面；进阶用户能把素材、生图、选图、生视频连起来，能看清每条连线传递什么；刷新/关闭页面后画布和后台任务均可恢复。

### 设计假设与范围边界

- 「无限画布」指可平移、缩放、扩展的项目内画布，不是无限制创建节点或执行任务。服务端仍限制节点数、图大小、附件与费用。
- 左侧保留模型选择与提示词优化，但操作对象是**当前选中节点**；节点内只放主要输入和结果。避免出现两套互不一致的表单。
- 画布融合的是创作路径；通用搜索、数据库、文档等工作流，以及已有定义和历史运行，不能因导航收拢而丢失。
- 图节点可以引用上游输出，也可挂载用户上传素材。两种来源的优先级由用户明确选择，不隐式覆盖。
- 「视频素材输入」与「模型接受参考视频」不同。首期视频上传用于保存、预览和后续复用；仅当适配器能力实测通过时，才开放视频作为模型输入。
- 前端关闭后任务仍由服务端推进。浏览器中的轮询只刷新 UI，不承担任务调度。

## 3. 信息架构与导航

建议主导航中的「工作流」退到「更多/自动化」或创作台的「模板与历史工作流」入口。**先收拢入口，再根据使用情况决定是否撤掉独立页面**；现有 `/workflows`、`/workflows/:workflowKey` 链接长期保留重定向或兼容访问，不能直接删。

首页「生成图片/视频」→ 创建或打开项目 → `/creative/projects/:projectId/canvas`。首页输入只用于预填，不自动提交计费任务。新项目默认放置一个对应类型的生成节点；如果已选首帧/参考图，可同时放置素材节点，并连接到生成节点的对应输入端口。项目有未完成画布时继续打开原画布，不重复创建默认节点。

图片/视频项目主视图为「画布」。项目级「剧情/分镜」「素材」「任务」「设定」继续通过次级导航或顶部菜单访问；任务和素材也应能从画布侧边抽屉快速打开。小说项目首期保持章节页，待小说节点契约明确后再迁入画布。

工作流模板的定位：是可复制到项目画布的起点，而不是要求用户先创建独立工作流。旧工作流定义可作为模板或高级编辑入口；迁移时只复制**定义**，旧运行历史留在原归属，不伪装成新项目运行。

## 4. 创作台布局与视觉

### 4.1 桌面布局

```text
┌ 顶栏：返回作品｜作品名/保存状态｜模板｜撤销/重做｜运行范围｜任务 ┐
├ 全局窄导航 ┬ 节点检查器 320–360px ┬ 可平移缩放画布（剩余宽度） ┤
│            │ 模型 / 提示词 / 素材   │ 节点、连线、预览、结果、状态    │
│            │ 优化 / 参数 / 生成     │ 右下角小地图与缩放控制         │
└────────────┴──────────────────────┴─────────────────────────────────┘
```

- 延续现有工作台浅色中性底、`--wb-*` 令牌和蓝色主操作；不同节点用克制的类别色作细线/图标标识，状态色只用于状态。不要出现整页高饱和节点色块。
- 顶栏约 52–60px；画布占宽优先。左侧检查器可折叠，折叠后保留选中节点名称和编辑入口。
- 节点建议宽 240–300px，视频节点预览 16:9，图片节点预览保持原比例并设最大高度。节点外框半径 ≤8px，内容密度高于营销卡片。
- 画布背景用低对比网格；连线在普通状态清楚可见，选中时突出。边上显示「提示词」「首帧」「参考图」等输入语义，不能只画一条线。
- 画布默认 `fitView` 仅在首次进入或点击「适应画布」时执行；用户拖动后刷新恢复上次视口，不因任务刷新跳回原点。
- 工具条用 `lucide-vue-next` 图标，陌生图标提供 tooltip；撤销/重做、缩放、适应画布、添加节点均有稳定尺寸与禁用态。
- 空画布显示一个可直接操作的生成节点，不显示大段功能说明。报错和缺配置提示贴近对应节点。

### 4.2 节点与检查器

节点卡片只保留：类型/名称、简短提示词或素材缩略图、主操作、状态、最新结果。选中节点后，左侧检查器按「模型 → 提示词 → 输入素材 → 生成参数 → 优化建议/历史」展开。检查器编辑和节点内快速编辑使用同一个状态源，失焦后自动保存草稿；明确展示「保存中/已保存/保存失败」。

提示词优化只生成建议，不触发媒体生成。保留原文、建议和采用动作；多镜方案在画布中可一键拆成多个待确认节点，拆分前预览数量和连线。技能生成方案也需单独确认，不因选中技能就提交生成。

素材上传可从左侧、节点内或素材库选择；上传先成为 `creative_asset`，再绑定节点输入。显示文件名、缩略图、类型、来源和尺寸/时长。上游结果如有多个候选，必须选择一个具体 `assetId`，或显式开启批量分支；首期不隐式全选。

结果在节点下半部就地展示，支持预览、下载、选为输出、继续添加下游节点。队列位置如果后台无法可靠计算，就只显示「排队中」，不显示虚构的精确名次。

### 4.3 小屏与无障碍

- 900px 以下检查器改抽屉，顶部工具条收为菜单；画布保持平移和缩放，不把 DAG 强压成窄列。
- 触摸端支持双指缩放、单指拖动画布；选中节点与移动节点分开操作，避免触屏误拖。
- 键盘可切换焦点到节点、打开编辑、删除选中边；危险动作有确认。状态有文字和图标，不只靠颜色。
- 尊重 `prefers-reduced-motion`；后台进度更新不改变节点尺寸或画布坐标。

## 5. 节点与连线契约

首期节点限定为：`asset_input`（上传/选素材）、`text_input`（文本）、`image_generate`、`image_edit`（视模型能力）、`video_generate`、`output_select`（多候选人工选定）。不在首期开放任意 HTTP/SQL/终端节点；旧高级工作流仍在兼容入口运行。

每个节点有稳定 `nodeId`、类型、标题、画布位置、配置、输入绑定和可展示的结果引用。端口必须声明类型：`text`、`image_asset`、`video_asset`、`asset_collection`。连线记录 `fromNodeId/fromPort/toNodeId/toPort`；同一端口是否允许多输入、最多几个，以及素材顺序由节点类型和模型能力决定。连线只建立数据依赖，绝不触发任务。

输入解析优先级建议为：显式选定的节点本地素材或文本 > 已绑定的上游端口输出；两者并存时 UI 要求选择模式 `replace / append`，且只有模型确实支持多素材时允许 `append`。不允许靠展示顺序推断第一张是首帧。服务端再次校验所有 `assetId` 的租户/用户归属、媒体类型和模型能力。

禁止环；同一生成节点不允许引用自己的后代。删除节点前展示影响范围，删除画布引用不删素材/历史运行。上游配置发生变化时，后代显示「输入已更新」，旧结果保持可查看但不视为新配置的产物。运行只取本次快照中的输入，不读取正在编辑的草稿。

首期运行范围：

1. **生成当前节点**：只解析其依赖；若依赖没有可用产物，提示先生成/选择上游，绝不默默触发整条链。
2. **从这里继续**：复用已选定且未失效的祖先产物，执行当前节点及选定的下游分支；运行前确认将产生的媒体任务数。
3. **运行整条流程**：按 DAG 执行可自动推进的节点；遇到多候选人工选片/缺输入时暂停并等待确认，不擅自替用户选片。

运行提交前预检：图合法、模型绑定可用、Prompt 长度、素材权限/类型、供应商能力、任务上限和预计生成条数。成本仅在有可靠模型单价时展示估算，未知时明确「费用未知」，不以 0 代替。一次运行使用不可变的图、模型、Prompt、素材快照。

## 6. 后台数据与接口设计

### 6.1 数据归属

建议新建项目画布草稿表，而非把每次拖动都保存成 `workflow_definition_version`：

| 拟议对象 | 最小字段 | 用途 |
| --- | --- | --- |
| `creative_canvas` | `id, project_id, tenant_id, user_id, title, draft_graph JSONB, revision, viewport JSONB, created_at, updated_at` | 项目当前可编辑草稿；项目/用户复合外键，`revision` 做并发写保护 |
| `creative_canvas_version` | `id, canvas_id, version, graph_snapshot JSONB, created_by, created_at` | 显式发布/运行快照；版本不可变 |
| `creative_canvas_run` 或现有 `workflow_run` 扩展 | `canvas_id, canvas_version, run_scope, from_node_id, status, graph_snapshot, created_at` | 画布运行归属与范围；优先评估扩展 `workflow_run`，避免双引擎 |
| 节点任务关联 | `run_id, node_id, attempt, media_job_id, status, selected_asset_id` | 一个节点可多次生成；按尝试保留历史，不覆盖旧结果 |

字段名与表名是方案，不是现有 schema。迁移应使用新的 Flyway 编号；当前仓库已经到 V30，实施前先重新扫描版本占用。`creative_canvas` 的 `project_id`、`tenant_id`、`user_id` 应匹配 `creative_project` 组合身份，防止跨租户关联。运行与节点结果按项目归属和当前用户授权读取，不能沿用只按 tenant 读写定义的旧接口直接暴露项目草稿。

现有 `workflow_node_execution` 以 `(run_id,node_key)` 唯一，只表达一次运行中一个节点的等待/结果。首期若每次「生成当前节点」创建新的 run，可以复用这个约束；同一 run 内同一节点原位重试则需审视 `attempt` 和关联表，保证历史任务不被覆盖。决定是否扩表，应在接口与数据库设计评审时用真实重试用例验证。

### 6.2 拟议 API

以下路径是**建议契约**，实现时按当前 `/api/ai/creative` 前缀及现有控制器风格定稿：

| 方法与路径（拟议） | 行为 |
| --- | --- |
| `GET /ai/creative/projects/{projectId}/canvas` | 返回草稿图、revision、viewport、节点最新任务摘要 |
| `PUT /ai/creative/projects/{projectId}/canvas` | 保存图与视口，携带 `expectedRevision`；冲突 409，返回最新 revision |
| `POST /ai/creative/projects/{projectId}/canvas/validate` | 结构、端口、模型能力、素材权限和运行范围预检；无计费动作 |
| `POST /ai/creative/projects/{projectId}/canvas/runs` | `scope=node/from_here/all`、`nodeId`、`expectedRevision`、幂等键；冻结快照并返回 runId |
| `GET /ai/creative/projects/{projectId}/canvas/runs/{runId}` | 返回节点状态、关联媒体任务、输出素材和等待人工选择原因 |
| `POST /ai/creative/projects/{projectId}/canvas/runs/{runId}/selections` | 指定节点候选 `assetId` 并恢复后继，校验候选属于该节点本次运行 |
| `POST /ai/creative/projects/{projectId}/canvas/runs/{runId}/cancel` | 停止尚未提交任务；已在供应商侧运行的任务按适配器真实取消能力处理 |

保存图要校验节点/边数量、位置坐标范围、JSON 大小、允许的节点类型、端口兼容性、无环和所有素材归属。保存草稿不要求 Prompt 完整；`validate`/`runs` 才要求运行范围内所有必填输入有效。并发编辑冲突返回 409，前端提供重新载入/比较，不能静默覆盖。

运行请求必须用服务端幂等键或唯一约束，防止双击/重试创建两批计费任务。启动时在事务中冻结图和目标节点集合；排队任务创建与工作流等待记录的边界要保证失败可恢复，不能出现已扣费任务却没有对应节点记录。

### 6.3 执行与状态机

```text
画布草稿 --校验/冻结--> 画布运行快照 --DAG 解析--> 节点执行
                                               ├─ 文本/选择节点：同步产出或等人工确认
                                               └─ 媒体节点：MediaJobService.create → QUEUED
                                                                          ↓
                                     MediaJobScheduler 认领/提交/查询/入库
                                                                          ↓
                                     WorkflowMediaResumeScheduler 回填节点输出
                                                                          ↓
                                                 解锁后继或等待人工选择
```

`MediaJobScheduler` 已有定时认领/轮询/租约/配额/异常提交对账，方案复用。画布运行状态拟议：`RUNNING / WAITING_EXTERNAL / WAITING_SELECTION / SUCCEEDED / FAILED / CANCELLED`；现有 `workflow_run` 约束仅允许前四项中的部分，实施前需明确 DB 迁移与旧消费者兼容，不能仅在 UI 添加新状态。

媒体节点结果以 `media_job_output → creative_asset` 作为事实来源。工作流节点存 `jobId`、输出 `assetId` 与快照索引，不复制二进制。多结果节点应呈现候选集合，后继只能读取已选结果。提交结果不明时沿用 `RECONCILING` 策略，不自动再次提交；入库失败走恢复入库，不再计费。取消时区分「取消排队」与「请求取消供应商任务」，不能保证所有供应商都能停止费用。

失败隔离：一个分支失败不应自动改写并行分支已成功结果；重试从失败节点或指定下游建立新运行/尝试，祖先结果复用要记录其来源运行与 assetId。避免“旧上游结果 + 新配置”被误认为同一次一致快照。

前端可先复用现有媒体任务 SSE/运行详情轮询；后续若增加画布运行事件流，应支持事件序号和断线补偿。无论采用哪种方式，最终 UI 都以服务端运行记录为准。后台定时器的开启情况需在部署配置中验证；当前 `creative.scheduler.enabled` 默认开启，但不能因此省略部署冒烟。

## 7. 前端实施拆分

1. **抽公共画布层**：从 `WorkflowEditor.vue` 提取 Vue Flow 容器、节点/边转换、撤销/重做、视口持久化；通用工作流编辑器继续消费公共层，避免行为回归。
2. **项目画布页**：新增 `/creative/projects/:projectId/canvas`，接入项目壳和草稿 API。首页进入时初始化默认节点。首期只支持一个生成节点也能完成一次任务。
3. **节点检查器**：复用当前创作表单的模型目录、Prompt 优化、素材选择和能力约束，但由统一节点草稿状态驱动。节点内结果区读取现有素材/任务预览组件。
4. **运行映射**：图中状态来自 run/node execution/media_job；顶部显示当前运行与任务抽屉。支持生成当前节点、选片、重试、取消、刷新恢复。
5. **导航收拢**：待画布端到端稳定后，把全局工作流入口移入自动化/模板；旧 URL 和项目内 `workflow` 历史继续可读。再评估是否把旧项目工作流列表合并为画布历史。

避免直接把 `WorkflowEditor.vue`、`ProjectStudioTab.vue` 两个大组件套在一起。它们分别包含全页导航和局部状态；简单嵌套会保留当前信息重复问题，并产生两个保存源。

## 8. 分期、验收与发布

### P0：交互原型与契约

完成桌面/窄屏静态原型、节点/端口 schema、模型能力矩阵、草稿/运行/候选状态定义。用两个真实流程走查：文生视频；上传参考图 → 生图 → 选图 → 图生视频。明确首页输入进入节点的映射，以及旧工作流数据保留方式。此阶段不触发付费 API。

### P1：可用的单节点创作画布

首页进入视频/图片画布，预填模型/Prompt/素材；节点和左侧编辑同步；草稿自动保存与 409 冲突处理；点击生成入现有 `media_job` 队列，刷新可恢复状态与产物。验收：关闭浏览器后任务继续，重开能看到最终结果；双击提交只有一个计费任务；未配置模型和上传失败有明确提示。

### P2：连接与分步运行

上线素材、图片生成、人工选片、视频生成节点；类型化端口、多输入绑定、节点校验；单节点运行与从节点继续；上游变更使下游待更新，历史结果可追溯。验收：一个上游产出两张图，用户选第二张作为首帧，供应商请求快照中确实是第二张；刷新或重启服务后能恢复等待和后继。

### P3：整图运行与入口收拢

整条 DAG 运行、人工选择暂停/恢复、分支失败隔离、模板复制、运行历史和旧 URL 兼容。完成真实供应商与模拟供应商两套 E2E；再把独立工作流入口降级为高级入口。首期不移除现有数据库表和历史页面。

### 发布门禁

- 前端：桌面、平板、手机截图与交互检查；拖动/缩放/弹层无重叠；深浅色和长提示词可读；浏览器刷新视口不跳动。
- 后端：图验证、租户/用户隔离、幂等提交、租约恢复、`RECONCILING`、入库失败、取消与重试测试。
- E2E：零计费 mock 先覆盖 P1/P2/P3 流程；真实供应商仅在明确测试预算内做单次验证，记录 `jobId`、模型和结果，不在文档写密钥。
- 回滚：功能开关允许恢复旧创作入口；新草稿表只做增量迁移；旧 workflow 定义和 run 不删除。回滚后已入队任务仍由既有调度器处理。

## 9. 待定决策

1. 项目画布是一项目一张，还是允许一项目多张？建议 P1 一项目一张，避免作品与画布列表再度重复；多方案可用版本和模板解决，真实需求出现后再扩展。
2. 整图运行遇到人工选片，是暂停整个 run 还是只暂停依赖该结果的分支？建议先暂停相关分支，其它独立分支可继续；实现前需确认现有执行器是否支持并行分支状态，P2 可先限制整图运行。
3. 旧 `workflow_definition_version` 是否直接作为画布版本存储？建议运行引擎复用，草稿另存并明确项目归属；具体表关系以接口设计评审和迁移成本验证后定稿。
4. 画布中的“视频作为输入”能力按供应商/模型逐项验收；未验证前只做上传、管理与预览。
5. 短剧「剧情/分镜/候选」如何映射画布节点，待 P2 单镜闭环稳定后设计；不要为迁移而抹掉现有剧集、场次、镜头的结构化数据。
