# 视频提示词优化师：内置技能与固化规则

日期：2026-11-04  
状态：已实施（P0）  
范围：AI 创作工作台中的视频提示词优化能力；不涉及新的媒体生成链路

## 1. 背景与定位

视频生成质量对提示词结构高度敏感。当前工作台已有两处文本改写入口：

- 项目「快速生成」与镜头检查器的「优化提示词」按钮（`PromptOptimizationService`，`VIDEO_PROMPT` 模式）；
- 内置技能「视频提示词导演」（从目标/风格生成一条新提示词）。

两者都缺一个面向"用户已经写好一段提示词，需要按固定标准体检并改写"的入口。本设计新增内置技能：

**视频提示词优化师**（slug `video-prompt-optimizer`）

- 输入：用户已写好的视频提示词，可附带风格、时长、平台等约束；
- 输出：诊断结论 + 按七要素改写后的单镜头提示词 + 实际改动清单 + 冲突/待补项；
- 边界：只做文本改写，不创建媒体任务、不产生计费；文案始终保留原文。

它与「视频提示词导演」的区别：导演面向"从想法开始"，优化师面向"已有稿件的标准化改写"。

## 2. 固化规则

规则集中在 `creative/support/VideoPromptGuide.RUBRIC`，内置技能与「优化提示词」按钮共用，避免两套口径。

### 2.1 七要素公式

```text
[主体] + [动作] + [环境] + [镜头语言] + [光线色调] + [风格] + [质感]
```

| 要素 | 要求 |
|---|---|
| 主体 | 外貌、服装、年龄、表情、关键道具；只写画面可见信息 |
| 动作 | 一个核心动作，写明部位、方向、速度、幅度；多动作建议拆镜 |
| 环境 | 地点、天气、时间、背景细节，与主体动作发生关系 |
| 镜头语言 | 景别 + 角度 + 一种主运镜 + 速度；可给等效焦距 |
| 光线色调 | 光源方向与性质 + 主色调；只用一个主光逻辑 |
| 风格 | 只选一种整体风格；风格名可用常用英文 |
| 质感 | 胶片颗粒、浅景深、自然皮肤质感等可验证介质词 |

### 2.2 镜头词汇表

- 景别：大远景 / 远景 / 全景 / 中景 / 近景 / 特写
- 角度：平视 / 俯拍 / 仰拍 / 过肩 / 主观视角
- 运镜：固定 / 推近 / 拉远 / 横移 / 摇镜 / 跟拍 / 环绕 / 升降 / 手持
- 光线：黄金时刻 / 蓝调时刻 / 侧逆光 / 柔光 / 轮廓光 / 体积光 / 顶光 / 实用光源
- 风格：电影写实 / 纪录片手持 / 日系清新 / 赛博朋克 / 动画 / 定格

### 2.3 避坑清单

- 一个提示词只给一个核心动作，不串联多个动作；
- 一个镜头只用一种主运镜；
- 用正向描述替代"不要……"类负向词，不假设模型支持 negative prompt；
- 人物解剖用正向表述，不写指令式英文补丁；
- 保留用户已给出的品牌、人物、台词、风格与参考图约束；
- 只描述画面可见内容，声音未接入就不写声音；
- 正文不超过 500 字。

### 2.4 与参考资料的差异

参考资料将"4K、photorealistic、film grain"列为画质项。本实现保留 `photorealistic`、`film grain` 这类**视觉介质词**，但明确禁止 `8K`、`超高清`、`大师级` 等无法由模型保证的画质承诺，与产品原则「不伪造模型能力」一致。

## 3. 实现

### 3.1 后端

- 新增 `creative/support/VideoPromptGuide.java`：共享 `RUBRIC` 常量；不含输出契约。
- `CreativeSkillContent` 新增种子 `video-prompt-optimizer`：
  - `category=DIRECTING`、`stage=PROMPT`、`inputTypes=TEXT`、`outputTypes=TEXT`、`requiredCapabilities=[CHAT]`；
  - 正文 = `RUBRIC` + 优化师专用输出契约（`summary/prompt/changes/warnings/missing`）；
  - 明确要求不输出 `shots`，避免前端误走"逐镜生成"。
- `CreativeSkillService.parsePlan` 增加可选字段 `changes`（字符串数组），其他技能不返回时为空数组。
- `PromptOptimizationService.SYSTEM_VIDEO_PROMPT` 改为复用 `RUBRIC`，仅保留自己的 `optimizedText` 输出契约。

### 3.2 前端

- `ProjectStudioTab.vue` 技能方案区展示 `plan.changes`（本次优化点），与 summary、warnings、missing 并列；
- 文本型技能继续使用"采用到输入台"：改写结果写回输入台，原文保留为草稿原稿；
- 技能库通过现有种子自动出现，无需新页面。

### 3.3 数据

无新增表、无迁移。技能行由启动时 `@PostConstruct seed()` 插入；新 slug 在已有环境也会自动补齐。后续修改正文需新增版本行（沿用现有"正文升版走显式版本流程"约定）。

## 4. 状态与安全边界

- 方案生成只调用文本模型，不创建 `MediaJob`，不产生计费；
- 技能运行失败保留 run 记录，可在原 run 重试方案；
- 用户确认/采用前不修改任何已确认内容；
- 输出仍需通过既有 `MODEL_PROMPT_MAX=500` 校验，超长在提交生成时被拒绝；
- 不新增跨项目、跨用户读取；素材引用规则不变。

## 5. 验收

1. 技能库出现「视频提示词优化师」，分类"导演与分镜"、阶段"提示词"、兼容状态 READY；
2. 在视频项目「快速生成」中粘贴一段粗糙提示词，生成方案后能看到诊断、改动清单、改写稿；
3. 改写稿可编辑并"采用到输入台"，原文与草稿不被覆盖；
4. 方案不返回 `shots`，不出现误触发的逐镜生成按钮；
5. 现有「优化提示词」按钮行为不回退，输出仍为结构化 `optimizedText/changes/suggestions/missing`。

## 6. 后续

- 需要真实模型抽检改写质量，重点看：多动作是否被正确拆出、主运镜是否唯一、是否仍出现画质承诺；
- 可考虑把七要素检查做成确定性 lint（不依赖模型），在提交前提示缺项；
- 若后续接入 negative prompt 或多参考图，再扩规则，不在当前版本提前承诺。
