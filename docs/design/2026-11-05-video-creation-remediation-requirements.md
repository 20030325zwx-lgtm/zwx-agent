# Aster 视频创作整改需求说明书

日期：2026-11-05  
版本：需求方案 v1.0  
状态：P0/P1/P2 已实施（2026-11-06，见 `2026-11-06-video-production-p0.md` 与 `2026-11-06-video-production-p1-p2.md`）；P3 待实施，本文不代表已全部上线。  
适用范围：VIDEO 项目的创建、故事与画风、分镜、生成与选片、成片及视频画布衔接。

## 1. 目标与设计依据

### 1.1 要解决的问题

让用户从一句想法或一段剧本开始，在同一个项目里完成故事整理、分镜编辑、视频生成、候选选片和成片导出。每一步都应知道：当前在做什么、已有结果是什么、缺什么、下一步点击哪里。

产品目标是完整的视频制作闭环。仅调整导航、按钮、卡片颜色，或只生成多个视频文件，不构成本次整改完成。

### 1.2 参考范围

- 用户提供的幻映 AI 截图及链接：https://fallbackp.top/canvas/1c_wv2RVZU8qVTu0N7Ap1。
- 截图可观察到五步引导「选择画风 → 输入故事 → 生成分镜 → 生成视频 → 合并成片」、画风和故事输入节点、分镜表格、时长/提示词/台词/关联资产字段、可选分镜图阶段。
- 链接只完成只读观察；当时页面处于专注模式并显示其他设备在线。没有实际提交生成、测试计费或完成合片。参考站的取消、恢复、导出、数据结构等内部能力均未验证。
- 参考内容只用于提炼流程和交互，不复制对方品牌、风格文案、图片或图标资产。
- 现状依据为当前源码、Git 状态及既有验收记录；历史文档与代码不一致时以源码为准。

### 1.3 与既有方案的关系

本方案补充并调整 `2026-11-04-creative-canvas-workflow-integration.md` 中视频项目默认进入自由画布的决策：新的视频项目推荐进入带阶段引导的「制作」视图；自由画布继续可达。图片、小说及通用工作流不在本次导航调整范围内。

「制作」与「画布」是同一项目的不同工作视角。最终共享镜头、素材、候选和任务引用；禁止维护两份名称相同、结果互不关联的分镜。分期实施时，未打通的数据关系必须明确告知用户。

视觉以当前 `frontend/src/design/tokens.js` 为基线。该文件已有暖灰底、石墨主按钮、鸢尾紫强调的 `--cr-*` 创作令牌；不能机械沿用早期文档中的蓝色主按钮，也不新增第三套主题体系。全局 `--wb-*` 的排版、间距和状态语义继续复用。

## 3. 用户场景与范围

### 3.1 必须支持的入口

1. 想法起步：输入「做一段 30 秒雨夜车站短片」，选择风格，生成分镜草稿。
2. 剧本起步：粘贴已有剧本，保留原文，自动拆镜后逐行调整。
3. 素材起步：选择已有视频，建立镜头及候选，直接进入选片/成片；模型生成不是必经步骤。
4. 继续项目：恢复上次阶段、当前集、选中镜头和未完成任务，刷新不创建重复项目或任务。
5. 系列制作：按需启用剧集、场次、角色、场景和连续性管理；单个短片不强制展示全部结构。

### 3.2 首个完整版本范围

包含故事编辑、项目画风、结构化分镜、单镜/批量视频生成、已有素材选片、顺序拼接和 MP4 导出。分镜图是可选增强，不作为文本生成视频或素材成片的前置条件。

复杂多轨剪辑、音色克隆、自动配乐、专业转场、多人实时协作、自动人物一致性判定不列入首个完整版本。台词文本的存在不代表已具备配音或字幕烧录能力。

## 4. 信息架构与整体布局

### 4.1 项目入口与导航

- 顶层只保留「制作」「画布」两个工作视角；「素材」「任务」「项目设置」以工具入口/抽屉访问。
- 制作视图顶部常驻五个阶段：「画风 → 故事 → 分镜 → 视频 → 成片」。画风可选择「暂不指定」，分镜图可跳过。
- 阶段栏是进度和导航，不是禁止返回的向导。已完成阶段可随时回访；后续阶段缺前置条件时允许查看空态，并说明缺什么。
- 新 VIDEO 项目默认进入制作视图；历史项目首次打开保持原入口，提供「进入制作」提示，之后记住用户选择。
- 现有 story/storyboard/settings 深链接保持可访问；新布局接管后再按镜头/场次上下文映射，不能直接丢失参数。

### 4.2 桌面布局线框（目标布局）

```text
┌ 全局窄导航 ┬ 返回作品  项目名  已保存       制作 / 画布    素材  任务(2)  ⋯ ┐
│            ├ ①画风 ─ ②故事 ─ ③分镜 ─ ④视频 ─ ⑤成片                     ┤
│            │ 当前集 · 6 个镜头 · 目标 30 秒 · 已选 4/6     [当前阶段主操作] │
│            ├──────────────────────────────┬───────────────────────────┤
│            │                              │ 选中镜头 · 镜03           │
│            │  分镜列表 / 视频结果 / 成片   │ 预览与候选                │
│            │  （随阶段切换，同一项目）    │ 提示词 / 素材 / 模型参数   │
│            │                              │ [保存] [生成此镜头]        │
│            └──────────────────────────────┴───────────────────────────┤
│            │ 必要时显示批次摘要 / 成片片段条；不遮挡最后一行             │
└────────────┴──────────────────────────────────────────────────────────┘
```

- 故事阶段以编辑器为主，右侧显示风格和项目摘要；分镜阶段以表格/镜头列表为主；视频阶段以媒体候选为主；成片阶段以播放器和片段条为主。
- 每个阶段只有一个项目级主要行动，镜头内可以有明确对象的局部行动。
- 不同时打开左检查器、右候选、素材栏和任务栏。素材/任务抽屉临时覆盖右侧，关闭后恢复原编辑状态。
- 高级参数默认折叠；普通用户无需看执行图、供应商任务 ID、租约或内部枚举。

## 5. 分阶段功能与交互需求

### 5.1 画风与项目设定（REQ-STYLE）

- 创建时最少输入项目名或故事内容；名称可从首句建议生成，用户可编辑。
- 画风选择器复用 30 种目录与预览图，提供搜索、分类、最近使用和收藏。卡片显示名称与一句说明。
- 项目保存默认风格；镜头显示「继承项目」或「单独设置」。改变默认风格只影响继承它的镜头。
- 可选输入画幅、目标总时长、题材和叙事气质。题材/气质作为补充，不把四级风格组合变成首次使用的必填项。
- 风格预览是示意图，不能暗示实际模型会生成完全相同效果。
- 「跟随原片」仅在有有效参考图时可选。删除最后一张参考图后明确提示该模式需调整，不静默以另一种风格生成。
- 更改风格后显示受影响镜头数；旧候选保留，标记「基于之前的设定」。用户决定保留旧结果还是重生成。
- 提示词优化和实际生成采用同一份风格解析规则，支持预览最终发送内容；不能出现界面已选风格但生成链路漏传。
- 第一版允许收藏/最近使用继续本地保存，界面不承诺跨设备同步；项目风格必须服务端持久化。

### 5.2 故事编辑（REQ-STORY）

- 主编辑器提示「描述故事、人物、关键动作和结尾，也可以直接粘贴剧本」。编辑正文不受单镜头模型提示词长度限制。
- 展示自动保存状态；项目目标时长是创作目标，供应商不支持精确时长时允许后续调整并明确差异。
- 「整理故事」先返回建议稿，支持原文对比、编辑、采用或放弃；不覆盖原文，也不自动触发视频生成。
- 点击「生成分镜草稿」展示使用的文本模型和拆分约束，保留原故事版本。
- 简单短片自动创建内部默认剧集/场次；用户看到「当前短片」，不需要给默认场次起名。
- 系列模式可管理剧集和场次，明确批量生成的作用范围是当前集、当前场次还是所选镜头。
- 文本模型调用可能产生费用，不能因为不是视频生成就显示“免费”。若价格不可获得，不展示伪精确估算。

### 5.3 结构化拆镜（REQ-PLAN）

生成结果必须是一份可校验的草稿，至少含稳定草稿行标识、镜头顺序、目标时长、画面动作、运镜描述、台词/旁白、生成提示词。角色/场景引用应指向可识别实体；模型不能自行编造已有 assetId。

交互流程：故事输入 → 生成中 → 草稿预览 → 用户调整 → 确认创建镜头。确认前不覆盖现有正式镜头。

- 预览显示镜头数、时长合计及与目标时长的偏差；模型支持的时长档位由能力表决定，不以任意整数输入冒充支持。
- 草稿支持增删、改序和编辑。建议片长不合理时显示具体原因及修正方式。
- 输出解析失败时保留原故事，显示「分镜格式未能解析，尚未修改已有镜头」；提供重试和人工编辑入口。
- 已有镜头时提供「追加镜头」或「替换所选未生成镜头」。替换前展示数量及引用影响；已有候选/成片引用的镜头不能静默替换。
- 确认写入使用服务端幂等键与项目/故事版本检查。重复点击不得重复建镜；期间故事已变更时提示重新确认来源版本。
- 同一草稿只允许一次有效采纳；后续修订产生新草稿版本，不复用已消费的写入意图。

### 5.4 分镜编辑（REQ-SHOT）

默认显示可编辑镜头列表，宽屏可切表格视图。每行含：序号、画面预览/占位、时长、画面与动作、台词摘要、关联素材、制作状态、更多操作。

- 单击选择镜头，正文可直接编辑；双击媒体打开大预览。点击输入框不能触发行选择后的页面跳转。
- 列表与右侧检查器共用同一草稿状态。未保存内容不能被后台轮询覆盖。
- 右侧依次为媒体、候选、提示词、参考素材、模型参数、高级剧情字段；不要要求用户滚过长表单才能看结果。
- 增加镜头可插入当前镜头之后；新镜头进入编辑态。支持拖动排序及「上移/下移」键盘替代。
- 修改顺序保持镜头 ID 不变，候选跟随镜头。运行中的批次使用提交时冻结顺序，当前编辑不改变已提交内容。
- 单行删除说明只删除/归档镜头引用，历史产物按素材策略保留。成片引用中的镜头必须先处理引用或明确生成新成片版本。
- 支持多选与「全选当前筛选结果」，显示总数；不能暗中选中筛选外镜头。
- 可选分镜图拥有独立候选和选定状态，与视频候选区分。只有用户明确选作首帧时才进入视频输入。
- 参考素材标明作用：角色参考、场景参考、首帧等；模型不支持的用途不能发送后再报错。

### 5.5 视频提交与批次（REQ-GEN）

- 单镜主按钮文案「生成此镜头 · 6 秒」；批量按钮「生成所选 4 镜」。时长来自实际选择档位。
- 提交前先保存当前修改，再校验并冻结输入。保存失败或冲突时不提交旧内容。
- 确认面板列出镜头范围、模型、时长、参考素材、预计任务数及成本来源。价格未知显示「费用未知」，不能显示 0。
- 预检失败逐镜列出原因，并可跳转修正；提交前允许明确排除失败项，不能悄悄改变批量范围。
- 预检通过后若镜头/模型配置改变，提交时服务端重新校验版本；不能仅相信前端通过标记。
- 同一提交意图的双击、网络重试、刷新恢复必须返回同一批次/任务。用户主动“再生成一版”使用新意图。
- 已在生成的镜头显示状态及任务入口，默认阻止重复提交；明确再次生成才新建候选。
- 批次失败不阻断其他可独立执行的镜头；重试只针对选定失败项。
- 供应商是否已受理不确定时，先对账恢复，不能把未知任务直接当失败再次提交并重复计费。
- 停止按钮文案「停止后续提交」。提示「已提交的任务仍可能完成并计费」；只有适配器真实支持取消时提供对应操作。
- 页面关闭后任务继续由服务端执行。重新打开能恢复批次、候选和选片状态。

### 5.6 候选比较与选片（REQ-SELECT）

- 每个候选显示预览、实际时长、生成/上传来源、创建时间、版本标签及「采用」。
- 视频默认静音且不自动播放整个列表；同一页面最多一个自动连续播放源。媒体未加载时保持占位尺寸。
- 采用按钮改为「已采用」，候选外框和角标同步变化；生成成功不自动采用。
- 新生成版本不替换旧选片；当前已采用候选始终可见。取消采用后，成片阶段提示缺镜头。
- 可将已有视频登记为镜头候选；它与生成候选遵循相同的归属、选片和成片规则。
- 候选与当前提示词/风格版本不同，展示「较早设定」，允许明确继续采用，不强制重新消费模型。
- 点击失败候选展示可理解的原因与下一步；内部错误详情进入可展开诊断区。
- 签名播放地址过期可重新获取，不能把 URL 过期误判为素材丢失或重新触发生成。

### 5.7 成片与导出（REQ-EXPORT）

首版成片定义：按用户确认的顺序拼接已选视频，输出一份可播放、可下载的 MP4。

- 进入成片时展示片段顺序、已选数、缺片镜头数及实际总时长。实际时长取媒体探测结果，不能直接使用生成目标时长。
- 缺片镜头阻止完整导出；允许用户明确选择「仅导出已选片段」，确认面板列出被排除镜头，成片记录保存该范围。
- 首版支持调整成片顺序和移除片段；移除不删除原镜头和素材。源镜头排序与成片排序分别保存，用户可选择重新同步。
- 统一输出画幅和分辨率；默认保持比例并补边，裁切须显式选择并预览，禁止默认拉伸。
- 首版顺序拼接不承诺精细裁切。若加入裁切，必须记录入点/出点并验证有效范围后单独验收。
- 默认保留片段原声，无音轨片段补静音；混合音频采样率/声道由服务端规范化。字幕、配音和配乐未交付前不展示可点击的假入口。
- 输出默认拟定为 MP4/H.264/AAC；编码器和许可/部署可用性在实施阶段确认，不能只在开发机可用。
- 导出冻结镜头 ID、候选 ID、素材版本/引用、排序及输出设置。期间继续编辑项目不改变在途成片。
- 提交采用幂等键；进度区分排队、准备素材、处理中、上传结果、完成/失败。后端无可计算百分比时只显示阶段。
- 完成后提供播放、下载、再次导出和版本历史。失败保留选择与顺序，可重试；取消后清理临时文件并保留源素材。
- 刷新、重启、下载链接过期均可恢复；链接过期只重新签名，不重新渲染。

## 6. 画布衔接规则

### 6.1 目标体验

制作视图负责阶段推进，画布负责自由组合和依赖表达。未来可在画布展示「项目风格」「故事」「分镜集合」「生成结果」「成片」业务节点，分镜集合节点展开后编辑同一份镜头数据。

- 从镜头「在画布中查看」定位对应节点，保留当前项目和镜头上下文。
- 新建故事流程可自动布置业务节点和必要连接；普通用户无需手工连接文本边、素材边和执行边。
- 连线显示业务含义，如「项目风格」「首帧」「角色参考」。不能仅用颜色区分。
- 镜头节点引用稳定 shotId；节点位置与缩放属于画布数据，剧情/提示词与选片属于镜头数据。
- 在任一视图提交镜头生成，经统一镜头生产入口登记候选；禁止画布和分镜分别为一次点击创建任务。
- 删除画布展示节点默认只移除展示引用，删除镜头必须是独立且明确的操作。

### 6.2 渐进衔接

P0/P1 保持旧自由节点兼容。自由视频节点不会自动成为正式分镜；提供「加入分镜」显式导入入口，选择已有/新建镜头并预览映射，重复导入可识别。

P3 再实现双视图编辑同一镜头。在这之前界面注明「此节点尚未关联分镜」，不能把“在同一项目”表述为“已自动同步”。两条执行链共享媒体调度能力，但镜头候选写回必须明确唯一责任方。

## 8. 状态、保存和失败处理

### 8.1 区分四类状态

镜头内容是否完整、后台任务是否成功、候选是否采用、成片是否导出是不同事实，不能放进单个“完成”标签。

| 维度 | 展示状态（产品语义，非现有枚举承诺） | 行为 |
| --- | --- | --- |
| 草稿 | 保存中 / 已保存 / 保存失败 / 版本冲突 | 失败提供重试；冲突保留本地文本并允许比较 |
| 镜头准备 | 待完善 / 可生成 / 设定已更新 | 指出缺失字段或与旧结果的差异 |
| 生成任务 | 排队 / 提交中 / 生成中 / 结果整理 / 失败 / 状态待确认 | 服务端为准；待确认先对账，不自动重复生成 |
| 候选 | 待选片 / 已采用 / 较早设定 | 明确结果和当前草稿关系 |
| 成片 | 缺片段 / 可导出 / 导出中 / 已导出 / 失败 | 展示本次导出冻结版本 |

阶段完成依据实际数据计算；“看过页面”不代表完成。“视频完成”要求目标范围中的镜头均有有效已选候选；“成片完成”要求有成功导出产物。

### 8.2 保存策略

- 输入停止约 800ms 后自动保存，失焦补存；提交生成前等待保存完成。
- 脏字段与服务端轮询数据分开合并。服务端返回 409 时禁止静默覆盖，提供保留本地内容、查看服务器版本、重新应用。
- 保存失败在顶栏持续显示，toast 只作补充。离开前有未保存内容则提示；网络恢复后可重试。
- 浏览器本地缓存如用于恢复，只保存必要草稿，按用户/项目隔离；不缓存模型密钥。

### 8.3 空态与异常文案

| 场景 | 文案及行动 |
| --- | --- |
| 无故事 | 「写下故事或粘贴剧本，开始拆分镜头」+ 编辑器 |
| 无镜头 | 「故事已准备好，生成分镜草稿」+ 主按钮；同时允许手工加镜头 |
| 无模型 | 「尚未配置视频模型」+ 模型设置入口，返回保留草稿 |
| 缺参考图 | 「当前模型需要首帧图片」+ 选择图片，不展示泛化“参数错误” |
| 生成失败 | 「镜03生成失败：可读原因」+ 查看详情/重新生成 |
| 未选片 | 「还有2个镜头待选片」+ 定位第一个 |
| 导出缺素材 | 「镜04的视频暂不可读取」+ 重新选片/刷新素材状态 |
| 暂时断网 | 「连接已断开，后台任务可能仍在执行」+ 恢复连接 |

## 9. 数据与服务改造要求

### 9.1 复用与新增边界

复用现有项目、剧集、场次、镜头、候选、批次、MediaJob、素材存储和画布运行基础。以下是待设计的数据概念，不是已存在的表名或接口承诺：

| 概念 | 需要记录的事实 | 实施要求 |
| --- | --- | --- |
| 视频制作设定 | 项目默认画风、画幅、目标时长、创作模式、版本 | 评估扩展现有项目设定；禁止为同一值建立两个权威来源 |
| 分镜草稿 | 来源故事版本、模型快照、结构化行、状态、采纳意图 | 确认前隔离，确认后保留来源追踪 |
| 镜头补充关联 | 项目风格继承/覆盖、参考素材角色、可选分镜图 | 使用明确关系，不能塞进不可解析文本 |
| 画布镜头映射 | 项目、节点、镜头、映射版本 | 所有权校验；同一任务只登记一次候选 |
| 生成输入快照 | 提示词、风格、参考素材、模型和参数、镜头版本 | 不可变，支持判断候选是否基于旧设定 |
| 成片定义与任务 | 排序后的候选引用、输出参数、任务状态、产物 | 草稿与运行快照分离，保留历史版本 |

全部访问按现有服务端 actor 校验项目/用户/租户归属；关联素材、候选、镜头必须属于允许范围。实际字段、表名、Flyway 版本号在实施前核对，不从本需求文档直接猜编号。

### 9.2 需要提供的服务契约

路径与 DTO 名称待详细设计；本节定义行为和错误语义：

1. 读取/保存视频制作设定，带 expectedVersion。
2. 创建分镜草稿、查询生成状态、更新草稿、确认采纳；返回来源版本与新增/替换数量。
3. 批量镜头编辑/排序与范围校验，错误定位到具体镜头和字段。
4. 生成预检，返回可提交项、阻塞项、模型能力、任务数量及可信成本信息；预检本身不调用媒体生成。
5. 提交/恢复批次、查询统一任务摘要、候选采用；提交带幂等键和预期版本。
6. 创建/保存成片草稿、校验素材、提交导出、查询/取消导出、获取签名下载地址。
7. 画布结果显式登记为镜头候选；校验素材、任务和目标镜头归属以及重复登记。

错误需区分输入无效、权限不足、版本冲突、模型能力不匹配、配额不足、供应商失败和执行状态未知。内部异常堆栈不直接作为用户文案。

### 9.3 成片运行要求

成片新增受控 ffmpeg/ffprobe 或等价媒体运行环境，具体进程/容器组织在实现设计中确定。必须有输入白名单、资源/时长上限、任务超时、并发限制、临时目录隔离与清理、进程取消和重启恢复。

输入从受权素材引用读取，不接受任意命令或任意外部路径。输出进入现有统一 ObjectStorage；本地临时文件不能成为永久下载地址。租约失效后旧执行者不能覆盖新任务状态，上传失败应支持恢复而不无条件重编码。

| P1 生成与选片统一 | 预检、单镜/批量、候选比较、失败恢复、素材候选、旧设定提示 | 在制作视图完成生成到选片，重复请求不创建重复计费任务 |

| P3 画布联动与增强 | 镜头映射、业务节点、统一提交/候选回写、可选分镜图、连续性辅助 | 双视图修改同一镜头一致，任务和候选无重复 |

P0/P1 可阶段发布，但产品不得声称“完整视频制作已完成”；P2 是首个闭环版本。P3 的双视图同步不作为 P0 提前承诺。字幕、配音、转场等另立范围。

优先做一次可交互设计稿，覆盖正常、加载、失败、无模型、旧结果与新设定不一致五种状态，再进入大规模页面替换。文档中的布局线框是需求表达，不是已经交付的交互原型。

## 13. 发布、兼容与实施前待确认事项

- 使用项目级/功能级开关逐步开放制作视图；先内部项目，再小范围项目，再默认新建入口。
- 数据迁移采用扩展方式，保留旧 URL、镜头 ID、候选、素材和运行历史。回退只切入口/功能开关，不删除新产生的内容。
- 本地后端据近期交接记录可能连接生产库；实施迁移前重新确认连接环境并在独立测试库演练，不根据旧记录直接执行写入。
- 当前 ProjectCanvasTab.vue 与 ProjectShell.vue 存在用户已有未提交布局改动，实施需合并保留，禁止覆盖。
- 需要在实施设计中确定：模型能力目录的数据来源、成本信息可用性、短片最大镜头数/时长/导出分辨率、媒体运行资源预算、运行中素材删除策略、现有批次与候选状态的兼容映射。
- 产品默认建议已经在本文给出：短片优先、生成后人工选片、项目风格可继承、成片默认保比例补边和保留原声。没有确认的供应商能力一律不作为可用选项暴露。

## 14. 交付完成定义

整改完成意味着：一个新用户能够从故事或已有素材出发，理解当前阶段，在同一项目中编辑镜头、生成和采用视频、导出成片；出错、刷新、重复点击及返回修改不会丢失成果或意外重复计费；页面在深浅主题和常用屏幕尺寸下保持清楚、稳定、可操作。

代码提交、构建通过、页面换肤或单个视频生成成功，均只证明部分工作完成，不能替代上述业务和交互验收。
