# AI 创作模块验收标准与结果记录规范

日期：2026-10-29。状态：验收规范，**当前没有任何用例执行通过的声明**。

配套：[实施手册](../design/2026-10-29-ai-creative-implementation.md)｜[总体设计](../design/2026-10-29-ai-creative-studio.md)。

## 1. 发布结论与强制门禁

- P1图片版：C00–C16完成，A01–A40全部PASS；网页与桌面两个发布形态分别完成实测。
- P2画布视频版：P1回归通过，B01–B05全部PASS。
- P3短剧成片版：P1/P2关键回归通过，D01–D05全部PASS。
- 任一必需环境缺失标BLOCKED；尚未执行标NOT_RUN；失败标FAIL。BLOCKED/NOT_RUN不算通过，不从分母剔除。
- 缺陷P0：越权、密钥泄漏、破坏数据、未经意图重复收费；P1：主流程不可用、任务不可恢复、结果丢失；P0/P1必须为0。
- P2/P3等级缺陷可以记录后续处理，但如果对应强制用例仍FAIL，则不能通过该阶段。发布范围改变需显式修订本文，不允许临时把失败项目降级来过关。
- “构建成功”“接口200”“Mock通过”“旧工作流曾生图”均不能单独代表新模块验收成功。

## 2. 环境与测试数据

| 标签 | 环境要求 |
| --- | --- |
| UNIT | 新增领域/适配器单元测试，时间与故障点可控 |
| PG | 独立PostgreSQL测试库；同生产主要版本；不操作用户业务库 |
| MOCK | 可控HTTP供应商，记录请求次数/请求键，提供成功、429、5xx、超时、断连、取消、坏文件等场景 |

## 4. 可测量的性能与界面标准

以下是**设计验收目标，尚未实测**。用固定构建、同机局域访问、隔离PG、关闭调试日志、Mock模型不访问公网测量；报告CPU/RAM、OS、JDK、Node、数据库版本、存储类型、样本数与统计方法。

1. 创建任务：允许测试队列容量≥100，20并发共100次不同请求；不含上游生成耗时，P95≤1秒，5xx为0。非法/限流用例单独统计，不混入延迟样本。
2. 列表/详情：准备1000条job与1000条资产，每页20条；分别100次请求，P95≤500ms；查询必须走归属/游标索引，不能每次全量读媒体。
3. 状态可见：同机Mock状态更新后，20个样本P95≤3秒在UI出现；断线后连接恢复时≤10秒追上快照。
4. 调度恢复：已知taskId任务在服务健康后≤30秒发出第一次恢复查询；外部供应商完成时间不纳入此指标。
5. 资源：Mock下持续完成200个单图job，最多8在途；完成后线程/连接数回到基线+5以内，事件监听与页面定时器不随任务数增长。用前后堆/连接数据定位增长，不能仅凭一次内存截图断言无泄漏。
6. 限制：超20MiB图片在流式过程中终止，错误文件不完整保留；视频阶段单独验证流式内存，不沿用图片实现。
7. 界面：1440×900、1024×768、390×844三个视口；浅/深主题；主操作无横向溢出，键盘能走完输入→模型→生成→下载，焦点可见，状态不只靠颜色表达。
8. 可恢复：刷新、关闭页签、重新登录、后端重启均不导致自动创建新的收费任务。用户草稿保存失败有可见提示，不能假显示“已保存”。

真实模型“质量”验收只要求提示词被正确传输、图像合法可展示；不以主观“好看”作为功能通过条件，不承诺随机模型可像素复现。

## 7. 执行证据与报告模板

提交代码前的常规命令示例：`git diff --check`、`mvn test`、`mvn -DskipTests package`、前端目录 `npm run build` 与 `npm run build:desktop`；桌面安装包按其package.json实际脚本执行。`-DskipTests package`只是打包，不计测试通过；测试类定向命令应在真实测试类创建后记录。仓库既有依赖外部服务的测试失败需单列原因，不能改成永久跳过来满足本模块门禁。
